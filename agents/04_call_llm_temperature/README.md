# 04 · Temperature 参数实验：亲手量化"随机性"

> 提示词一字不改，模型为什么每次回答不一样？答案藏在 `temperature` 这个
> 采样参数里。本篇做一次严格的对照实验：固定提示词与角色设定，只改
> temperature（0.0 / 0.5 / 1.0），横向对比输出的长度、词汇多样性和关键词
> 命中率，并讲透它背后的数学。读完你能为不同任务选对温度档位。

## Background

多数人初学时的做法是照抄教程或文档里的参数值：看到示例写 0.7 就一直用
0.7，说不清它到底改变了什么，也从没对比过不同取值的输出差异。

困惑很快会在具体场景出现：同一段提示词，今天回答工整、明天回答跑偏，
不知道是模型变了还是参数在起作用；到了工具调用场景，输出一发散，程序
解析直接报错——此时才需要回头弄清这个参数。

temperature（温度）并不是新发明：它借用了统计力学里"温度"的概念，从
早期语言模型的采样研究沿用至今，是几乎所有大模型接口都暴露的采样参数。
它值得被当成工程参数对待，而不是"听说 0.7 比较好"——这正是本篇用
对照实验量化它的原因。

## What

temperature 是控制采样随机性的参数。采样指模型逐个挑选下一个输出词的
过程：每个候选词都有一个概率，概率大的词更容易被选中。temperature 的
数学作用就一步——对模型打分做 softmax 前先除以 T：

`p(x) = softmax(logits / T)`

其中 logits（模型给每个候选词打的原始分数）经 softmax（把一组分数归一
化成总和为 1 的概率分布的函数）变成概率。

心智模型：**可以把 temperature 想象成采样分布的"形状旋钮"——T→0 永远
选最高分词，T 越大长尾词（概率低、少见的词）越容易被抽中。** 但和普通
旋钮不同的是：它没有统一的最优档位，最优值取决于任务——工具调用要低、
创意写作要高，这正是实验要回答的问题。

## When to Use

核心判断：按任务对"稳定"与"发散"的需求选档位，而不是凭感觉。

典型场景：

- **写工具调用、分类、抽取类逻辑**：输出要被程序解析，选低温（T→0），
  输出可复现；
- **做头脑风暴、创意写作功能**：需要多样表达，选高温（1.0 附近），让
  长尾词有机会；
- **做可复现的实验或测试**：固定 T=0，让多次运行结果几乎一致。

何时不用：输出质量不稳时先检查 Prompt 是否说清了要求——temperature
只改变分布形状，弥补不了指令模糊；日常对话用接口默认值即可。

档位选择速查（即 What 节公式的四种形态）：

| T | 效果 | 适用场景 |
| :--- | :--- | :--- |
| T→0 | 分布退化为 argmax（直接取最高分词），输出可复现 | 工具调用、分类、抽取 |
| 0.5 | 分布略收窄，稳定中有变化 | 日常对话、摘要 |
| 1.0 | 原始分布，长尾词有机会 | 头脑风暴、创意写作 |
| T>1 | 人为压平分布，明显发散 | 少用；容易牺牲指令遵循 |

## Quick Start

前置条件与 01 实验相同：Ollama 已启动、已执行 `ollama pull
qwen3.8:latest`、Python 环境装有 `requests` 库。

```bash
cd agents/04_call_llm_temperature
python call_llm_temperature.py
```

脚本依次做三件事：

1. 打印实验设计（固定 Prompt + 三档温度）；
2. 依次以 0.0 / 0.5 / 1.0 调用（每轮间隔 0.5s），打印各档输出；
3. `analyze_results()` 对比长度、词数、关键词命中、词汇多样性并给出结论。

预期输出：`0.0` 档措辞工整命中关键词；`1.0` 档可能更"放飞"甚至偏离约束
（这正是教学点——多发散的模型越可能牺牲指令遵循）。

实验设计是控制变量：固定不变的——Prompt（含"必须包含'数据'和'模式'"
的硬约束）、system 消息（设定角色与规则的消息）、`num_predict=150`
（Ollama 里限制生成 token 数的参数，token 即模型处理文本的最小单位）。

唯一的自变量：`options.temperature`。观测量：输出长度、词汇多样性
（去重词数）、关键词命中率。

**任何结论都必须在这样的控制变量下得出**——这也是评估 Agent 的基本功
（30 实验会复用这套思路建评估集）。

## How It Works

本节讲两层机制：数学上除以 T 发生了什么，以及实验输出里那些"不稳定"
现象的来源。

### 数学本质：就一个除数

对 logits 除以 T 再 softmax：T<1 放大分数差异，使分布更尖——高分词
几乎必中，这就是 `0.0` 档措辞工整、多次运行几乎一致的原因；T>1 压平
分布，使采样更均匀——长尾词获得机会，这就是 `1.0` 档"放飞"的来源；
T→0 等价 argmax。

你在 Quick Start 看到的两档反差，就来自这同一个除数：尖锐分布牺牲
多样性换稳定，平缓分布相反。一个需要知道的边界：**T=0 并不 100%
确定**，GPU 浮点并行会引入微量非确定性，但工程上足够当作"可复现"使用
（原因与严格复现的做法见文末 Q2）。

### 真实的坑：thinking 字段

qwen3.8 是推理模型（会把思考过程单独输出的模型），响应里可能同时有
`message.thinking` 和 `message.content`，且答案有时只出现在 thinking
里。

`extract_content()` 做了三级兜底：`content` → `thinking` 的最后
有效行 → `response` 字段。

```python
def extract_content(response_data):
    message = response_data.get("message", {})
    content = message.get("content", "").strip()
    if not content and message.get("thinking"):      # 推理模型兜底
        for line in reversed(message["thinking"].splitlines()):
            line = line.strip()
            if line and not line.startswith("Thinking"):
                return line                           # thinking 里最后一条有效行
    return content or response_data.get("response")   # generate 接口风格兜底
```

兜底全部落空时**打印响应的字段名列表**——这是调试陌生模型响应结构的
通用技巧。

## Pitfalls & Q&A

踩坑清单（每条 = 现象 + 原因 + 解法）：

- **计时数据抖动、结论不稳**：原因：本地推理有排队，相邻调用互相污染
  计时。解法：温度实验每次调用之间加 `sleep(0.5)`。
- **长度对比失去意义**：原因：对照实验同时改了 `max_tokens`，两个变量
  一起变。解法：只留 temperature 一个自变量，其余全部固定。
- **"1.0 档看起来更聪明"式结论**：现象是评价全凭主观印象，无法复现。
  原因：没用可量化指标。解法：用关键词命中率、词汇多样性、输出长度
  说话。

**Q1: Agent 的工具调用为什么建议低温？**

工具名和参数 JSON 必须精确匹配注册表，发散采样会增加幻觉（模型一本
正经编造不存在内容的现象）工具名、格式错误的概率；低温提升可解析率。

**Q2: temperature=0 能保证完全确定性吗？**

不能完全保证。GPU 上浮点并行归约（reduction，把一串数并行累加成一个值
的运算）的顺序不定，会引入微量非确定性；要
严格复现需固定 seed（随机数种子）+ 确定性推理配置。

**Q3: top_p 和 temperature 什么关系？**

都是控制采样分布的手段：top_p 是"截断"（只从累计概率前 p 的词里采），
temperature 是"调形"。实践里二选一调，同时大幅调整容易互相抵消。

**Q4: 怎么科学地对比两个参数档位的效果？**

控制变量 + 量化指标（命中率/多样性/长度）+ 多次重复，参考本篇实验
设计。
