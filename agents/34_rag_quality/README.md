# 34 · RAG 质量量化：Faithfulness / Relevance + chunking 对照

> 给 RAG（检索增强生成：先从文档库检索相关片段，再让大模型（LLM，在海量
> 文本上训练的生成式语言模型）基于片段作答）
> 应用做质量量化：用两个可计算的指标分别回答"检索找得准不准"与"答案有没有
> 材料依据"，并在三种文档切分策略之间做对照实验。读完本篇你能获得：两个指标
> 的定义与归因用法、一套可直接运行的最小评估管线，以及这类指标现有实现的局限。

## Background

在出现量化指标之前，评估一个 RAG 应用主要靠人工抽查：从真实提问里挑几条，
人读一遍答案，凭经验判断"答得行不行"。要更细，就得把流水线（数据依次经过
多个处理步骤的执行链）各环节的中间结果——切出的块、检索命中的块、最终答案
——逐一翻出来看。

人工抽查在两种情况撞墙。一是规模：提问一多就抽查不过来，结论也因人而异。

二是归因：用户反馈"答案不对"时，面对的是两个性质不同的嫌疑——检索没把
相关材料找回来，或者材料找对了、模型却没照着材料答。两种原因混在同一个
"效果不好"里，改提示词（写给大模型的指令文本）、换模型还是调检索参数
全靠猜，改完也没有数字确认是否变好。

解决思路是把"效果不好"拆成两个可计算的问题分别打分：检索侧看"找回的材料
与问题相关吗"，生成侧看"答案的每句话在材料里有依据吗"。这两个分数一旦能算
出来，排查就从猜变成了定位。这就是本实验双指标的出发点。

## What

定义：RAG 质量量化是用可计算的指标，给 RAG 流水线的检索与生成两个环节
分别打分的评估方法。两个指标分开归因：

- **Faithfulness（忠实度）**：答案逐句回溯，句子有检索证据支撑的占比——
  低分即幻觉（模型编造了检索材料里不存在的内容）信号，可做线上监控；
- **Relevance（相关度）**：检索块与查询的相关度（用 embedding 相似度近似
  ——embedding 指把文本映射成向量，语义相近的文本向量距离也近）——低分
  先查 chunking、embedding 与召回（检索阶段从全库找回候选块的动作），不要
  急着改提示词。

chunking（文档切分：把长文档切成适合检索的小块，块是检索的最小单位）三种
策略：固定长度（按固定字符数切，不关心内容边界）/ 递归字符（先按段落，
段落过长再按句子逐级回退）/ 段落感知（优先在语义边界切）。

心智模型一句话：**先分桶（检索 vs 生成）再动手——两个指标就是分桶依据。**

可以把两个指标想象成快递查询里的两段物流记录：Relevance 告诉你仓库有没有
发对货，Faithfulness 告诉你运输途中货物有没有被损坏或掉包。但和查快递不同的
是，这对指标只负责把问题定位到环节，不直接给出修法——定位之后仍要回到对应
环节调参数。

## When to Use

这节回答三个问题：什么场景值得搭这套指标、什么情况不必、和别的评估方式
怎么选。

典型场景：

- 知识库问答系统上线前验收：准备一批标准问答，跑双指标打分，低于阈值
  不放行；
- 线上收到"回答不准"的反馈需要定位：先看两个指标把问题分桶到检索或生成，
  再决定动哪一侧；
- 调整切分参数或更换 embedding 模型时：用双指标做前后对照，用数字而不是
  肉眼确认改动是否有效。

何时不用：

- 语料只有几篇文档、问答形式简单：肉眼抽查几组就够，搭管线属于过度工程
  （小语料上指标区分度有限，见 Pitfalls & Q&A）；
- 应用不基于检索材料作答（纯聊天、纯创作）：Faithfulness 没有"检索证据"
  可对照，指标无从算起。

同类方案对比：

| 方案 | 差异 | 什么时候选它 |
|---|---|---|
| 人工抽查 | 零成本，但主观、不可扩展，定位不了环节 | 语料极小，临时看一眼 |
| 端到端单指标 | 只给最终答案评分，分不清检索与生成的责任 | 只关心结果好坏，不打算排查 |
| 双指标分桶（本实验） | 成本低、离线可跑，能把问题定位到检索或生成 | 多数 RAG 应用的第一步评估 |
| NLI / 引用式 LLM Judge | 接近语义判断，但要额外跑模型、成本更高 | 生产环境的严肃评估 |

表中 NLI（自然语言推理：判断一句话对另一句话是支持、矛盾还是无关的模型
任务）与引用式 LLM Judge（让一个 LLM 依据材料逐句核对答案并打分的评估
方式）都是语义级方案，用于替代本实验的字面重合法——字面重合指只看词是否
逐字出现、不做语义判断的评分方式，实现见 How It Works。

## How It Works

这节按数据流走一遍 demo 管线，并解释 Quick Start 输出表格里每个数字的来源。

### 管线五步

1. **切分**：三种策略函数分别把 6 个文档切成块，每块带上来源文档标记；
2. **检索**：从查询里用正则表达式（按字符模式切分文本）抽关键词，只留长度
   不小于 2 的词，按关键词在块里的出现次数排序，取前 3 块（top_k，即只保留
   得分最高的 k 个结果，这里 k=3）；
3. **生成**：demo 模式不调用 LLM，直接把检索到的 3 个块各截前 50 个字符
   拼成"答案"——为的是离线可跑、结果可复现；
4. **打分**：对每条查询分别计算 Relevance 与 Faithfulness；
5. **汇总**：6 条查询取平均，每种策略打印一行。

### 两个指标的实现

```python
def relevance(query, chunk):
    kws = [w for w in re.findall(r"[\w一-鿿]+", query) if len(w) >= 2]
    hits = sum(1 for w in kws if w in chunk["text"])
    return hits / max(len(kws), 1)


def faithfulness(answer, retrieved_texts):
    """答案中的关键词是否被检索内容支撑。"""
    support_text = " ".join(r["text"] for r in retrieved_texts)
    claims = re.findall(r"[一-鿿\w]{2,}", answer)
    if not claims: return 1.0
    supported = sum(1 for c in claims if c in support_text)
    return supported / len(claims)
```

两个函数用同一招：字面重合近似。这样写的理由是零模型依赖、离线可跑、结果
可复现；代价是"语义上对不对"判断不了，局限见下一节。

### 表格里的数字从哪来

- chunks 列三行都是 6：语料中每个文档都不超过一块的容量上限（100 字符），
  三种策略都只切出每文档 1 块——策略之间没有产生实际差异，这就是"小语料
  区分度有限"的直接原因；
- Relevance 均 0.25：该指标衡量查询关键词有多大比例逐字出现在检索块里。
  查询措辞与文档原文不会完全重合，平均下来只有约四分之一的关键词能命中；
- Faithfulness 均 1.00：demo 的"答案"就是从检索块里截出来拼接的，答案里的
  每个词必然都能在检索内容中找到，字面重合法对这种"材料拼出来的答案"必然
  给满分。这个 1.00 说明的是答案与材料同源，不代表生成环节质量。

输出末行的结论（递归字符最均衡、是生产默认）并不来自这张小表——表里三种
策略数值完全相同；该口径来自语义边界保留与 overlap 衔接的机制分析，大语料
上的真机对照见 [qa/28](../../qa/28_rag_quality/README.md)。

## Pitfalls & Q&A

### 踩坑清单

**1. 答案明明正确，Faithfulness 却很低；或答案在编造，Faithfulness 却不低。**

原因：字面重合只认词面、不认语义——对"换了说法的正确句"会误判（词面对不上），
对"含共用词的幻觉句"会漏判（词恰好都在材料里），两个方向都有误差，qa/28 有
实测数据。解法：生产环境改用语义级方案——NLI 或引用式 LLM Judge（定义见
When to Use 的方案对比）。

**2. 三种切分策略的分数一模一样，对照不出优劣。**

原因即 How It Works 所述：小语料上每个文档只切出 1 块，策略没有产生实际差异。
解法：评估管线先搭好，语料上量后再下结论；真机大语料的对照数据见 qa/28。

**3. 想给 chunking 找一组万能参数，换批语料就失效。**

原因：粒度、边界、overlap 三个参数互相牵制，又和语料的行文结构强相关，不
存在普适最优。解法：用双指标驱动调优——每改一组参数就跑一遍评估，按分数
选择。

### 深入问答

**Q1: "RAG 效果差怎么排查？"**

先分桶再动手（心智模型见 What），两个指标的组合给出排查顺序：

- 只 Relevance 低：修检索侧（chunking / 嵌入 / 召回）；
- 只 Faithfulness 低：修生成侧（提示词约束 / 引用要求 / 幻觉检测）；
- 两个都低：先修检索——检索质量决定答案质量的上限，检索侧坏掉时，生成侧
  的约束无从发力；
- 两个都高：这套指标覆盖的环节基本正常，问题要去指标之外找（查询理解、
  数据质量等）。
