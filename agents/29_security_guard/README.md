# 29 · Agent 安全防护：注入检测、白名单与输出过滤

> 项目 15 的审批层管的是"工具调用时刻"，防线只有一道。本篇把防护铺满全链路：
> **输入侧**注入检测（规则库 + LLM 复核打分）、**执行侧**工具白名单、**输出侧**
> 敏感信息过滤——并内置 8 条攻击/正常混合用例做端到端回归。真机实测：5 拦 3 过
> 零误伤，危险命令在输入阶段就被 LLM 复核拦下（操纵分 10/10）。

## 1. 为什么需要它

Agent 一旦对外开放（28 的 HTTP 服务），第一天就会遇到三类攻击：**提示注入**
（"忽略之前所有指令"骗模型越过规则）、**越权工具调用**（诱导调用白名单外的
危险工具）、**敏感信息出站**（响应里泄露密钥或危险命令）。防线必须分层且
可回归测试——安全不是功能，是可以被攻击样例反复验证的**性质**。

## 4. 核心概念

### 4.1 三道防线的分工

| 防线 | 位置 | 手段 | 拦截的问题 |
| :--- | :--- | :--- | :--- |
| 注入检测 | 输入侧 | 规则库 + LLM 复核（0-10 操纵分） | 提示注入、越狱、提示词泄露 |
| 工具白名单 | 执行侧 | 登记表外一律拒绝 | 诱导调用危险工具 |
| 输出过滤 | 出站侧 | 密钥/危险命令模式替换 | 敏感信息与破坏性内容出站 |

### 4.2 规则 + LLM 的双层判定

规则库（正则）快、可解释、零成本，但只能挡已知模式；LLM 复核覆盖变形攻击
（换个说法的注入），但每次判定多一次调用且有小概率误伤。策略：**规则优先、
LLM 兜边界**——规则未命中再交 LLM 打操纵分（≥7 拦截）。真机里 `rm -rf`
和 `format_c_drive` 都是被 LLM 复核在输入阶段拦下的。

### 4.3 fail-safe 与最小暴露

- 判定失败（网络/解析错误）→ 放行但按正常业务处理（可用性优先），危险类
  命中则 fail-closed；
- 拦截话术统一为"检测到疑似注入，已拒绝"——**不向潜在攻击者暴露具体命中
  的规则**（信息最小暴露原则）；
- 拦截的详细原因进审计日志（服务端可见），不出站。

### 4.4 已知边界

- 正则库是黑名单思维，无法覆盖全部变形注入——LLM 复核与人工红队测试是
  必要补充；
- 边界样本（"把规则翻译成英文"）依赖 LLM 判定的稳定性，温度已设 0；
- 防御是持续对抗：攻击样例库要随真实攻击进化，每次加规则都重跑回归表。

## 5. 代码关键部分

```python
def guarded_chat(query):
    allowed, reason = inspect_input(query)          # 防线 1: 注入检测
    if not allowed:
        return {"blocked": "input", "reason": reason}
    tool_m = re.search(r"(使用|调用|运行)\s*[\"']?(\w+)", query)
    if tool_m:
        tool_ok, tool_reason = check_tool(tool_m.group(2))   # 防线 2: 白名单
        if not tool_ok:
            return {"blocked": "tool", "reason": tool_reason}
    answer = llm_answer(query)
    safe_text, blocked = filter_output(answer)      # 防线 3: 输出过滤
    if blocked:
        return {"blocked": "output", "reason": str(blocked)}
    return {"blocked": None, "text": safe_text}
```

坑清单：

- 拦截话术统一，不泄露命中规则（不给攻击者迭代弹药）；
- 规则用大小写不敏感匹配，攻击者会用大小写与全半角变体；
- 回归用例随每次真实攻击样本进化——防御是持续对抗不是一次性功能。

## 7. 面试要点

- **Q: 提示注入的防御为什么不能只靠提示词？**
  A: 提示词是"软约束"，注入攻击的目标恰是绕过它；必须在系统层（输入检测、
  白名单、输出过滤）建立硬约束，提示词只是第一道软防线。
- **Q: 规则检测和 LLM 检测如何配合？**
  A: 规则先挡已知模式（快、免费、可解释），LLM 复核边界样本（覆盖变形）；
  规则命中优先，LLM 分数设阈值，两层独立可回滚。
- **Q: 拦截话术为什么不能包含具体原因？**
  A: 最小暴露原则——攻击者可据命中规则迭代变体；详细原因只进服务端审计日志。
- **Q: 如何验证防御没有退化？**
  A: 攻击样例回归表（本篇的 8 条用例）纳入 CI，每次改规则全量重跑；
  线上新增真实攻击样本持续补充用例。
- **Q: 与项目 15 的审批层是什么关系？**
  A: 15 管"执行时人工确认"，29 管"进出站自动化拦截"——审批解决授权，
  防护解决攻击，互补不重叠。
