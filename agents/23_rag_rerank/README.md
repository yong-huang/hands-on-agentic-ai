# 23 · RAG 重排序与优化：一次"预期被数据推翻"的实验

> 对同一检索库做严格对照实验：**不压缩假设、加入易混淆干扰语料、三种排序
> 策略、手工标注的评估集**。结果出乎预设预期：在小语料、检索模型已经很强
> 的场景下，三种策略打平，其中一种还略降。读完你能掌握"用数据检验优化
> 手段"的完整方法，而不是照抄社区结论。

## Background

在向量检索之后再补一道精排，社区里流传着一个默认结论："加上它就能提升
检索精度"。多数实践照这个结论直接选型，默认它对任何场景都成立。

默认结论是有前提的——它来自大语料、检索器较弱的场景。不看前提直接套用，
代价是真实的：精排的每一步都额外花钱（让大模型逐个候选打分尤其贵），
而在基线已经很强的场景里，多一道工序不但没有收益，还可能把排序改坏。
失败的情形很少被写进教程，照抄的人无从知道边界。

本篇的做法是把"这个结论在我的场景成立吗"变成一个可测量的实验：控制
变量、构造干扰、手工标注答案、用数字裁决。这套"不预设立场"的对照方法
源自 04 实验（温度对照实验），无论结论正负，收获的都是测量检索质量的
能力。

## What

**重排序（rerank）是在向量检索召回候选之后、按更细的相关性标准把候选重新
排一次序的优化步骤。**向量检索指先把文本转成向量（一组能表达语义的数字）、
再按向量间距离找相近内容的检索方式，本实验复用 21 实验的索引；召回指
初筛：先从库里取出一批可能相关的候选块。

本篇把重排做成一条可测量的实验管线：查询先经向量检索召回 5 个候选
（baseline，即不重排的基线），再分别用 MMR（Maximal Marginal Relevance，
最大边际相关——纯数学算法，兼顾相关性与多样性）和 LLM（大语言模型）打分
（qwen3.8 逐候选评 0-10）重排。

三种排序在手工标注的评估集上对比 hit@3（前 3 名命中标注相关块的比例）
与 MRR（平均倒数排名，名次越靠前分越高）。索引中刻意加入 6 条主题相邻的
易混淆语料（微调 / 注意力 / 思维链……），制造真实的排序压力。

可以把重排想象成招聘的复试环节：初筛（向量检索）按简历粗排 5 名候选人，
复试（重排）逐个细看再定最终名次。但和复试不同的是，复试官不一定比初筛
更准——当初筛已经足够好时，多一轮复试只会新增误差和成本，这正是本实验
要用数据检验的假设。

心智模型一句话：**重排序是"用更多成本换更准的排序"——但值不值，必须
测。**

## When to Use

在候选排序质量直接决定答案质量的场景考虑重排：注入给模型的 top-3 里混着
部分相关的块，答案因此跑偏；主题相邻的资料扎堆，真正命中的块排在第三名
之后；大语料上初筛粗糙，需要精排把关。

不用的情况：小语料加强检索器（本实验证明基线已近天花板，重排没有提升
空间）；对延迟和成本敏感的线上服务（LLM 重排每个候选都要一次模型调用）。

| 策略 | 额外成本 | 改变什么 | 什么时候选它 |
| :--- | :--- | :--- | :--- |
| baseline | 零 | —— | 基线必测，先看它够不够 |
| MMR | 纯数学（候选两两余弦） | 用 λ 权衡相关性与多样性 | 需要多角度覆盖、去冗余的检索 |
| LLM 重排 | 每候选一次 LLM 调用 | 按语义相关度重新打分 | 候选胶着、精度优先且预算充足 |

## How It Works

MMR 的实现——相关性打头，后续位置留给与已选差异大的块：

```python
def rerank_mmr(query_vec, candidates, embeddings, lam=LAMBDA, top_k=None):
    """最大边际相关: 相关性打头, 后续位置留给与已选差异大的块"""
    order, selected, pool = [], [], list(range(len(candidates)))
    for _ in range(min(top_k or len(candidates), len(pool))):
        best, best_score = None, -1e9
        for idx in pool:
            rel = cosine_sim(query_vec, embeddings[idx])
            red = max((cosine_sim(embeddings[idx], embeddings[s]) for s in selected),
                      default=0.0)
            score = lam * rel - (1 - lam) * red
            if score > best_score:
                best, best_score = idx, score
        order.append(best); selected.append(best); pool.remove(best)
    return order
```

每轮选块时给每个候选取两个量：`rel` 是与查询的余弦相似度（衡量两个向量
方向是否一致的指标，越接近 1 越相似），`red` 是与已选块的最大相似度
（冗余度）。

总分 `lam * rel - (1 - lam) * red` 用 λ（一个 0 到 1 的权重）在两者间
取舍：λ 越大越偏精度，越小越偏多样性。得分最高的块进入结果序列并移出
候选池，重复直到选满。

Quick Start 表格里"文档应该怎么切分？"一行 MMR 掉到 0/3，就是多样性项
把相关块挤出了 top-3——它为去冗余牺牲了纯精度。

**负结果的归因分析**：强检索器 + 小语料 = 基线天花板已高（nomic 在 15 条
库里的排序几乎无可挑剔，重排没有提升空间）；MMR 的多样性目标对精确任务
是损耗。

重排序的真实收益场景是**大语料、弱检索器（如纯 BM25，一种只看词频的经典
关键词排序算法）、易混淆候选排名胶着**——你的场景是否属于这三类，测了
才知道。

**方法论：负结果也是结果**。完整保留"预期 → 实验 → 归因"的链条：预期
重排序获胜，数据说不，归因到"语料规模与检索器强度"。任何优化（重排、
切分参数、embedding 换型）都应该先跑一次这样的对照评估——这套"不预设立场、
用数据裁决"的做法源自 04 实验（温度对照实验）确立的实验方法论。

## Pitfalls & Q&A

踩坑清单（每条：现象 → 原因 → 解法）：

- **评估被一次格式抖动毁掉**。现象：某轮 LLM 打分解析失败，整组数字报废。
  原因：LLM 输出格式不稳定，且高温下更随机。解法：打分用 `temperature=0`
  （采样温度参数，0 表示输出尽量确定）并在解析失败时给中位分兜底。
- **测不出策略差异**。现象：三种策略结果完全一样，以为实验失效。原因：
  干扰语料与目标主题无关，被强 embedding 轻松压制，没有形成排序压力。
  解法：干扰语料要用"主题相邻"的内容。
- **数字版本混乱**。现象：不同轮次的对比数字对不上。原因：评估集、索引、
  策略有改动后仍混用旧数据。解法：任一变化都要重跑全部实验。

**Q1: 怎么评估检索质量？**

手工标注查询-相关块对，用 hit@3 / MRR 等排序指标（定义见 What 节）；评分
环节尽量确定性（关键词/规则），保证可复现。

**Q2: LLM 重排的成本怎么控制？**

只重排召回的 top-N（而非全库）、截断候选文本、低温短输出；或用轻量
cross-encoder（一种把查询与候选拼在一起打分的小型专用模型）替代 LLM。

**Q3: MMR 什么时候该用、什么时候别用？**

在相关性之外引入多样性惩罚（λ 权衡），适合"多角度覆盖"的检索任务；对
"只要最准那条"的任务，多样性反而损耗精度（本实验实测 0.667 → 0.640）。
