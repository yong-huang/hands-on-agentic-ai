# 23 · RAG 重排序与优化：一次"预期被数据推翻"的实验

> 对同一索引做严格对照实验：**不压缩假设、加入易混淆干扰语料、三种排序
> 策略、手工标注的评估集**。结果出乎预设预期：在小语料 + 强 embedding 的
> 场景下，三种策略打平，MMR 还略降——这个"负结果"比一个被修饰出来的
> 成功更有教学价值。

## What

实验管线：查询先经向量检索召回 5 个候选（baseline），再分别用 MMR（纯
数学，兼顾相关性与多样性）和 LLM 打分（qwen3.8 逐候选评 0-10）重排，三种
排序在手工标注的评估集上对比 hit@3 与 MRR。索引中刻意加入 6 条主题相邻的
易混淆语料（微调 / 注意力 / 思维链……），制造真实的排序压力。

三种排序策略的成本结构：

| 策略 | 额外成本 | 改变什么 |
| :--- | :--- | :--- |
| baseline | 零 | —— |
| MMR | 纯数学（候选两两余弦） | 用 λ 权衡相关性与多样性 |
| LLM 重排 | 每候选一次 LLM 调用 | 按语义相关度重新打分 |

心智模型一句话：**重排序是"用更多成本换更准的排序"——但值不值，必须
测。**

## Why

"上重排序能提升 RAG 精度"是社区常见默认结论，但默认结论必须用数据验证
——这正是项目 04（温度实验）确立的方法论在 RAG 上的应用。无论结果是正是
负，你获得的都是**测量检索质量的能力**——这比任何单一结论都值钱。

MMR 的实现——相关性打头，后续位置留给与已选差异大的块：

```python
def rerank_mmr(query_vec, candidates, embeddings, lam=LAMBDA, top_k=None):
    """最大边际相关: 相关性打头, 后续位置留给与已选差异大的块"""
    order, selected, pool = [], [], list(range(len(candidates)))
    for _ in range(min(top_k or len(candidates), len(pool))):
        best, best_score = None, -1e9
        for idx in pool:
            rel = cosine_sim(query_vec, embeddings[idx])
            red = max((cosine_sim(embeddings[idx], embeddings[s]) for s in selected),
                      default=0.0)
            score = lam * rel - (1 - lam) * red
            if score > best_score:
                best, best_score = idx, score
        order.append(best); selected.append(best); pool.remove(best)
    return order
```

## Deep Dive

**负结果的归因分析**：强检索器 + 小语料 = 基线天花板已高（nomic 在 15 条
库里的排序几乎无可挑剔，重排没有提升空间）；MMR 的多样性目标对精确任务是
损耗（"怎么切分"查询中把相关块挤出 top-3——它为去冗余牺牲纯精度）；重排
序的真实收益场景是**大语料、弱检索器（如纯 BM25）、易混淆候选排名胶着**
——你的场景是否属于这三类，测了才知道。

**方法论：负结果也是结果**。完整保留"预期 → 实验 → 归因"的链条：预期
重排序获胜，数据说不，归因到"语料规模与检索器强度"。任何优化（重排、
切分参数、embedding 换型）都应该先跑一次这样的对照评估。

踩坑清单：

- LLM 打分要 `temperature=0` 并解析失败时给中位分兜底，不要让一次格式
  抖动毁掉整轮评估；
- 干扰语料要用"主题相邻"的内容——无关主题被强 embedding 轻松压制，测不
  出差异；
- 评估集、索引、策略任一变化都要重跑全部实验，别混用不同版本的数字。

## Q&A

**Q1: MMR 和普通重排的区别？**

MMR 在相关性之外引入多样性惩罚（λ 权衡），适合"多角度覆盖"的检索任务；
对"只要最准那条"的任务，多样性反而损耗精度（本实验实测 0.667→0.640）。

**Q2: 怎么评估检索质量？**

手工标注查询-相关块对，用 hit@k / MRR 等排序指标；评分环节尽量确定性
（关键词/规则），保证可复现。

**Q3: LLM 重排的成本怎么控制？**

只重排召回的 top-N（而非全库）、截断候选文本、低温短输出；或用轻量
cross-encoder 替代 LLM。

**Q4: 如果实验结果与预期相反怎么办？**

如实报告并归因（检索器强度、语料规模、干扰设计）——负结果约束了技术
决策的适用边界，和正结果同样有价值。
