# 23 · RAG 重排序与优化：一次"预期被数据推翻"的实验

> 向量检索的 top-k 是"几何最近"，未必是"语义最相关"——重排序（rerank）
> 号称解决这件事。本篇对同一索引做了严格对照实验：**不压缩假设、加入易混淆
> 干扰语料、三种排序策略、手工标注的评估集**。结果出乎预设预期：在小语料 +
> 强 embedding 的场景下，三种策略打平，MMR 还略降——这个"负结果"比一个
> 被修饰出来的成功更有教学价值。

## 1. 为什么需要它

"上重排序能提升 RAG 精度"是社区常见默认结论，但默认结论必须用数据验证——
这正是项目 04（温度实验）确立的方法论在 RAG 上的应用。本篇把评估做成可复现
的实验：手工标注 5 个查询的相关块、三种排序策略（零成本基线 / 纯数学 MMR /
LLM 打分重排）、双指标（hit@3 / MRR）。无论结果是正是负，你获得的都是
**测量检索质量的能力**——这比任何单一结论都值钱。

## 4. 核心概念

### 4.1 负结果告诉我们什么

预设预期是"重排序提升精度"，实测是三策略打平（LLM 与 baseline 完全一致，
MMR 略降）。归因分析：

- **强检索器 + 小语料 = 基线天花板已高**：nomic-embed-text 在 15 条库里
  的排序几乎无可挑剔，重排没有提升空间；
- **MMR 的多样性目标对精确任务是损耗**："怎么切分"查询中 MMR 把相关块
  挤出 top-3（0/3）——它为去冗余牺牲了纯精度；
- **重排序的真实收益场景**：大语料、弱检索器（如纯 BM25）、易混淆候选
  排名胶着时。你的场景是否属于这三类——测了才知道。

### 4.2 三种排序策略的成本结构

| 策略 | 额外成本 | 改变什么 |
| :--- | :--- | :--- |
| baseline | 零 | —— |
| MMR | 纯数学（候选两两余弦） | 用 λ 权衡相关性与多样性 |
| LLM 重排 | 每候选一次 LLM 调用 | 按语义相关度重新打分 |

### 4.3 评估集的设计

5 个查询手工标注相关块 id，指标用 hit@3（前 3 是否含相关块）与 MRR
（首个相关块的倒数排名）。设计要点：查询覆盖知识库的不同章节；相关块标注
允许多个（同一问题可能多个块都相关）；**评分用确定性关键词而非 LLM**，
保证可复现。

### 4.4 方法论：负结果也是结果

本项目完整保留了"预期 → 实验 → 归因"的链条：我们预期重排序获胜，数据说不，
归因到"语料规模与检索器强度"。这套方法可直接迁移到你的生产系统——**任何
优化（重排、切分参数、embedding 换型）都应该先跑一次这样的对照评估**。

## 5. 代码关键部分

```python
def rerank_mmr(query_vec, candidates, embeddings, lam=LAMBDA, top_k=None):
    """最大边际相关: 相关性打头, 后续位置留给与已选差异大的块"""
    order, selected, pool = [], [], list(range(len(candidates)))
    for _ in range(min(top_k or len(candidates), len(pool))):
        best, best_score = None, -1e9
        for idx in pool:
            rel = cosine_sim(query_vec, embeddings[idx])
            red = max((cosine_sim(embeddings[idx], embeddings[s]) for s in selected),
                      default=0.0)
            score = lam * rel - (1 - lam) * red
            if score > best_score:
                best, best_score = idx, score
        order.append(best); selected.append(best); pool.remove(best)
    return order
```

坑清单：

- LLM 打分要 `temperature=0` 并解析失败时给中位分兜底，不要让一次格式抖动
  毁掉整轮评估；
- 干扰语料要用"主题相邻"的内容——无关主题被强 embedding 轻松压制，测不出
  差异（本实验两版干扰语料的对比就说明了这一点）；
- 评估集、索引、策略任一变化都要重跑全部实验，别混用不同版本的数字。

## 7. 面试要点

- **Q: 重排序在 RAG 里解决什么问题？什么时候值得上？**
  A: 向量召回是"几何最近"而非"语义最相关"，重排用额外成本修正排序。值得
  上的场景：大语料、弱基线检索器（BM25/弱 embedding）、候选排名胶着。
  小语料 + 强 embedding 时收益趋近于零——应先评估再引入。
- **Q: MMR 和普通重排的区别？**
  A: MMR 在相关性之外引入多样性惩罚（λ 权衡），适合"多角度覆盖"的检索
  任务；对"只要最准那条"的任务，多样性反而损耗精度（本实验实测 0.667→0.640）。
- **Q: 怎么评估检索质量？**
  A: 手工标注查询-相关块对，用 hit@k / MRR 等排序指标；评分环节尽量确定性
  （关键词/规则），保证可复现。
- **Q: LLM 重排的成本怎么控制？**
  A: 只重排召回的 top-N（而非全库）、截断候选文本、低温短输出；或用轻量
  cross-encoder 替代 LLM。
- **Q: 如果实验结果与预期相反怎么办？**
  A: 如实报告并归因（检索器强度、语料规模、干扰设计）——负结果约束了
  技术决策的适用边界，和正结果同样有价值。

## 8. 总结

本篇的结论不是"重排序有用"，而是"重排序在本实验条件下无增益，且 MMR 有
微损"——附完整实验方法与归因。测量能力比结论更重要：有了这套标注评估框架，
切分参数、embedding 换型、重排引入都可以数据驱动地决策。下一篇进入第六阶段：
用 LangGraph 把多步流程变成可管理的状态图。
