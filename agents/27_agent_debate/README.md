# 27 · 多智能体辩论与投票：用立场对立逼出真实权衡

> 三个立场对立的专家（架构师/兼容性工程师/求实审计师）就"Function
> Calling vs 文本协议 ReAct"正面对辩两轮、互相反驳，最后投票产生 2:1 的
> 结论。辩题就是本系列 06 与 11 的真实架构分歧。

## What

辩论流程：三个专家 Agent 并行立论（round 1）→ 各自阅读全部立场后反驳
（round 2）→ 每人投票（可投给任何一方，含理由）→ 主持人计票宣布多数派
结论。辩论实录全程累积，投票模型能看到完整上下文。

角色 bias：立场是设计出来的——

| Agent | bias 提示词 | 效果 |
| :--- | :--- | :--- |
| 架构师 | "天然倾向标准化与协议化方案" | 先验偏向 FC |
| 兼容性工程师 | "关注模型兼容性与实现成本" | 先验偏向 ReAct |
| 求实审计师 | "中立，只看成本与证据" | 摇摆票，决定结论 |

**摇摆票的存在是辩论有意义的前提**——没有中立者，投票只是形式。

投票机制：`temperature=0` 的 JSON 输出（`{"vote", "reason"}`），允许投给
任何一方（含自己）但必须给理由；多数派获胜；平票时以审计师（中立者）为准。

心智模型一句话：**立场对立的角色 + 互相可见的发言 + 匿名于立场的投票 =
结论的公信力。**

## Why

Du et al. (2023) 的研究表明：多 Agent 辩论能显著提升事实性与推理质量
——本质是**用角色对立制造认知压力**。中立综述的毛病是回避取舍；而让一个
天然倾向标准化的架构师和一个天然关注兼容性的工程师正面对抗，双方必须给出
证据并回应对方的最强反驳，权衡分析才会真实发生。投票（而非主持人裁决）
让结论带完整的辩论上下文，可追溯。

## How

```bash
cd agents/27_agent_debate
python agent_debate.py --demo   # 离线：预置发言与投票
python agent_debate.py          # 真实：三专家两轮辩论 + 投票（9 次 LLM 调用）
```

**真机实测**：round 1 三方立论（FC 的结构化可靠性 vs ReAct 的零依赖兼容
性，审计师意外先行选了 FC）；round 2 的反驳质量显著提升——兼容性工程师
指出"FC 依赖厂商私有实现"，审计师反驳"FC 是 OpenAI 发起的行业标准而非
私有黑盒"。投票：FC 2 票（架构师 + 审计师"长期解析成本更低"）、ReAct 1 票
（现状兼容优先）——**FC 以 2:1 获胜**。

**辩论轮次：transcript 的累积**——Round 2 的每个 Agent 都能看到**全部**
round 1 发言（transcript 累积传入），所以反驳是针对性的（"兼容性工程师
混淆了通用与可靠"）。轮数不是越多越好：2-3 轮后发言开始重复，边际收益
归零。

投票函数：

```python
def vote(agent, transcript):
    raw = chat([{"role": "user", "content": VOTE_PROMPT.format(
        topic=DEBATE_TOPIC, name=agent["name"], bias=agent["bias"],
        transcript=transcript)}], temperature=0.0)
    m = re.search(r"\{.*\}", raw, re.S)
    return json.loads(m.group(0)) if m else {"vote": "无效", "reason": raw[:60]}
```

## Deep Dive

**票型本身就是信息**：2:1 说明结论有争议，落地时应配灰度验证。

**已知边界**：角色 bias 会让"辩论"退化为"立场表演"——审计师的中立设定
与"允许改票"是对冲手段；三个 Agent 是同一模型的不同人格，相关性偏差仍在
（生产可混用不同模型）；辩论成本 = 人数 × 轮数 × 调用，9 次调用是本篇的
预算，token 成本随轮次平方增长——控制在 2-3 轮。

踩坑清单：

- 提示词里的 JSON 示例花括号必须转义（`{{}}`），否则 `.format` 直接
  KeyError（本篇真机踩到）；
- transcript 累积全部发言传给反驳与投票轮——上下文是辩论质量的燃料；
- 投票解析失败时记"无效票"而不是中断，保证流程走完。

## Q&A

**Q1: 辩论和项目 26 的评审有什么区别？**

评审是多视角**质检同一产物**（意见汇聚后修订）；辩论是多个**立场就同一
问题对抗**（结论由投票产生）——前者改产物，后者选方案。

**Q2: 如何避免辩论变成立场表演？**

设置中立摇摆票、允许改票、限制轮数防重复、要求反驳针对对方最强论点。

**Q3: 平票怎么处理？**

以中立者票为准、引入额外证据轮、或上报人工——策略要预先声明而非事后
决定。
