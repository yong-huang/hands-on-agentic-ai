# 19 · 记忆更新策略：重要性判定、查重与融合

> 给 Agent（能调用工具、按目标自主行动的 LLM——大语言模型——应用）的长期
> 记忆装上三道写入闸门：判断值不值得记、检查是否记过、改写冲突的旧记忆。
> 读完你能在自己的记忆库里挡住琐碎与重复的写入，并让偏好变化自动更新旧
> 记忆，而不是新旧并存。

## Background

一个典型的 Agent 长期记忆库最初只有一种操作：把用户说过的每句话直接追加进
存储。这种来一条存一条的写入方式（下文称裸入库）实现简单，记忆条目少的时候，
多出来的几条冗余记录不影响使用。

问题在记忆变多后出现。用户先说"最喜欢吃火锅"，一个月后说"更爱吃日料了"，
两句话语义相近但内容冲突；库里两条都留着，检索时模型不知道哪条是当前偏好。
同一事实换个说法再存一遍、天气寒暄和核心画像被同等对待，都是同类病：重复、
过时、噪音。

病根是"只进不出"：写入端既不判断值不值得记，也不判断有没有记过、要不要
修正旧记录。解决办法是把数据库的查重约束、文档系统的就地更新、人对信息
价值的判断，搬到记忆写入路径上，形成一条三道闸门的决策管线。

## What

**记忆更新策略是一种写入端过滤管线：每条新陈述依次通过重要性判定、向量
查重、LLM 融合三道决策，通过检查的内容才以正确形态留在记忆库里。** LLM
（Large Language Model，大语言模型）在这里承担打分与改写两种职责；向量是
文本的一串数字表示，语义越接近的文本对应的向量越接近。

| 决策 | 手段 | 阈值 | 拦截的问题 |
| :--- | :--- | :--- | :--- |
| 重要性判定 | LLM 打分 0-10 | < 4 丢弃 | 琐碎噪音入库 |
| 向量查重 | 余弦最相似旧记忆 | ≥ 0.85 跳过 | 同一事实重复占用 |
| LLM 融合 | 更新旧事实并重嵌入 | 0.70-0.85 触发 | 新旧偏好并存、模型不知哪个新 |

表中两个术语：余弦相似度衡量两个向量方向是否一致，取值 -1 到 1，越接近 1
越相似；重嵌入指文本被改写后重新计算一遍向量，让向量跟上新内容。

可以把这套管线想象成期刊编辑部的收稿流程：先审"值不值得刊登"（重要性），
再查"是否与已刊文章重复"（查重），相似但角度不同就合并改写后重发（融合）。
但和编辑部不同的是，这里每一关都由数字阈值和模型自动裁决，没有人工裁量，
因此在临界值附近会出错——这是后文阈值标定问题的来源。

心智模型一句话：**先问值不值得记，再问是不是记过了，最后问要不要改写旧
记忆。**

## When to Use

在给助手做长期记忆、且会话之间要延续用户画像的时候，这套策略直接可用：
个人助理记住用户的偏好与背景；客服机器人归档跨天工单、避免重复记录同一
诉求；笔记类应用把零散输入整理成不重复、可更新的知识条目。

以下情况可以不用：记忆只存活在单次会话内（会话结束即丢弃，没有"旧记忆"
可冲突）；记忆条目极少（几十条以内，全量扫描加人工维护更可控）；写入内容
是强约束数据（如订单号），此时精确匹配比模型判定更可靠。

| 方案 | 差异 | 什么时候选它 |
| :--- | :--- | :--- |
| 裸入库 | 来一条存一条，无判断 | 原型验证、条目极少且不怕脏数据 |
| 精确/规则去重 | 字符串或编辑距离（把一个字符串改成另一个所需的最少增删改次数）匹配，快且可解释 | 表述固定的重复（同一订单号反复提交） |
| 本篇三重决策 | LLM 判重要性 + 向量查重 + LLM 融合 | 语义会变、说法多样的自然语言记忆 |

## Quick Start

前置条件：本地 Ollama 服务（localhost:11434，一个本地运行大模型的工具），
已拉取 `qwen3.8:latest` 与 `nomic-embed-text` 两个模型——前者负责判定与
融合，后者负责生成向量。

```bash
cd agents/19_memory_update
python memory_update.py --demo   # 离线：difflib 查重 + 规则判定模拟决策流
python memory_update.py          # 真实：裸入库 vs 托管入库对照实验
```

`--demo` 不调用任何在线服务，用标准库 difflib（Python 自带的文本序列比对
模块）替代向量查重、用固定规则替代 LLM 打分，适合在无模型环境下先验证
决策流本身。

真实模式把同一组 5 条陈述分别跑 17 实验式的裸入库和本篇的托管入库。
真机实测的预期结果：

- 「更爱吃日料了」→ **merged**：与旧记忆融合成"我叫张三，现在更爱吃日料，
  火锅吃得少"（相似度 0.82）——偏好变化被更新而不是并存；
- 重复的"喜欢吃火锅"→ **skip_duplicate**（相似度 0.93）；
- "今天天气真不错"→ **skip_trivial**（重要性 0 分）；
- 最终：裸入库 5 条（含重复 + 琐碎）vs 托管入库 2 条（干净、带重要性分）。

诚实预期：托管入库不是"把 5 条都存进去"，而是 5 条里只有 1 条作为全新
记忆入库，其余分别被丢弃、跳过或合并进旧记忆；库变小且每条带重要性分，
才是运行成功的标志。

## How It Works

核心是 `ManagedMemory.remember` 方法，一次调用走完三道决策：

```python
def remember(self, statement):
    imp = judge_importance(statement)                    # 决策 1: 重要性
    if imp < IMPORTANCE_FLOOR:
        return "skip_trivial", f"重要性 {imp}"
    vec = embed(statement)
    best_sim, best = max(((cosine(vec, it["vec"]), it) for it in self.items),
                         default=(0.0, None))
    if best_sim >= DUP_THRESHOLD:                        # 决策 2: 查重
        return "skip_duplicate", best["text"]
    if best_sim >= MERGE_THRESHOLD:                      # 决策 3: 融合
        merged = llm_merge(best["text"], statement)
        best.update(text=merged, vec=embed(merged),
                    importance=max(best["importance"], imp))
        return "merged", merged
    self.items.append({"text": statement, "vec": vec, "importance": imp})
    return "added", statement
```

执行顺序：决策 1 先用 `judge_importance` 打分，低于 4 分在进库之前就被
丢弃；存活者经 `embed` 转成向量，`max(...)` 对库内每条旧记忆算余弦相似度、
只留最高的一对。

这对相似度决定走决策 2（跳过）、决策 3（融合）还是入库。
`best.update(...)` 里同时更新文本与向量，就是 What 节说的重嵌入。

融合是"更新"而非"追加"。「最喜欢吃火锅」之后来了「更爱吃日料了」——
两者语义相关（0.82）但内容冲突。`llm_merge` 把新信息合并进旧记忆并重嵌入，
库里永远只保留一条当前有效的偏好。没有融合的记忆库无法表达"变化"。

Quick Start 里的三个实测结果正对应三条分支：0.82 落在 0.70-0.85 区间触发
决策 3，返回 merged；0.93 ≥ 0.85 触发决策 2，返回 skip_duplicate；"今天
天气真不错"打分 0 分，在决策 1 就被丢弃，根本走不到查重那两行。

决策审计是治理的基础设施：`ManagedMemory.log` 记录每次决策（陈述、决策
类型、依据）——为什么这条被丢？那条和谁合并了？出了错能回放。`--demo`
离线版（difflib 查重 + 规则判定）与真实版决策逻辑一致，验证的就是这条
可测试的决策流。

## Pitfalls & Q&A

踩坑清单（每条：现象 → 原因 → 解法）：

- **判定失败静默丢数据**。现象：网络或解析出错后，用户的陈述直接消失。
  原因：LLM 打分调用失败被当成低分处理。解法：失败时保守放行（重要性记
  5），不要静默丢弃用户信息，并配合重试与决策日志。
- **融合后查重失真**。现象：相似事实反复触发融合、相似度不再可信。原因：
  文本被改写但没有重嵌入，相似度算在过期向量上。解法：融合后必须对合并
  文本重新 embed（即代码中的 `embed(merged)`）。
- **决策不可追溯**。现象：库里少了条记忆却说不清原因。原因：只写功能代码、
  不留审计。解法：决策日志与功能代码同等重要，每次决策落一条记录。

已知边界：0.85/0.70 是经验值，语料变了（中文/英文、长短句）需要重新标定；
LLM 打分有噪声，边界附近的分数建议重试或取多次均值；本策略仍然没有
"遗忘"，按时间衰减的主动遗忘是记忆系统的下一步。

**Q1: 重复和融合的界线怎么定？**

由两条阈值切分：相似度 ≥ 0.85 判重复跳过，0.70-0.85 交给 LLM 融合，
< 0.70 作为新记忆。执行位置见 How It Works 的 `remember` 代码；阈值靠
语料标定，不是通用常数。

**Q2: 记忆治理还缺什么？**

主动遗忘（时间衰减/容量驱逐）、访问统计（长期不被召回的记忆降权）、用户
可见可编辑的记忆面板。
