# 28 · RAG 质量量化（Faithfulness / Relevance）

> 在 30 条文档语料上比较 3 种 chunking（切块建索引策略：整段 / 滑窗（滑动窗口）200 字 / 句级）：Relevance = 检索块与问题的 embedding（文本向量）相似度均值，Faithfulness = 答案逐句回溯检索证据（按字面重合率）算有支撑句占比；再注入幻觉句（与证据不符的生成内容）验证指标能否抓出幻觉。真机：nomic 检索 + qwen3.8 生成回答（3 题 × 3 chunking）。读完本篇，你能把"答错"归因到检索或生成两侧，并知道字面重合法这条路的边界。

## Background

RAG（Retrieval-Augmented Generation，检索增强生成：先从文档库检索相关片段，再让语言模型基于片段作答）系统上线后，最常见的评估方式是人工点开几个问答看感觉，或者只记一个笼统的"回答质量分"。

痛点出在归因：系统答错时，说不清是检索根本没检到相关内容，还是检到了但模型没照着检索结果说。两类问题的修法完全不同——前者要调切块和检索，后者要调提示词和生成模型——归因错了，调优就是在摸黑。换一种切块大小、换一个模型，效果好没好也只能靠感觉判断。

要把这条路修通，做法是把质量拆成检索侧与生成侧两个可量测的指标，再配上注入幻觉的对照实验来验证指标本身灵不灵。本实验实现这套量测，并在真机模型上诚实报告它抓到了什么、没抓到什么。

## What

本实验用两个指标分开归因 RAG 的质量问题：

- **Relevance** 管"检索得准不准"——检索块与问题的 embedding（语义越接近的文本，向量越相似）相似度取均值，低分归因检索问题；
- **Faithfulness** 管"说得对不对"——答案逐句回溯检索证据，按字面重合率算"有支撑句"的占比，低分归因生成问题，是幻觉的量化。

心智模型一句话：**检索问题与生成问题要分开量测——混在一个分数里就无法归因。**

可以把这两个指标想象成医院的两张化验单：一张查"取的样本对不对"（检索侧），一张查"诊断报告有没有依据"（生成侧）。但和化验单不同的是，这里的"有没有依据"用字面重合来判断，抽象改写的正确句子也会被误判，指标本身需要用对照实验标定，不能当成绝对真相。

## When to Use

双指标的价值在"改了之后能不能量化变好"。典型场景：

- 给 RAG 应用建质量基线时，换切块策略、换 embedding 模型、换生成模型前后各跑一遍，用数字而不是感觉判断回归。
- 排查"答非所问"的用户投诉时，先看两个指标谁低，决定去修检索还是修生成。
- 系统上线后做幻觉监控时，用 Faithfulness 持续打分，低分样本自动进人工复核队列。

何时不用：答案唯一的任务（直接规则判定即可）、不依赖文档检索的纯对话场景。对判定精度要求高的生产结论，字面重合法不够，要换更强的判定器（见 How It Works）。

同类方案对比：

| 方案 | 差异 | 什么时候选它 |
|:--|:--|:--|
| 单一"回答质量"总分 | 简单，但检索/生成问题无法归因 | 只需要粗粒度报警的场景 |
| 人工抽检 | 最可靠，慢、不可持续 | 上线前的最终把关 |
| Relevance + Faithfulness（本实验） | 两侧分开归因，可自动化 | 日常回归与线上监控 |
| RAGAS 等开源评测框架 | 指标更多、依赖更重 | 需要现成多指标体系时 |

## Quick Start

前置条件：Python 3，无第三方依赖。`MOCK=1` 用 hash 向量（用哈希值当向量的确定性假实现）+ 抽取式回答，离线可复现；不带 `MOCK=1` 时用 nomic 做检索向量、qwen3.8 生成回答，需要可用的模型服务。

```bash
cd qa/28_rag_quality
MOCK=1 python3 rag_quality.py    # 离线: hash 向量 + 抽取式回答
python3 rag_quality.py           # 真实: nomic + qwen3.8
```

`MOCK=1` 运行输出（节选）：

```text
==> 幻觉注入对照 (验证 Faithfulness 能抓幻觉)
  干净回答 Faithfulness = 1.00
  注入幻觉后 Faithfulness = 0.50 ✓ 被抓出
```

真机实测：

| chunking | 块数 | Relevance | Faithfulness |
|:--|:--:|:--:|:--:|
| whole | 30 | 0.648 | 0.44 |
| window | 30 | 0.648 | 0.44 |
| pair(句级) | 59 | **0.698** | 0.42 |

真机两个诚实的指标发现：

1. **幻觉对照未被抓出**（注入前后都 0.50）——字面重合法存在双向误差：抽象改写的正确句被判"无支撑"（低估），含共用词的幻觉句可能过阈值。结论：字面重合法只适合做初筛，生产 Faithfulness 要用 NLI（自然语言推理模型：判断两句话是否互为支撑的专用模型）或带引用要求的 LLM Judge。
2. 句级切块 Relevance 更高（0.698）且证据粒度精确，与"chunking 越细证据越准"的预期一致；Faithfulness 三者接近（qwen 回答抽象度高，字面支撑天然低）。

诚实预期：离线节选的 Faithfulness 读数（1.00 / 0.50）由假实现决定、逐次
一致；3 种 chunking 的离线 Relevance 每次运行在约 0.23~0.26 间浮动、只够
看量级。真机数值随模型与语料变化，"句级切块 Relevance 更高"的结构性结论
以真机实测为准。

## How It Works

流程分三段：先用三种切块策略把 30 条文档各建一个索引（whole 整段一块、window 滑窗 200 字、pair 句级两两成块，所以块数是 59 对 30——你在表格里看到的块数差异就来自这里）；检索时把问题转成向量，按相似度取回最相关的块，交给 qwen3.8 生成回答；最后计算两个指标。

Relevance 的算法：对取回的每个块算"块向量与问题向量"的相似度，取均值。句级切块的块更短、主题更集中，与问题的相似度更容易拉开，这对应表中 0.698 对 0.648 的差距。

Faithfulness 的算法：把答案拆成句子，逐句回溯检索证据，按字面重合率判断该句是否"有支撑"，取有支撑句的占比。离线实验验证了可检测性：注入幻觉后指标从 1.00 降到 0.50 立刻下降（运行输出见 Quick Start），所以生产上可以用它做线上幻觉监控，低分样本进人工复核队列。

但真机上注入幻觉前后都是 0.50（未被抓出），说明字面重合这把尺子在抽象改写面前会失灵，生产判定要升级到 NLI 或带引用要求的 LLM Judge。

## Pitfalls & Q&A

踩坑清单：

- 现象：注入了明显幻觉，Faithfulness 却没有下降。原因：字面重合法的双向误差——幻觉句与证据共用了一些词就可能过阈值（实测细节见 Quick Start 发现 1）。解法：字面法只做初筛；要下结论就换 NLI 或带引用要求的 LLM Judge。
- 现象：换了生成模型后 Faithfulness 集体走低，误以为系统变差。原因：生成端回答越抽象、改写越多，字面支撑天然越低（qwen 即属此类），指标随生成风格波动。解法：换生成模型后重新标定 Faithfulness 的基线，再比较，不做跨模型直接比大小。
- 现象：调块大小全凭感觉，改完说不清好坏。原因：没有可量测的验收指标。解法：用 Hit@k（前 k 个检索结果里包含正确证据的比例）+ Faithfulness 双指标驱动调参。

**Q: chunking 怎么选？**

没有万能解：句子级证据精确、整段上下文完整，要按任务的误差代价选择——漏一条证据代价高的场景偏向细粒度，上下文断裂代价高的场景偏向整段。用 Hit@k + Faithfulness 双指标驱动调参，而不是凭感觉定块大小。
