# 02 · CoT 失效场景解剖：何时该关 CoT

> 三类对 CoT 不利的任务（简单常识 / 干扰数学 / 隐藏意图），有/无 CoT 两种
> 模式跑正确率 + token 消耗。qwen3.8 实测：**A 类常识题 CoT 有害 -20%，
> 且 CoT 消耗 65 倍 token**。知道 CoT 什么时候没用，比知道它有用更有价值；
> 读完本篇，你能拿到一套数据驱动的"开/关 CoT"判断规则。

## Background

让模型"一步步思考"的提示技巧流行之后，许多应用把它当成默认增强手段：
不管问题难易，提示词里一律加上"请一步步思考"。教程演示的也多是复杂
题，看起来"写了推理过程总没坏处"。

全开的做法在两类情况下出问题：一是简单任务上推理过程纯属多余，token
（模型生成文本的最小单位）消耗成倍增长；二是在部分任务上，被迫生成的
推理链反而把答案带偏，正确率下降。开发者缺少一份可复现的数据来说明
边界在哪里。

本篇把边界做成实验：构造三类对"逐步推理"不友好程度不同的任务，同一
模型跑有/无逐步推理两种模式，用正确率和 token 消耗回答"什么时候该关"。

## What

CoT（Chain-of-Thought，思维链）是一种提示方法：要求模型先输出逐步推理
过程，再给最终答案（它的正收益场景与三种变体对比见 01 项目）。本篇
关注它的反面：任务不友好时会发生什么。

按"对 CoT 的友好度"，任务可分成三层：

| 类别 | 任务特征 | 预期 |
| :--- | :--- | :--- |
| A·简单常识 | 零推理需求（"首都哪里"） | CoT 零增益，白花 token |
| B·干扰数学 | 题面含无关数字诱导错误推理链 | CoT 推理链被带偏，正确率降 |
| C·隐藏意图 | 需理解隐含条件（折扣/倒数/合作） | CoT 推理链帮助理解题意 |

心智模型一句话：**CoT 不是默认该开的开关——它的价值取决于任务的推理
深度与干扰强度。** 例如"地球自转方向"这类问题，答案一个词就够，写入
推理过程只有坏处；而"先涨价 20% 再打 8 折"则需要推理链理清两次换算。

## When to Use

在为线上服务或评测脚本选择回答模式时，先判断任务属于哪一类：

- 做简单问答、FAQ（常见问题解答）类机器人，选直接回答——CoT 只会增加
  延迟和账单；
- 出数学评测题且题面可能混入无关数字时，先测目标模型的抗干扰能力；
- 应用题含隐含条件（折扣、倒数、合作完工），需要先理解题意再作答时，
  开 CoT。

何时不用 CoT 的判断规则（数据依据见 How It Works）：

- **A 类（简单常识）→ 关 CoT**：零增益 + 65 倍 token 浪费 + 实测 -20%；
- **B 类（干扰数学）→ 看模型**：qwen3.8（本系列实验默认使用的开源
  大模型）抗干扰能力足够，弱模型需实测；
- **C 类（隐藏意图）→ 开 CoT**：推理链帮助理解隐含条件。

四种候选方案的选型对比：

| 方案 | 差异 | 什么时候选它 |
| :--- | :--- | :--- |
| 直接回答 | 不写推理过程，token 最省 | 简单常识、高频短问答 |
| Zero-shot CoT | 一句指令让模型逐步思考 | 含隐含条件的中等复杂度任务 |
| Few-shot CoT | 附带人工编写的推理示例 | 复杂任务且需稳定输出格式 |
| 按任务分级启用 | 先判任务类型再选上面三种 | 生产系统，实现见文末问答 |

## Quick Start

前置条件：Python 3，无第三方依赖。真实模式默认连接本机 Ollama
（本地运行开源模型的工具，地址 `http://localhost:11434/v1`，模型
`qwen3.8:latest`）。

可通过环境变量 `LLM_BASE_URL` / `LLM_MODEL` / `LLM_API_KEY` 指向其他
OpenAI 兼容接口。

```bash
cd qa/02_cot_failure
MOCK=1 python3 cot_failure.py    # 离线：预置正误模式
python3 cot_failure.py           # 真实：qwen3.8 两种模式 × 15 题
```

MOCK 输出为预置演示数据（B 类 CoT -20%、C 类 +20% 为预设方向，5 题小
样本逐轮有浮动），与真机实测（A 类 -20%）不同；结论以真机表为准。

真机实测（每类 5 题，共 15 题）：

| 类别 | direct | CoT | 差异 |
| :--- | :--- | :--- | :--- |
| A·简单常识 | 4/5 | **3/5** | **-20% ←CoT 有害** |
| B·干扰数学 | 5/5 | 5/5 | +0% |
| C·隐藏意图 | 5/5 | 5/5 | +0% |
| **token 消耗** | **53** | **3476（65×）** | |

诚实预期：A 类 -20% 和 65 倍 token 都是实测结果，不是脚本故障；B、C
两类在 qwen3.8 上无差异，也符合其能力较强的表现。三条现象的机制解释
见下节。

## How It Works

**A 类为什么开 CoT 反而降分。** 简单题加 CoT 后，模型输出冗长的推理
过程——一个直接答"东方"就能得分的地球自转问题，CoT 版本写了一整段
自转方向的物理解释，冗余内容反而干扰了简单答案的提取。表中 4/5 → 3/5
就来自这条机制。

**B 类为什么没有差异。** 干扰数字既没有带偏直接回答，也没有影响 CoT
推理链，这是 qwen3.8 指令遵循能力（按提示词要求行事的能力）足够强的
表现。换言之，"CoT 会被带偏"是任务与模型能力的联合结果，不是 CoT 的
必然缺陷。

**token 为什么是 65 倍而不是预期的 2-3 倍。** 53 字符对 3476 字符：
CoT 输出包含完整的 markdown 格式（带标题、列表等排版标记的文本格式）
推理过程，篇幅远超答案本身。生产系统按 token 计费时，这笔开销必须
计入。

**本质局限。** 推理链可能被题面无关信息带偏，且"逐步思考"不保证每步
正确——错误的中间结论会传导到最终答案。因此判断规则不是二分法而是
连续谱：按任务的推理深度和干扰强度动态调整，而不是全开或全关。

## Pitfalls & Q&A

踩坑清单：

- **现象：简单常识题开了 CoT 后答错。** 原因：冗余推理干扰答案提取
  （A 类机制）。解法：这类任务切回直接回答模式。
- **现象：接入 CoT 后 token 账单远超预期的 2-3 倍，达到几十倍。**
  原因：推理过程附带完整 markdown 排版，篇幅远超答案。解法：按任务
  分级启用，简单任务不开 CoT。
- **现象：换一个更弱的模型，B 类干扰题开始出错。** 原因：抗干扰能力
  依模型而异，qwen3.8 的结果不能直接外推。解法：换模型后用同一分层
  题集重测。

**Q: 生产上怎么实现自动分级？**

按任务类型分级启用 CoT——简单题直接回答、中等题 Zero-shot CoT、复杂题
Few-shot CoT；或训练一个分类器（根据输入特征自动预测类别的模型）预判。
评估方法：三类分层题集 + 有/无 CoT 对照 + 关键词判分。
