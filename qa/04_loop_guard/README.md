# 04 · ReAct 死循环检测与防护

> Agent 死循环不报错、不崩溃，只是烧钱空转。四层防护（defense in depth）：
> L1 步数上限 / L2 重复 Action / L3 Thought 相似度 / L4 预算熔断
> （token+耗时），任何一层触发即输出诊断并**强制"失败总结"**——不空转、
> 不静默截断。

## What

| 层 | 信号 | 抓什么循环 | 参数 |
|:--|:--|:--|:--|
| L1 步数上限 | 执行轮数 | 硬兜底，漏网循环最终被它拦 | max_steps=8 |
| L2 重复 Action | (action, input) 签名 | 撞墙式重试（连续 3 次完全相同） | repeat_limit=3 |
| L3 Thought 相似度 | 相邻思考文本编辑相似度 | 换汤不换药的复读（输入微调、思考没变） | ≥0.85 |
| L4 预算熔断 | 累计 token / 耗时 | 每步都不同但永不收敛的资源空转 | 1200 est.tokens / 30s |

三层在线信号互为补充——L2 看**行为**、L3 看**语义**、L4 看**资源**，
单一信号都会误报/漏报；L1 不参与判断，只负责兜底。触发后统一走
`force_summary()`：把防护原因喂回模型，要求基于已有 Observation 产出
失败总结。

心智模型一句话：**从外到内观察 Agent 是否在推进——行为、语义、资源
三层互补，兜底另设一层。**

## Why

死循环来自降级模型、重试逻辑 bug，特征是"不报错、只在烧钱"。只设
max_steps 一道防线，要么误杀慢任务、要么漏掉"每步都不同但永不收敛"的
空转——防护需要分层，且触发后要有意义地收尾，而不是静默截断。

## How

```bash
cd qa/04_loop_guard
MOCK=1 python3 loop_guard.py    # 离线：脚本化病态策略，结果确定
python3 loop_guard.py           # 真实：S1 真模型首轮决策+卡带重放注入
```

实测（离线 mock / 真机各跑一轮，两轮全绿）：

| 场景 | 期望层 | 实际层 | 触发步数 | 结果 |
|:--|:--:|:--:|:--:|:--|
| S1 工具恒失败（航班服务恒 503） | L2 | L2 | 3 | ✓ 拦截 + 失败总结 |
| S2 模型复读（忽略 Observation 反复查天气） | L3 | L3 | 2 | ✓ 拦截，且总结里把已有答案捞了回来 |
| S3 目标矛盾（北京/上海出发反复摇摆） | L4 | L4 | 5 | ✓ token 熔断 |
| S3 消融（关掉 L4） | L1 | L1 | 9 | ✓ 步数上限兜底 |

真机说明：健康模型不会自己死循环——qwen3.8 对故障工具**一次失败即自行
finish**（还附上替代建议）。所以 S1 采用"真模型首轮决策 + 卡带重放注入"：
第一轮是真实 LLM 对真故障工具的真实决策，之后原样重放模拟卡死的 Agent，
L2 拦截与强制总结（由真模型产出）在真机上确定可复现。

## Deep Dive

**拦截的价值是交接而非止血**：S2 里答案其实第一步就拿到了，复读只是掩盖
了已有 Observation；强制总结把半成品结果交接出来——这是护栏的核心价值。

踩坑清单：

- **层间要划清语义边界**：完全相同的决策归 L2 管，L3 必须让位——否则
  相似度 1.00 会在第 2 步抢先触发，"连续 3 次"永远数不满（实测踩到后用
  identical-streak 修复）。

## Q&A

**Q1: 最大步数怎么设？**

它是兜底不是唯一防护；按任务复杂度分级（简单 3-5 / 研究型 10-20），触发
后必须强制总结、有意义地收尾，而不是静默截断。

**Q2: 怎么测防护？**

死循环来自降级模型/重试逻辑 bug，健康模型测不出防护——要注入病态策略：
离线用脚本化策略，真机用重放注入，才能稳定复现尾部风险。
