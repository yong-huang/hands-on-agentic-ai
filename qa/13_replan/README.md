# 13 · 规划失败检测与重规划

> 团建组织管线注入 3 类失败各 1 次：①工具瞬断（场地查询 504）→ 重试；
> ②前提失效（20 座大巴无货）→ 改路（改订 2 辆 10 座）；③规划错误
> （餐厅预算 3000 超剩余额度 2000）→ 全局重规划。每步有断言式校验器，
> 失败按错误签名分类到 RETRY/ALTERNATIVE/REPLAN。真机对照 LLM 分类器。

## What

失败分类决定响应——三类失败三种处置：

| 失败类型 | 例子 | 响应 |
|:--|:--|:--|
| 工具瞬断 | 查询 504 | RETRY 重试 |
| 前提失效 | 20 座大巴无货 | ALTERNATIVE 改路 |
| 规划错误 | 预算超额 | REPLAN 全局重排 |

心智模型一句话：**一律重试会把错误计划执行三遍——先分类，再响应。**

## Why

执行管线必然遇故障，但不同失败的正确响应完全不同：瞬断重试就能好，
前提失效要换路，规划本身错要重排。响应错了轻则浪费、重则把错误计划
执行到底。

## How

```bash
cd qa/13_replan
MOCK=1 python3 replan.py    # 离线: 注入故障全规则处置
python3 replan.py           # 真实: 追加 LLM 失败分类对照
```

实测：三类失败分别走对 重试/改路/重规划，管线最终完成 ✓；真机 LLM
分类器对 3 个失败样例与规则判定 3/3 一致（504→RETRY、无货→ALTERNATIVE、
超额→REPLAN）。

决策轨迹（节选）：

```
[step 2] 订场地 -> ERROR: 504  ✗ 分类=RETRY
         ↳ 响应[重试] 第 2 次尝试 -> 湖畔厅预订成功 ¥1200 ✓
[step 3] 订 20 座大巴 -> ERROR: 无可用车型 ✗ 分类=ALTERNATIVE
         ↳ 响应[改路] -> 10 座中巴 ×2 ¥800 ✓
[step 4] 订餐厅 ¥3000 -> WARNING 超剩余额度 ✗ 分类=REPLAN
         ↳ 响应[重规划] 剩余计划改为 餐厅¥1800 -> 预算重算 ✓
```

## Deep Dive

**先校验再行动**：断言式校验器分两层——结果形状（ERROR/正常）+ 语义
（表面成功但违反预算约束）。第三类失败最隐蔽，专抓"假成功"。

**重规划 ≠ 从头再来**：只重排受影响的剩余子目标，已完成结果复用（与
[31 断点续跑](../31_checkpoint_resume/README.md)同一思想）。

## Q&A

**Q1: 为什么"假成功"是最隐蔽的失败？**

工具返回了正常响应，但结果违反了任务约束（餐厅订到了、预算爆了）——
形状校验层完全放行，只有语义校验层（对照任务约束的断言）能抓住。

**Q2: 规则分类器和 LLM 分类器什么关系？**

规则分类器按错误签名确定性分类，是默认路径；LLM 分类器处理规则覆盖
不到的模糊失败——本实验真机对照 3/3 一致，说明三类边界场景下两者可
互为校验。
