# 29 · Agent 可观测性（Tracing + 回放）

> 给一次确定性 Agent 执行（规划 → 3 个工具调用，含一次异常重试）埋点：
> JSONL 事件流落盘 → trace 树 CLI 渲染 → 成本/延迟统计面板 → 时间旅行
> 回放（读回事件，不调任何模型逐步重放）。全流程离线可跑。

## What

可观测性的核心是 span 事件模型：每个 span 记
类型/父子关系/输入输出/token/耗时/异常，JSONL 落盘——事后一切分析
（树/统计/回放）都从它派生。

心智模型一句话：**一切皆事件——渲染、统计、回放都只是同一份事件流的
不同视图。**

## Why

Agent 执行是黑盒：出错要定位"谁调了谁、哪一步炸了"，优化要知道
"贵不贵、慢不慢"，复盘要能离线重放现场——没有事件流，这三件事都
只能靠猜。

## How

```bash
cd qa/29_observability
python3 observability.py    # 生成事件 -> 渲染 -> 统计 -> 回放
```

实测（全离线确定）：5 个 span 落盘并一致回放（5=5 ✓）。trace 树一眼
看清调用结构与异常：

```
[agent] root (0ms)
  [llm] planner (25ms, 180 tok)
  [tool] 查库存 (24ms, 40 tok)
  [tool] 查价格 (42ms, 40 tok) ⚠ 第一次尝试失败: 价格服务 503
  [tool] 下单 (23ms, 40 tok)
```

统计面板：spans=5，总 token=300，估算成本 ¥0.0006，P99 延迟 39ms，
工具调用 {查库存:1, 查价格:1, 下单:1}，异常 span 1（重试后成功）。

## Deep Dive

**三类视图各答一个问题**：trace 树回答"谁调了谁"——排障先找异常 span
再下钻输入输出；统计面板回答"贵不贵、慢不慢"（token 成本 + P99 延迟）；
时间旅行回答"当时发生了什么"——用记录的事件离线复现执行路径，不调
模型，调试、回归测试、故障复盘都靠它。

生产同构：LangSmith/Langfuse/OTel 的 span 模型与此一致——本篇实现的
是最小核。

## Q&A

**Q1: 为什么坚持 JSONL 事件流而不是直接存渲染结果？**

事件是原始事实，树/面板/回放是派生视图——存了事件随时能补新视图；
只存渲染结果则每个新分析需求都要重新跑一遍 Agent。
