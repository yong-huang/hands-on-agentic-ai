# 11 · Reflection 反思机制

> 客服场景事件流（9 条记忆），每 3 条触发反思：把近期记忆归纳为高层
> 洞察，按 重要性×新近性（半衰期 72h）打分入库。同一模糊问题对比
> 有/无 Reflection 的回答质量（真机 LLM-as-Judge）与洞察引用数。

## What

Reflection（Generative Agents）机制三要素：

- **触发器**：每累计 N 条记忆反思一次，流水账蒸馏为高层洞察；
- **打分**：重要性 × 新近性（指数衰减）决定检索权重；洞察与原始记忆
  同池竞争——分层而非替换；
- **价值边界**：原始记忆回答"发生过什么"，洞察回答"客户是谁、什么
  有效"。

心智模型一句话：**Reflection 是记忆的蒸馏器——但蒸馏只在原液太多时
才有价值。**

## Why

Reflection 常被当成免费增益。本篇用同题对照实测它的适用边界：强模型 +
少量记忆的场景下是否有增益、还是反而跑题。

## How

```bash
cd qa/11_reflection
MOCK=1 python3 reflection.py    # 离线: 预置洞察与回答 (引用 0 vs 2, 2.0 vs 4.4)
python3 reflection.py           # 真实: qwen3.8 做反思、作答与评分
```

真机实测出现**反常**：无 Reflection 版 4.0 分（回答主动覆盖电话偏好 +
VIP 身份，洞察引用 2/2）；有 Reflection 版 3.0 分（引用 1，且倾向元分析
式跑题）。两轮测量稳定（-4.0 → 修复 Judge 解析后 -1.0）。

诚实结论：**qwen3.8 这类强模型 + 少量记忆的场景下，原始记忆已足够支撑
高质量回答，Reflection 无增益甚至负增益**——洞察上下文反而诱发模型
"先分析再行动"的跑题。离线模式用抽取式基线（0 引用/2.0 分 vs 2 引用/
4.4 分）复现了机制的理想收益。

## Deep Dive

**Reflection 的适用前提**：记忆量大到原始条目互相淹没、或模型较难自发
归纳时，蒸馏出的洞察才有检索价值；强模型小记忆场景收益趋零甚至为负
（本实验实测数据背书）。检验洞察是否真被使用，看**洞察引用计数**——
行为指标比主观评分硬。

## Q&A

**Q1: 什么时候该上 Reflection？**

两个前提满足其一：记忆量大到原始条目互相淹没，或模型较难自发归纳。
都不满足时，洞察上下文反而诱发"先分析再行动"式跑题——先测再上。
