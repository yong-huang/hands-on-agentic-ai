# 27 · Agent 评测 Harness + LLM-as-Judge

> 20 任务双通道评测：可判定集（有唯一答案、规则能判的任务）由规则评分器与 LLM-Judge（用一个 LLM 给模型输出打分的评审员）对跑 0/1 分、测一致率（判定相同的比例）；开放集（无唯一答案）仅 Judge 按 rubric（评分细则）打 1-5 分；偏见实验对同一答案换身份标注（GPT-4 vs 7B 小模型）与换位置（A/B 对比顺序）。读完你能搭起带验收线的评测 harness（评测框架），并会用探针实测自己的 Judge。

## Background

自动化评测 Agent（自主多步执行任务的程序）输出，最直接的做法是规则评分器：精确匹配、关键词包含这类程序化判断，类似单元测试的断言。答案唯一或可枚举时，它免费、稳定、可复现。

规则判不了的是开放任务：写一段文案、出一个方案，没有唯一答案，程序写不出判定条件。传统做法只能人工评审，而人工慢、贵、标准因人而异——待评测的版本一多（换提示词、换模型都要回归一遍），人工评测就成瓶颈。

对这个空档，目前的通行手段是 LLM-as-Judge：用一个 LLM 按给定标准给另一个模型的输出打分，让开放式任务也能规模化回归。但 Judge 本身也是模型，它可靠吗、偏见有多严重，不能靠引用结论，要在自己的场景里实测。本实验就是一套这样的实测。

## What

Harness（评测框架）负责组织任务、调用被测模型、汇总分数；LLM-as-Judge 是其中负责打分的评审员。本实验把评测拆成双通道，外加一组偏见探针（probe，用受控对照样本专门检验某一偏见是否存在的小实验）：

- **可判定集**：规则评分器与 LLM-Judge 对跑，测一致率——能规则判定的绝不劳烦 Judge；
- **开放集**：仅 LLM-Judge，必须带 rubric（评分细则：维度 + 分值定义），否则打分不可复现；
- **偏见探针**：同一答案换身份标注、换对比位置——"评测自己的评测器"。

心智模型一句话：**Judge 分数只做排序不做绝对结论——关键评测仍以规则/人工为准。**

可以把 LLM-Judge 想象成外聘的阅卷老师：批主观题快，多少份都接得住。但和阅卷老师不同的是，这位老师自己也有偏好（倾向于某类来源、某个位置、更长的答案），且没有标准答案兜底，所以上岗前要先用探针考察老师本身。

## When to Use

是否引入 Judge，看任务有没有唯一答案、评测要跑多少遍。典型场景：

- 给聊天、写作、方案类开放任务做回归评测时，每次改提示词或换模型都要重新比较几十上百个回答，人工评不过来。
- 对比多个候选版本（不同模型、不同提示词）时，需要的是"哪个更好"的排序，Judge 的分数形态正好匹配。
- 可判定集之外的长尾任务里，需要一条统一口径的自动化评分线时。

何时不用：任务有精确答案时直接写规则评分器，零成本且无偏见；影响上线或结算的最终结论，Judge 只能做初筛，仍需人工复核。

同类方案对比：

| 方案 | 差异 | 什么时候选它 |
|:--|:--|:--|
| 规则评分器 | 免费可复现，只覆盖有唯一答案的任务 | 可判定集的默认选择 |
| 人工评审 | 最可靠，慢且贵、标准漂移 | 小样本抽检、最终裁决 |
| LLM-as-Judge（本实验） | 开放任务可规模化，需校准与探针 | 开放集的批量回归与排序 |
| 人工 + Judge 混合 | Judge 初筛 + 人工复核低分样本 | 预算有限又要兜底的团队 |

## Quick Start

前置条件：Python 3，无第三方依赖。`MOCK=1` 使用预置回答与预置评分（离线、确定性）；不带 `MOCK=1` 时由 qwen3.8 当 Judge（5 判定 + 2 开放 + 4 探针），需要可用的模型服务。

```bash
cd qa/27_eval_judge
MOCK=1 python3 eval_judge.py    # 离线: 预置回答与评分 (偏见两种均复现)
python3 eval_judge.py           # 真实: qwen3.8 当 Judge (5 判定 + 2 开放 + 4 探针)
```

`MOCK=1` 运行输出（节选）：

```text
==> 可判定集 (规则 vs Judge)
  gold=4     ans=4        规则=1 judge=1 ✓
  ...
一致率: 10/10 = 100% (验收 >=80%) ✓

==> 开放集 (LLM-Judge rubric 1-5)
  ...
均值: 4.09

==> 偏见实验 (同一答案)
  身份偏差: GPT-4=4.6 vs 小模型=3.4 -> 分差 1.2 ✓ 复现
  位置偏差: A在前选A=4.2 B在前选B=3.5 -> ✓ 复现(位置翻转选择)
```

离线一致率/均值为预置数据，与真机表数字不同属预期。

真机实测：

| 指标 | 结果 |
|:--|:--|
| Judge 与规则评分一致率 | **5/5 = 100%**（验收 ≥80% ✓） |
| 开放集 rubric 均值 | 4.0 |
| 身份偏差（GPT-4 vs 小模型） | 分差 0.0 · 未复现 |
| 位置偏差（A/B 换序） | 两次都选更优答案 · 未复现 |

两个反直觉发现：(1) qwen3.8 当 Judge 与规则完全一致——可判定任务上 Judge 是可靠的；(2) 两个经典偏见在真机 Judge 上都未复现（身份标注与顺序不影响判断）——**偏见主要存在于小模型 Judge / 长列表对比场景**，把"偏见存在"背成教条不如实测自己的 Judge。

离线模式复现了两种偏差（4.6 vs 3.4；A/B 换序翻转），验证了实验设计的可检测性。诚实预期：离线结果是预置数据、逐字复现；真机结果随 Judge 模型与版本变化，偏见可能复现也可能不复现——这正是要先探针再下结论的原因。

## How It Works

双通道各走各的验收：可判定集上，同一批回答分别交给规则评分器与 Judge 打 0/1 分，统计两者一致的比例，验收线 ≥80%——你在 Quick Start 表格里看到的 100%，就是 5 个判定任务全数一致的结果。开放集没有规则可对跑，Judge 直接按 rubric 的维度与分值打 1-5 分。

偏见探针是本实验的核心方法：拿同一份答案，只改动一个可疑变量。身份探针把答案的来源标注在"GPT-4"与"7B 小模型"之间切换；位置探针在 A/B 对比中交换两个答案的顺序；冗长探针注入更长的答案。偏见如果存在，换变量就会复现分数差异；不存在，就能在自己场景下排除。

离线模式在这套探针上复现了偏差（身份标注不同导致 4.6 vs 3.4，A/B 换序翻转了选择），这一步不是多余——它证明探针本身足够灵敏。否则真机上"未复现"会有另一种解释：探针根本测不出偏见。缓解手段：匿名化来源、随机化位置、多次取样取均值。

## Pitfalls & Q&A

踩坑清单：

- 现象：同一个答案两次评分结果不同，打分不可复现。原因：开放集没给 rubric，Judge 按自己的默认标准自由发挥。解法：rubric 必须带维度与分值定义，把评分标准写进提示。
- 现象：论文里说好的偏见，在自己的 Judge 上测不出来（或反过来，莫名出现）。原因：偏见与 Judge 模型、任务形态强相关——小模型 Judge、长列表对比场景更易出现。解法：用探针实测自己的 Judge，实测可复现或可排除，都比背教条可靠。
- 现象：拿 Judge 的 4 分直接当"质量达标"的上线依据。原因：把排序用分数当成了绝对结论。解法：Judge 分数只用于排序比较，绝对结论交给规则评分或人工。

**Q: LLM-as-Judge 怎么设计才可靠？**

三条：只处理规则判不了的开放集；rubric 带维度与分值定义（否则打分不可复现）；分数只用于排序比较，绝对结论交给规则评分或人工（通道划分见上文 How It Works）。
