# 23 · Generator-Critic 辩论模式

> 20 道易错题（运算顺序/单位换算/经典脑筋题陷阱）三种模式对跑：
> direct（1 次调用）/ cot（1 次调用）/ debate（生成器起草 → 评审挑错 →
> 生成器修订，3 次调用）。答案可程序判定，输出正确率与成本对比。

## What

三种回答模式的成本结构：

| 模式 | 流程 | 每题调用 |
|:--|:--|:--:|
| direct | 直接作答 | 1.0 |
| cot | 单模型逐步推理 | 1.0 |
| debate | 生成器起草 → 评审挑错 → 生成器修订 | 3.0 |

心智模型一句话：**辩论的收益 = 可验证的易错任务 × 错误的高代价——
两个因子都不满足时，3 倍成本白花。**

## Why

"多 Agent 协作比单 Agent 好"是常见直觉，但多 Agent 有真实的成本与
复杂度。它到底什么时候赢，要拿单 Agent + CoT 这个强基线对跑——打不过
基线就不该上多 Agent。

## How

```bash
cd qa/23_generator_critic
MOCK=1 python3 generator_critic.py    # 离线: 确定性模型, 20 题全量
python3 generator_critic.py           # 真实: qwen3.8, 6 道代表题
```

真机实测（6 道代表题）：三种模式 6/6 全对（代表题上 qwen3.8 已是天花板，
正确率拉不开）；成本差异如实呈现。离线 20 题全量（确定性难度模型）：
direct 8/20 → cot 13/20 → debate 20/20，单调提升，辩论成本 3 倍。

## Deep Dive

**辩论的价值边界**：评审 Agent 提供独立视角，修订能挽回初答的粗心
错误——前提是答案可验证、错误可被指出；开放式创作任务收益趋零。成本
是"质量价格"：debate 每题 3 次调用换正确率，错误代价高的场景（下单/
发邮件）才划算。

## Q&A

**Q1: 什么时候该上多 Agent 协作？**

同时满足两个条件：任务易错但可验证（评审的意见有判据），且错误代价高
（值得付 3 倍调用）。先跑单 Agent + CoT 基线——多 Agent 打不过它就
别上。
