# 07 · 短期记忆管理器（窗口 + 摘要压缩）

> 20 轮长对话，前几轮埋 5 个关键事实（姓名/城市/截止日/预算/咖啡偏好），
> 两种超限策略对跑：滑动窗口（丢最旧）vs 摘要压缩（LLM 归纳旧对话）。
> 第 20 轮提问 5 个事实，统计保留率。

## What

上下文窗口放不下 20 轮对话时的两种超限策略：

- **滑动窗口**：只留最近 N 轮，旧的直接丢——零成本、可预测，但"最近的
  才存在"，早期事实整段蒸发；
- **摘要压缩**：LLM 把旧对话归纳成摘要——保留语义骨架，但细节（数字/
  日期/专名）最易被抹平，且每次压缩多一次 LLM 调用与延迟。

实验用保留率量化两种丢失：预算 350 est.tokens 人为收紧，使 20 轮必然
多次溢出（窗口截断 5 次 / 摘要压缩 1 次均真实触发）。

心智模型一句话：**窗口确定性丢早期，摘要不可预测地丢细节——选哪种，
取决于你丢不起哪种。**

## Why

长对话的第一堵墙是上下文窗口溢出。两种策略的丢失模式完全不同，但多数
描述停留在定性——本篇埋 5 个事实、第 20 轮提问，用保留率给出可复现的
定量对比。

## How

```bash
cd qa/07_short_memory
MOCK=1 python3 short_memory.py    # 离线: 窗口机械执行 + 摘要走预置
python3 short_memory.py           # 真实: qwen3.8 做摘要与最终问答
```

实测（预算 350 est.tokens）：

| 事实 | 滑动窗口 | 摘要压缩(真机) |
|:--|:--:|:--:|
| 姓名(T1) | ✗ | ✓ |
| 城市(T1) | ✗ | ✓ |
| 截止日(T2) | ✗ | ✓ |
| 预算(T2) | ✗ | ✓ |
| 咖啡(T16) | ✓ | ✓ |
| **保留率** | **1/5** | **5/5** |

真机 qwen3.8 的摘要把预算细节也保留了（提示词要求"必须保留数字"）——
摘要压缩的下限很高，但代价是每次压缩一次 LLM 调用，且失败模式从
"确定性丢失"变成"不可预测的漏记"。两种策略各自的丢失场景：窗口确定性
丢早期（实测保留率 1/5），摘要丢细节（离线预置摘要抹掉预算后 4/5 可
复现）。

## Deep Dive

**失败模式的性质差异比保留率数字更重要**：窗口的丢失是确定性的——
你知道哪些轮次一定没了，可以针对性补救；摘要的丢失是概率性的——哪条
细节被抹平不可预测，无法在事前兜底。生产系统必须按"丢得起哪种"来选。

## Q&A

**Q1: 生产上怎么组合？**

组合拳：窗口保近期原文 + 摘要保远期骨架 + 关键事实抽取进长期记忆库
