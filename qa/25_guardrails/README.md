# 25 · 越狱防护与 Guardrails

> 双层护栏串联：规则层（关键词/正则硬特征，0 LLM 成本直接拦）+ 模型层
> （仅"可疑但没露馅"的请求进 LLM 分类器，fail-safe 解析失败即拦）。
> 测试集：10 条越狱尝试 + 10 条正常请求（含易误伤的教育性边界题）。

## What

| 层 | 手段 | 特点 |
|:--|:--|:--|
| 规则层 | 关键词/正则硬特征 | 毫秒级、可解释、0 成本；软肋是变体绕过（谐音/编码） |
| 模型层 | LLM 分类器只复核灰区请求 | 准；软肋是成本与误伤 |

心智模型一句话：**规则与模型两层都要——规则拦特征明显的，模型兜
语义灰区的。**

## Why

规则护栏挡得住"角色扮演越狱"这类硬特征，挡不住谐音/编码变体；全量
走模型分类既贵又慢，还有误伤。护栏的正确形态是串联分层，让每层只做
自己擅长的那一段。

## How

```bash
cd qa/25_guardrails
MOCK=1 python3 guardrails.py    # 离线: 确定性双层模拟
python3 guardrails.py           # 真实: 可疑请求真的过 qwen3.8 分类器
```

真机实测：**越狱拦截 10/10，正常误伤 0/10**；全程模型层仅 1 次调用
（其余全被规则层 0 成本拦下）。

| 指标 | 结果 |
|:--|:--:|
| 越狱拦截 | 10/10 ✓ |
| 正常误伤 | 0/10 ✓（含"反诈中心是做什么的"等边界题） |
| 模型层调用 | 1 次 |
| 规则层成本 | 0 次 |

## Deep Dive

**分层串联的经济性**：实测 20 条请求只有 1 条需要模型——规则层把
95% 的流量以零成本处理，模型层的成本与延迟只花在真正的灰区上。
**fail-safe 原则**：分类器解析失败一律按拦截处理，宁可误伤不可漏放
——护栏的错误方向必须偏向安全。

## Q&A

**Q1: 护栏用规则约束还是模型判断？**

两层都要，且要说清各自失败模式：规则的软肋是变体绕过（所以要留模型
层兜灰区），模型的软肋是成本与误伤（所以不能全量走模型）。只答其一
都意味着没测过误伤率与成本。
