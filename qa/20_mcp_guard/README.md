# 20 · MCP Server 安全加固

> 给[项目 19](../19_mcp_server/README.md) 的书店 Server 包一层服务端
> 安全网关：①参数白名单（字段/类型/范围）②只读/读写权限分离 ③调用
> 审计 JSONL ④每 client 限速 ⑤参数注入特征扫描（提示词/SQL）。5 条
> 恶意调用 + 3 条正常回归验证。

## What

五层安全网关，全部在 server 侧强制执行：

| 层 | 挡什么 |
|:--|:--|
| 限速 | 滥用/打爆 |
| 权限分离 | 只读会话调写操作 |
| 参数白名单 | 白名单外字段、超范围值 |
| 注入扫描 | 参数里藏指令/SQL |
| 审计 | 兜底留痕（谁/何时/哪层/为什么） |

心智模型一句话：**服务端是唯一可信边界——客户端/模型侧的约束都能被
注入绕过。**

## Why

模型和客户端都不可信：工具参数是模型可控输入，藏在里面的恶意指令与
提示词注入同源。约束只在客户端做等于没做——最小权限必须是 server 侧
的 schema 与中间件，不是文档里的建议。

## How

```bash
cd qa/20_mcp_guard
MOCK=1 python3 mcp_guard.py    # 打安全网关 (拦截矩阵)
python3 mcp_guard.py serve     # 亦可作为加固版 MCP Server 被 stdio 拉起
```

实测：

| 攻击 | 拦截层 | 结果 |
|:--|:--|:--|
| 白名单外字段 admin=true | whitelist | ✓ 拒绝 |
| qty=1000000 超范围 | whitelist | ✓ 拒绝 |
| sku 藏 `drop table users;--` | injection | ✓ 拦截 |
| sku 藏"忽略之前所有指令…" | injection | ✓ 拦截 |
| 只读会话调 place_order | permission | ✓ 拒绝 |

**拦截 5/5，正常调用 3/3 不受影响，审计日志 8 条**（每条含
client/tool/verdict/layer/args）。

## Deep Dive

**纵深是有顺序的**：限速挡滥用 → 权限挡越权 → 白名单挡畸形 → 注入
扫描挡劫持 → 才轮到业务逻辑。每层的拒绝理由不同、审计要记命中层——
事后复盘"哪类攻击最多"全靠这一字段。

## Q&A

**Q1: 注入检测为什么盯参数？**

工具参数是模型可控的自由文本输入，藏在里面的指令（"忽略之前所有
指令…"）与 SQL（`drop table users;--`）和网页注入同源同罪——参数在
进入业务逻辑前必须过特征扫描。

**Q2: 白名单外字段为什么要直接拒绝而不是忽略？**

`admin=true` 这类字段被忽略时，攻击者可以慢慢试探哪些字段生效；直接
拒绝让探测立刻暴露，也让 schema 成为最小权限的执行载体。
