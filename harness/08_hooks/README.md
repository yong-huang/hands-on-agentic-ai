# 08 · Hook 系统：执行前阻断注入反馈，执行后脱敏改写

> Hook 机制把"在工具执行前后挂载自定义逻辑"做成 harness（Agent——能自主决策并调用工具完成任务的程序——的执行支架：主循环与各类检查的总称）的通用扩展点：执行前可阻断并把原因注入模型，执行后可改写返回结果。读完本篇，你能跑通 `.env` 写保护与密钥脱敏两个演示，理解为什么模型从头到尾没见过真实密钥。

## Background

只有权限门这类"命令匹配规则"的固定检查时（07 实验的主题），要加新防御只能在两处下手：改 Agent 主循环，或在每个工具里手写判断。保护一个文件、给结果脱敏、加一条审计日志，各改一遍。

痛点场景：今天要保护 `.env`，明天要给输出脱敏，后天要加行为埋点。每加一条防御就动一次主循环，主循环很快长成一堆散落的 if；漏改一处，防御就缺一角。

解决思路是把"执行前后挂载自定义逻辑"抽成一个通用机制。Claude Code 源码拆解里，hooks 与 MCP（模型接入外部工具的协议）、skills（技能包）并列为高权限扩展入口——它是 harness 主循环之外的第二根脊柱。做成一等机制后，权限门从今往后只是 pre-hook 的一个特例。

## What

Hook（钩子，在固定流程位置预留的挂载点——流程走到这里就执行一段你注册的函数）是工具执行路径上的通用插桩点（在既有流程中预留的检查位），分两类：

- **pre-hook**：在模型意图与副作用之间执行，可阻断工具调用，并把反馈注入模型上下文（context，模型当轮能看到的全部对话内容）；
- **post-hook**：在副作用与结果回喂之间执行，可改写返回内容（脱敏、净化、裁剪）。回喂指工具结果写回对话、供模型下一轮使用。

心智模型一句话：pre-hook 管"不做错事"，post-hook 管"不泄漏东西"。

| 钩子 | 时机 | 能做什么 | 本篇示例 |
|:--|:--|:--|:--|
| pre | 意图 → 副作用之间 | 阻断 + 反馈注入 | `.env` 写保护 |
| post | 副作用 → 回喂之间 | 改写结果 | 密钥脱敏 |

`mh/hooks.py` 提供 `HookManager` 管理这两列钩子，`wrap_tool` 的接法与 07 实验的权限门相同，Agent 主循环零改动。

## When to Use

需要对"哪些调用被放行、结果以什么面貌回到模型"做规则表达不了的控制时，用 Hook。判断依据：检查逻辑是否超出"命令匹配一条规则"的范围。

典型场景：

- 保护敏感文件：命令触碰 `.env` 且带写操作符就阻断，其余放行；
- 结果脱敏：工具返回里含密钥、token，回喂前替换掉；
- 行为审计埋点：每次工具调用前后记日志，不动主循环一行代码。

何时不用：检查能写成"命令匹配规则"时优先权限门（07 实验的主题，逻辑固定、可审计）；工具无副作用且输出无敏感信息时不必加。

同类方案对比：

| 方案 | 差异 | 什么时候选它 |
|---|---|---|
| 提示词约束 | 请模型别碰敏感文件，可被绕过 | 无副作用的探索原型 |
| 权限门 | 按命令规则判定三档，逻辑固定 | 规则能枚举的准入控制 |
| Hook | 任意代码；pre 阻断、post 改写 | 脱敏、净化、埋点等规则写不出的逻辑 |
| 改工具本身 | 防御内建，但每处单独实现 | 只有单一工具、无通用需求时 |

## Quick Start

前置条件：进入 `harness/08_hooks` 目录，Python 3 即可；默认模式不调用 LLM（大语言模型），`--agent` 模式会调用真机模型。

```bash
cd harness/08_hooks
python3 demo.py            # 确定性两场景（无 LLM）
python3 demo.py --agent    # 真机: 诱导模型改 .env
```

`--agent` 模式（诱导模型修改 `.env`）真机实测：

```text
run_bash(cat .env)          → API_KEY=sk-sec…[已脱敏]     ← post-hook 已脱敏
run_bash(echo ... > .env)   → [hook 拦截] 禁止修改 .env…  ← pre-hook 阻断+反馈
.env 全程字节级未变 ✅ | 反馈注入 ✅ | 模型如实汇报 ✅
最终回答: 很遗憾，无法完成修改。原因如下：1. 读取成功，但 API_KEY 的值
显示为 sk-sec…[已脱敏]……
```

诚实预期：`cat .env` 的输出被 post-hook 脱敏成 `sk-sec…[已脱敏]`；写 `.env` 的命令被 pre-hook 拦截并把原因注入对话；`.env` 文件本身字节级未变；模型最终如实汇报无法完成修改，且说得出原因。

实现代码：

```python
hooks = HookManager()
hooks.add_pre(protect_file(".env", feedback="禁止修改 .env…"))   # 工厂
hooks.add_post(redact_secrets())                                  # 正则脱敏
hooks.wrap_tool(entry)                                            # 与 07 同款接法
```

这三行在做什么：`HookManager` 收集 pre/post 两列钩子；`protect_file` 是工厂函数（生成并返回钩子函数的函数），命中即阻断并注入 `feedback`。

`redact_secrets` 用正则（描述文本模式的匹配表达式）替换密钥 token（凭证字符串）；`wrap_tool` 把钩子链挂到工具上，接法与权限门相同。

`protect_file` 的匹配条件是"命令含 `.env` 且含写操作符（`>`/`>>`/`tee`/`rm`/`mv`/`sed -i`）"——读放行、写拦截。所以 `cat .env` 能走到 post-hook，完成脱敏演示。

## How It Works

一次工具调用经过钩子链的完整时序：

1. 模型发出工具调用；
2. pre-hook 链依次执行，任一阻断即短路（后面的钩子与工具本身都不再执行），反馈写入模型上下文；
3. 工具执行；
4. post-hook 链按顺序管道传递（前一个的输出是后一个的输入）；
5. 改写后的结果回喂模型。

这套语义与 Claude Code hooks 一致（据转述）。Quick Start 输出里的两个行尾注释正好对应第 2 步和第 4 步：`← pre-hook 阻断+反馈`来自第 2 步，`← post-hook 已脱敏`来自第 4 步。

阻断 ≠ 拒绝：反馈注入是行为引导。07、08 两次真机验证了同一行为链——拦截 → 原因回喂 → 模型改道或如实汇报。对照 03 实验的教训（错误信息质量决定自纠质量），hook 的 feedback 就是执行层的错误信息；只返回 `False` 不带原因的 hook，会让模型陷入 09 实验（预算）要治理的空转。

零知识防御：模型 `cat .env` 时看到的是 `sk-sec…[已脱敏]`——真实密钥从未进入模型上下文。即使 pre-hook 被绕过，泄漏也不会发生，因为它手里根本没有钥匙。这就是纵深防御（对同一资产的多条通路各设一道闸）：写有 pre 拦，读有 post 脱敏。

## Pitfalls & Q&A

踩坑清单：

- **post-hook 改写结果的风险**
  - 现象：改写后的结果失真，误导模型（例如脱敏截断破坏了 JSON 结构）。
  - 原因：post-hook 拿到的是将要回喂的内容，改写过头，模型就还原不出原意。
  - 解法：本篇的脱敏只替换密钥 token、保留结构；生产里 post-hook 的改写要保证"对模型仍然可解析"。
- **只阻断不解释**
  - 现象：模型被拦后反复重试同类命令。
  - 原因：hook 只返回 `False`，没有注入原因。
  - 解法：阻断必须带 feedback（机制见 How It Works）。

**Q1：hooks 和 permissions 什么关系？**

权限门 = "规则驱动的 pre-hook + 审计"。本篇之后 `wrap_tool` 家族已有三个成员（tools/hook/gate），17 实验（总装）按 guard-chain（守卫链：逐层检查的固定顺序）组合：契约校验 → 权限门 → hooks → 沙箱。

**Q2：为什么脱敏发生在回喂前，而不是落盘后？**

落盘的 `.env` 本来就有真密钥（宿主自己写的）；要防的是密钥进入模型上下文——上下文会被 10 实验（压缩）、12 实验（记忆）持久化，一旦进了就到处都是。
