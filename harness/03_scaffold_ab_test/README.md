# 03 · 固定模型变 Harness：亲手复现"换 harness 比换模型影响大"

> **模型不动、任务不动、判分器不动，只变 harness 的契约治理配置**——
> A 配置裸奔（无 schema 校验、原始错误直传、输出不截断、JSON 解析失败即判负），
> B 配置契约治理（jsonschema 校验 + 友好错误回传自纠 + 8KB 截断 + 一次结构
> 修复机会）。这是 alphaXiv 论文"固定模型、只变支架"方法论的迷你复现。

## What

受控实验机制：10 个可自动判分的文件操作任务 × 2 种 harness 配置。模型、
任务、判分器全部相同，唯一变量是 `exec_tool()` 一个函数里的契约治理三道
工序——参数校验、错误翻译、输出截断，外加一次"输出不是合法 JSON"的结构
修复机会。

心智模型一句话：**契约治理 = 让模型每次失败都拿到"下一步该怎么改"的
确定性信息。**

| 要素 | A 配置（裸奔） | B 配置（契约治理） |
|:--|:--|:--|
| 模型 / 任务 / 判分器 | 相同 | 相同 |
| 参数校验 | 无，args 直传 | 缺必填参数即拒绝并说明 |
| 错误回传 | 原始 `repr(e)` | 归纳为"哪里错、怎么改" |
| 输出截断 | 无 | 8KB |
| JSON 解析失败 | 直接判负 | 给一次结构修复机会 |

## Why

"Harness 比模型重要"在 2026 年已有大量实证（同模型换 scaffold 42% vs 78%、
Vercel 删 80% 工具成功率反升），但别人的数据是别人的。本实验在自己的
Ollama 上把这句话变成一张自己的对比表——它同时也是 16 评测台的雏形：
先会对比两个配置，才能回归两个版本。

## How

```bash
cd harness/03_scaffold_ab_test
MOCK=1 python3 scaffold_ab_test.py --selftest   # 离线自检
python3 scaffold_ab_test.py --tasks 3           # 冒烟（3 任务 × 2 配置）
python3 scaffold_ab_test.py                     # 验收口径：10 任务 × 2 配置
```

跑批断点续跑：`results/trial_*.json` 已存在的任务自动跳过。产物
`results/COMPARE.md` 是自动生成的对比表（解决率 / 平均轮次）。

真机 10 任务 × 2 配置（temperature=0）的结果：

```text
[A0-A9] 全部 ✅，平均 3.3 轮
[B0-B9] 全部 ✅，平均 3.2 轮
配置 B 修复机会使用次数: 0 次
A/B 逐任务轨迹 diff: 完全一致
```

| 配置 | 解决率 | 平均轮次 | 轨迹 diff |
|:--|:--:|:--:|:--|
| A 裸奔 | 10/10 | 3.3 | 与 B 完全一致 |
| B 契约治理 | 10/10 | 3.2 | — |

**零差异——这是本次实验最重要的发现，不是失败。**逐字相同的轨迹说明：
20 次跑批里 40 个工具调用全部一次成功，A 组的三道"裸奔惩罚"（无校验、
原始错误、无截断）**一次都没被触发**。qwen3.8（27B）在这种简单任务域里
根本不犯错，契约治理自然无从体现。这与 alphaXiv 论文的发现同构：固定模型
只变支架版本，解决率围绕均值停滞——**支架差异要在故障域才显形**。

三个推论写进后续实验的设计约束：

1. **契约治理的价值在故障域**——05 工具契约实验必须注入扰动（错参数、
   坏路径）才能测出 A/B 分野；强模型 + 顺任务测不出 harness 差异；
2. **修复预算 0 次使用**说明强提示词下模型一次就对，预算体系（09 预算）
   要按弱模型/难任务校准；
3. **temperature=0 的可复现性**再次应验：想看分布差异，需要采样温度 > 0
   或任务难度梯度——评测台（16）的任务集必须分难度档。

引用文献里的"42% vs 78%"发生在 SWE-bench 级难度的故障密集域；本实验
用 10 个顺任务复现了它的对照命题：**顺任务域里 harness 不可区分**。
两半合起来才是完整结论：**harness 的价值与任务故障密度成正比**。

实现集中在三个函数：

```python
exec_tool(cfg, name, args, sandbox)  # A/B 全部差异集中在这一个函数
feed(cfg, text)                      # B: 8KB 截断；A: 原样
write_compare(recs)                  # 自动生成 COMPARE.md 对比表
```

**错误回传是工具契约的灵魂**：A 组拿到 `KeyError('path')` 只知道"出错了"；
B 组拿到"参数校验失败: 工具 write_file 缺少必填参数 ['path']，请重新输出
完整 JSON"——错误信息的质量决定自纠的成功率（05 工具契约的主题预演）。
**修复预算是 harness 的显式资源**：B 组的"一次结构修复机会"是有意设计的
稀缺资源（不限次会变成死循环津贴），09 预算会把它推广成 token/轮次/修复
次数三维预算体系。

## Deep Dive

**为什么全部差异能塞进一个函数？**受控实验的效力来自只变一个变量：A/B
两组共用同一套主循环与判分器，`exec_tool()` 内部按配置决定"直传 or 校验、
甩原始错误 or 翻译、原样 or 截断"。治理层是纯函数式插拔，不触碰循环本身。

踩坑清单（与 01 共通的不再重复）：

- **mock 序列是跨任务共享的迭代器**：冒烟时各任务会"抢剧本"，只适合验证
  管道不适合验证行为；真机数据请看真模型。

## Q&A

**Q1: 为什么不用更强模型"顺便"提分？**

受控实验的效力来自只变一个变量；混入模型升级就无法归因。18 实验会做反
方向（固定 harness 变模型）补全 2×2。

**Q2: 解决率之外为什么记录轮次？**

alphaXiv 论文的教训：支架演进可能"功能不变、成本翻倍"。轮次是 token 成本
的代理指标，回归评测必须看两个维度。
