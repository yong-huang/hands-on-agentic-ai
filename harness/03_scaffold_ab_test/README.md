# 03 · 固定模型变 Harness：亲手复现"换 harness 比换模型影响大"

> 固定模型、任务与判分器，只变 harness（模型外围的执行与约束设施层）的契约治理配置：A 配置裸奔（无 schema 校验、原始错误直传、输出不截断、JSON 解析失败即判负），B 配置契约治理（jsonschema 校验 + 友好错误回传自纠 + 8KB 截断 + 一次结构修复机会）。这是 alphaXiv 论文"固定模型、只变支架"方法论的迷你复现，读完能得到一张自己的 A/B 对比表，以及"零差异"结果背后的完整解释。

## Background

评估 harness（模型外围负责执行、约束与反馈的工程设施层）改动的好坏，常见做法是凭观感："加了校验感觉更稳了"，或者干脆换个更强模型提分。改进效果与模型能力混在一起，无法归因到具体哪一层起了作用。

痛点场景：团队争论要不要给工具调用加 schema 校验（按声明的参数结构检查输入），双方都拿不出本地数据。论文与业界实证不少——同模型换 scaffold（支架，模型外围的提示与结构支撑）得分 42% vs 78%、Vercel 删掉 80% 的工具后成功率反升。

但别人的数据产生在别人的环境里，不能直接回答自己系统的问题。

alphaXiv 论文给出的方法论是"固定模型、只变支架"：控制除 harness 外的一切变量，差异就只能来自 harness。本实验把这套方法论做成迷你复现，在自己的机器上得到自己的对比表。

## What

本实验是一个受控 A/B：10 个可自动判分的文件操作任务 × 2 种 harness 配置。模型、任务、判分器全部相同，唯一变量是 `exec_tool()` 一个函数里的契约治理三道工序——参数校验、错误翻译、输出截断，外加一次"输出不是合法 JSON"的结构修复机会。

契约治理（对工具调用施加的确定性检查与转换：执行前校验参数、失败时翻译错误、回传前截断输出）一句话定义：**让模型每次失败都拿到"下一步该怎么改"的确定性信息。**

可以把契约治理想象成网页表单的即时校验：填错字段当场提示"哪个字段错、该怎么改"，而不是提交后弹一个含糊的服务器错误。但和表单校验不同的是，这里的"填表人"是模型——错误信息要作为输入喂回给它，供下一轮自纠。

A/B 差异全景：

| 要素 | A 配置（裸奔） | B 配置（契约治理） |
|:--|:--|:--|
| 模型 / 任务 / 判分器 | 相同 | 相同 |
| 参数校验 | 无，args 直传 | 缺必填参数即拒绝并说明 |
| 错误回传 | 原始 `repr(e)` | 归纳为"哪里错、怎么改" |
| 输出截断 | 无 | 8KB |
| JSON 解析失败 | 直接判负 | 给一次结构修复机会 |

## When to Use

什么时候需要这种"只变一个变量"的对照：任何要判断某项 harness 改动值不值得上的场合。

典型场景：

1. 评估一项 harness 改进（加校验、加截断、翻译错误信息）要不要上线：固定模型与任务集，A/B 跑出本地数据再决定。
2. 检验论文或厂商宣称的 harness 收益：把宣称翻译成本地受控实验，看在自己的任务域是否成立。
3. 为回归评测打底座：先会对比两个配置，才能回归两个版本（16 评测台的雏形）。

何时不用：模型还没定、任务集还在变时，A/B 结论不稳定；只求跑通功能、不关心归因时，直接采用更好配置即可。

同类方案对比：

| 方案 | 与本实验的差异 | 什么时候选它 |
|:--|:--|:--|
| 直接换更强模型 | 提分快，但无法归因是能力还是设施 | 原型期追求效果，不追问原因 |
| 固定模型 A/B 配置（本实验） | 只变 harness，差异可完全归因 | 评估某项 harness 改动的贡献 |
| 固定 harness 变模型（18 实验的方向） | 归因模型贡献，harness 固定 | 多个候选模型之间做选型 |

## Quick Start

前置条件：Python 3；离线自检（`MOCK=1`，环境变量开关，用假模型离线运行）不需要模型服务；真机运行需要本机装有 Ollama（在本地运行大语言模型 LLM 的工具）。本次真机数据来自 qwen3.8（27B），`temperature=0`（采样温度参数设为 0，输出完全确定，结果可逐字复现）。

```bash
cd harness/03_scaffold_ab_test
MOCK=1 python3 scaffold_ab_test.py --selftest   # 离线自检
python3 scaffold_ab_test.py --tasks 3           # 冒烟（3 任务 × 2 配置）
python3 scaffold_ab_test.py                     # 验收口径：10 任务 × 2 配置
```

第二条命令是冒烟测试（用最小规模快速验证流程能跑通）。跑批支持断点续跑：`results/trial_*.json` 已存在的任务自动跳过。产物 `results/COMPARE.md` 是自动生成的对比表（解决率 / 平均轮次）。

真机 10 任务 × 2 配置（temperature=0）的结果：

```text
[A0-A9] 全部 ✅，平均 3.3 轮
[B0-B9] 全部 ✅，平均 3.2 轮
配置 B 修复机会使用次数: 0 次
A/B 逐任务轨迹 diff: 完全一致
```

| 配置 | 解决率 | 平均轮次 | 轨迹 diff |
|:--|:--:|:--:|:--|
| A 裸奔 | 10/10 | 3.3 | 与 B 完全一致 |
| B 契约治理 | 10/10 | 3.2 | — |

诚实预期：重跑应复现 10/10 对 10/10、平均 3.3 对 3.2 轮、修复机会使用 0 次、轨迹逐字一致。**零差异是本次真机的真实结果，不是实验失败**——原因见 How It Works；若某任务中断，重跑会从断点继续。

## How It Works

### 全部差异塞进一个函数

受控实验的效力来自只变一个变量：A/B 两组共用同一套主循环与判分器，`exec_tool()` 内部按配置决定"直传 or 校验、甩原始错误 or 翻译、原样 or 截断"。治理层是纯函数式插拔，不触碰循环本身。实现集中在三个函数：

```python
exec_tool(cfg, name, args, sandbox)  # A/B 全部差异集中在这一个函数
feed(cfg, text)                      # B: 8KB 截断；A: 原样
write_compare(recs)                  # 自动生成 COMPARE.md 对比表
```

### 分叉点：治理工序只在出错时生效

本实验不注入故障，10 个任务全是顺任务（模型一次就对、无故障发生）。读 `exec_tool()` 源码可见，A/B 的分叉点全部挂在出错路径上：`cfg == "B"` 的参数校验只在缺必填参数时拒绝，错误翻译只在执行抛异常时启用，8KB 截断只在输出超长时生效。

参数齐全时，两个配置走的是同一条成功路径，治理工序没有触发机会——差异自然无从体现（展开见下节）。

### 零差异说明了什么

输出里的"轨迹 diff: 完全一致"意味着：20 次跑批里 40 个工具调用全部一次成功，A 组的三道"裸奔惩罚"（无校验、原始错误、无截断）**一次都没被触发**。qwen3.8（27B）在这种简单任务域里根本不犯错，契约治理自然无从体现。

这与 alphaXiv 论文的发现同构：固定模型只变支架版本，解决率围绕均值停滞——**支架差异要在故障域才显形**。推论是契约治理的价值在故障域：05 工具契约实验必须注入扰动（错参数、坏路径）才能测出 A/B 分野，强模型 + 顺任务测不出 harness 差异。

引用文献里的 42% vs 78% 发生在 SWE-bench（以真实 GitHub issue 修复为任务的编程基准）级难度的故障密集域；本实验用 10 个顺任务复现了它的对照命题：**顺任务域里 harness 不可区分**。

两半合起来才是完整结论：**harness 的价值与任务故障密度成正比。**

### 错误回传与修复预算

**错误回传是工具契约的灵魂**：A 组拿到 `KeyError('path')` 只知道"出错了"；B 组拿到"参数校验失败: 工具 write_file 缺少必填参数 ['path']，请重新输出完整 JSON"——错误信息的质量决定自纠的成功率（05 工具契约的主题预演）。

**修复预算是 harness 的显式资源**：B 组的"一次结构修复机会"是有意设计的稀缺资源（不限次会变成死循环津贴），09 预算会把它推广成 token（模型计费与限长的最小文本单位）/轮次/修复次数三维预算体系。

"修复机会使用 0 次"还给出另一条设计约束：强提示词下模型一次就对，预算体系要按弱模型/难任务校准。temperature=0 保证可复现；想看分布差异，需要采样温度 > 0 或任务难度梯度——评测台（16）的任务集必须分难度档。

## Pitfalls & Q&A

### 踩坑清单

1. **mock 序列是跨任务共享的迭代器**。现象：冒烟时各任务会"抢剧本"，行为数据不可信。原因：MOCK 模式的假回复序列被多个任务共享消费。解法：冒烟只适合验证管道，不适合验证行为；真机数据请看真模型。（与 01 共通的代理劫持等坑不再重复。）

### 深入问答

**Q：为什么不用更强模型"顺便"提分？**

受控实验的效力来自只变一个变量；混入模型升级就无法归因。18 实验会做反方向（固定 harness 变模型）补全 2×2。

**Q：解决率之外为什么记录轮次？**

alphaXiv 论文的教训：支架演进可能"功能不变、成本翻倍"。轮次是 token 成本的代理指标，回归评测必须看两个维度。
