# 18 · 收尾对照：换模型 vs 换 Harness，2×2 给出答案

> Model 和 Harness（包在模型外面的执行框架）各自值多少分？本篇复用
> 16 评测台的任务集与判分器，跑一张 2×2 表：两个模型（qwen3.8 27B /
> qwen3:4b 4B）× 两套 harness（裸 loop / 全装），40 次真机跑批，结论
> 是量化过的，不是引用来的。读完本篇你能用一张表回答"该升级模型还是
> 加固框架"。

## Background

没有交叉对照时，选型靠单轴印象：模型看 benchmark 跑分（公开测试集上
的成绩单），harness 看功能列表。"更强的模型"和"更好的框架"听起来
都有理，但没人能回答：预算有限时，钱该花在哪一轴？

痛点出在两轴会互相掩盖：单看 harness 对照，强模型上加防护像白花钱；
单看模型跑分，看不见弱模型在真实多步任务里的塌法。03 的受控对照（只
动一个变量、其余固定的对照实验）只压了一个轴（harness 配置），模型
这根轴是悬空的。

本篇把第二个轴加上，构成完整 2×2——论文方法的完整复现：两个模型 ×
两套 harness，40 次真机跑批。如果你能预测每个格的结果并解释为什么，
就说明真正理解了两个因子各自的作用。

## What

2×2 对照实验：任务集与判分器全程不动（复用 16 评测台），只动两个
变量——模型（行）与 harness（列），40 次真机跑批汇成一张表。模型名
里的 B 是参数量单位（十亿）。

裸 loop 指无防护的模型-工具循环，全装指契约（工具调用前按声明格式
校验参数）、沙箱（限制时长与输出大小的受限执行环境）、预算（轮次与
token 用量止损）齐备的 harness。

心智模型一句话：**Agent = Model × Harness，是乘法——两个因子各有
下限，harness 的边际价值（每多一分投入换来的增益）随模型变弱而
放大。**

可以把结果想象成两个因子的乘积：任一因子接近零，乘积就近零。但和
算术乘法不同的是：乘法只给出一个数，这里每个格还带着轮次与 token
两维代价——乘积好看不等于便宜（见 Quick Start 的数据表）。

## When to Use

典型场景：

- 预算有限，要在"升级模型"与"加固 harness"之间分配时——用一张
  2×2 把两轴的边际收益摆上台面。
- 接入新模型前，预测现有 harness 对它的增益方向。
- 向团队论证治理投入：弱模型域的实测数据比原则式主张更有说服力。

何时不用：样本量不足以支撑结论时（本实验每格只有 10 个任务，属
方向性证据）；只关心单轴问题（比如单纯换模型）时，单轴对照更省。

同类做法对比：

| 方案 | 差异 | 什么时候选它 |
|:--|:--|:--|
| 单模型 benchmark 跑分 | 只测模型，单轴、静态题 | 模型海选初筛 |
| 单轴 harness 对照（16 的做法） | 固定模型，比 harness 配置 | 日常回归 |
| 2×2 交叉对照（本篇） | 模型 × harness 两轴同动 | 轴间取舍与归因 |
| 线上 A/B 实验 | 真实流量、成本高 | 已部署系统的最终裁决 |

## Quick Start

前置条件：Python 3；真机需要能跑 qwen3.8 与 qwen3:4b 两个模型的接入；
全量 4 格 × 10 任务约 1 小时，支持断点续跑。

```bash
cd harness/18_model_vs_harness
python3 run_2x2.py --quick    # 快速版: 每格 4 任务
python3 run_2x2.py            # 全量: 4 格 × 10 任务(约 1 小时, 断点续跑)
```

真机数据（详见 [REPORT.md](REPORT.md)；token 即模型计量文本长度的
单位，est token 为按字符估算的用量，口径同 16 评测台）：

| 格 | 解决率 | 平均轮次 | est token/任务 |
|:--|:--:|:--:|:--:|
| qwen3.8 + 裸 loop | 10/10 | 2.0 | 67 |
| qwen3.8 + full harness | 10/10 | 2.1 | 69 |
| qwen3:4b + 裸 loop | **1/10** | 1.1 | 752 |
| qwen3:4b + full harness | **5/10** | 1.5 | 764 |

表中解决率即任务通过比例。三条核心结论（验收项，pp 即百分点）：

1. **harness 的收益与模型强度成反比**：强模型域 +0pp，弱模型域 +40pp
   （×5）——05/09 观察到的"harness 价值 ∝ 故障密度"的最终定理形式：
   **弱模型就是持续的故障源**；
2. **harness 救不了太弱的模型**：4b+full（5/10）仍远逊 3.8+bare
   （10/10），乘法关系的另一面；
3. **无效推理有成本证据**：4b 每任务烧 11 倍 token 换 1/10 解决率——
   09 预算止损对弱模型是刚需，不是优化。

诚实预期：单任务集、单领域、样本 10/格——方向性结论可靠，数字不可
外推；要下更硬的结论，需要多任务域 × 多模型。

实现入口速览：

```python
run_one(model_key, harness, task_i, ...)   # 单格单任务, 断点续跑(rows.json)
report(rows)                               # 2×2 表生成
```

## How It Works

把三条结论收拢成一句定理：**模型决定上限，harness 决定下限，harness
的边际价值随模型变弱而放大（弱模型域实测 ×5）。**

为什么 4b 在裸 loop 下只有 1/10？多步任务对小模型是"连续不走神"的
考验，一步偏差全盘皆输——这正是 harness 各模块（校验/止损/恢复）存在
的理由：**把"不走神"从模型职责挪到工程职责**。

表里 4b 那一行从裸 loop 到 full harness 的变化（1/10→5/10、轮次
1.1→1.5、token 752→764），就是工程接手"不走神"职责后的代价与收益。

两个工程细节：`importlib.reload(mh.llm)` 让 `LLM_MODEL` 环境变量在
切换单元格时生效（Python 模块导入后默认缓存，不 reload 换不了模型）；
`rows.json` 断点续跑——40 次跑批随时可中断续作，已完成的格不重跑。

## Pitfalls & Q&A

**Q1: full 对 4b 的提升来自哪个模块？**

主要三类：schema（参数格式说明）错误回传（自纠）、沙箱拒绝的明确反馈
（不瞎猜）、预算 HANDOFF（预算耗尽即止损移交，不会无限烧）。逐模块
归因是 16 评测台的后续工作。
