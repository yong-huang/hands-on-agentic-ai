# 16 · Harness 评测台：Agent QA 回归管线

> 前十五个实验每次都在变强，**但你怎么知道？** alphaXiv 论文的核心警示：
> 支架演进不必然提升解决率，却让 token 消耗 391K→668K——"功能正常"的
> 测试抓不住效率型退化。`harness/eval/` 就是本系列的质检科：固定 10 任务
> 集、固定判分器、受控配置对比，解决率/轮次/token 三维指标，任一指标
> 回退即 🔴 标红 exit 1。

## 1. 为什么需要它

03 实验证明了"测 harness 要受控对照"，本篇把它产品化：任务集入库存、
配置一行切换、结果自动出表。此后 mh/ 的任何改动（新模块、参数调整、
模型切换）都可以一键回归——**这正是支架工程的刚需**（Agent QA），
也是 17 终极总装与 18 收尾对照的基础设施。

## 3. 快速开始

```bash
cd harness/eval
MOCK=1 bash run.sh            # 离线: 管道自检(含🔴回退演练)
bash run.sh                   # 真机全量: 2 配置 × 10 任务(约 1 小时)
python3 eval_run.py --profile full --tasks 3   # 快速冒烟
```

真机实测（2026-09-20，qwen3.8，10 任务 × 2 配置，`results/`+`COMPARE.md` 为产物）：

```text
| 指标        | baseline v0.1 | full v1.0 | 变化      |
| pass        |     10/10     |   10/10   | +0        |
| avg_turns   |      2.0      |    2.1    | +5% 🔴回退 |
| avg_tokens  |      67       |    69     | +3% 🔴回退 |
```

两个重要的真发现：

1. **评测台首跑就抓到一个真 bug**：第一版 full 配置 10 任务全灭（全部
   顶满轮次、0 产出）——排查出 run_bash 解包了外层包装函数的**字符串**
   而非 sandbox_run 的元组（双重包装 bug）。门禁 exit 1 的语义第一天
   就兑现了价值。
2. **修复后两配置打平，full 只多付 ~3-5% 开销**——这是沙箱+契约治理在
   简单任务上的真实价格（安全有单价）。+3%/+5% 被严格门禁判 🔴 是设计
   使然：阈值放宽与否是策略决策，"发现即报告"是评测台的本分。

## 4. 核心概念

### 4.1 两套配置 = 两个快照

| | baseline v0.1 | full v1.0 |
|:--|:--|:--|
| 工具 | 裸 subprocess(15s 兜底) | `@tool` 契约 + 沙箱(3s/8KB/守卫) |
| 预算 | 无 | max_turns=10 + token 止损 |
| 崩溃处理 | 单任务炸死全批 | 评测台捕获, 记 ❌ 继续 |

### 4.2 三维指标与回退判定

- **解决率**（有效性，越高越好）、**平均轮次**（收敛速度，越低越好）、
  **est token**（成本，越低越好）。对比表中任一指标向坏方向变化即标
  🔴回退并 exit 1——回归评测的"门禁"语义，可直挂 CI。

### 4.3 评测台自身的健壮性

单任务崩溃被捕获记 ❌ 而非中止全批；任务集含串行依赖（09 教训：可批量
任务测不出配置差异）；token 用字符估算（精确计量是 16 之后的事）。

## 7. 深入要点

- **为什么对比配置而不是对比 git 版本？** 语义等价：git 快照之间的差异
  最终都体现在行为配置上。等 mh/ 有正式版本后，`--profile` 换成
  `--ref v0.1 v1.0` 即可（接口已留）。
- **回退就该 exit 1 吗？** 是门禁语义：评测不过，改动不合入。生产里
  对应"支架的 PR 也要跑支架回归"——论文呼吁的 Agent QA 学科的最小实现。
- **为什么任务不判分模型输出只判文件？** 与 01 同源：确定性信息优于
  概率性汇报。模型说"做完了"不算数，磁盘说了算。
- **est token 够准吗？** 方向正确、粒度够回归用；精确计量（eval_count）
  是后续优化，不能阻塞门禁上线。
