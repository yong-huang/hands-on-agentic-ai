# 16 · Harness 评测台：Agent QA 回归管线

> alphaXiv 论文的核心警示：支架演进不必然提升解决率，却让 token 消耗
> 391K→668K——"功能正常"的测试抓不住效率型退化。`harness/eval/` 就是本
> 系列的质检科：固定 10 任务集（含不可批量串行依赖）、固定判分器、受控
> 配置对比，解决率/轮次/token 三维指标，任一指标回退即 🔴 标红 exit 1。

## What

评测台机制：左半边固定不变——10 个任务（含串行依赖，09 的教训）与文件
系统判分（01 的哲学）；右半边是唯一变量——两套配置。baseline(v0.1)=04
水平的裸 loop + 无防护 run_bash；full(v1.0)=契约+沙箱+预算的完整形态。
产出三维对比表，任一指标向坏方向变化即标 🔴 回退并 exit 1。

心智模型一句话：**评测台回答的不是"能不能用"，是"比昨天强了多少、
代价是什么"。**

| | baseline v0.1 | full v1.0 |
|:--|:--:|:--:|
| 工具 | 裸 subprocess(15s 兜底) | `@tool` 契约 + 沙箱(3s/8KB/守卫) |
| 预算 | 无 | max_turns=10 + token 止损 |
| 崩溃处理 | 单任务炸死全批 | 评测台捕获, 记 ❌ 继续 |

## Why

03 实验证明了"测 harness 要受控对照"，本篇把它产品化：任务集入库存、
配置一行切换、结果自动出表。此后 mh/ 的任何改动（新模块、参数调整、
模型切换）都可以一键回归——**这正是支架工程的刚需**（Agent QA），也是
17 终极总装与 18 收尾对照的基础设施。

## How

```bash
cd harness/eval
MOCK=1 bash run.sh            # 离线: 管道自检(含🔴回退演练)
bash run.sh                   # 真机全量: 2 配置 × 10 任务(约 1 小时)
python3 eval_run.py --profile full --tasks 3   # 快速冒烟
```

真机实测（10 任务 × 2 配置，`results/` + `COMPARE.md` 为产物）：

```text
| 指标 | baseline v0.1 | full v1.0 | 变化 |
|:--|:--:|:--:|:--:|
| pass | 9/10 | 9/10 | +0 |
| avg_turns | 5.0 | 5.0 | +0% |
| avg_tokens | 100 | 100 | +0% |
```

串行任务集下两配置**完全打平（+0%，无回退）**；唯一失败的 task 9 在两个
配置下同样失败——是任务/模型能力边界，不是配置回退，门禁放行。三维
指标各有方向：**解决率**（有效性，越高越好）、**平均轮次**（收敛速度，
越低越好）、**est token**（成本，越低越好）。阈值放宽与否是策略决策，
"发现即报告"是评测台的本分——回归评测的"门禁"语义可直挂 CI。

评测台自身的健壮性：单任务崩溃被捕获记 ❌ 而非中止全批；任务集含串行
依赖（可批量任务测不出配置差异）；token 用字符估算。

实现代码：

```python
TASKS            # 10 任务: (指令, 文件系统判分函数)
build_tools(p)   # 唯一变量: profile → 工具表
compare(res)     # 对比表生成 + 回退标红 + exit 1
run.sh           # 两配置跑批 + 自动对比
```

## Deep Dive

**回退就该 exit 1——这是门禁语义**：评测不过，改动不合入。生产里对应
"支架的 PR 也要跑支架回归"——alphaXiv 论文呼吁的 Agent QA 学科的最小
实现。

踩坑清单：

- **双重包装 bug（评测台首跑抓到的真 bug）**：第一版 full 配置 10 任务
  全灭（全部顶满轮次、0 产出）——排查出 run_bash 解包了外层包装函数的
  **字符串**而非 sandbox_run 的元组（双重包装 bug）。门禁 exit 1 的语义
  第一天就兑现了价值。

## Q&A

**Q1: 为什么对比配置而不是对比 git 版本？**

语义等价：git 快照之间的差异最终都体现在行为配置上。等 mh/ 有正式版本
后，`--profile` 换成 `--ref v0.1 v1.0` 即可（接口已留）。

**Q2: est token 够准吗？**

方向正确、粒度够回归用；精确计量（eval_count）是后续优化，不能阻塞门禁
上线。
