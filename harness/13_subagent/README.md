# 13 · 子代理调度：任务描述就是上下文防火墙

> 主代理亲自翻 100 行 README 做统计时，翻页过程会永久占据它的上下文——
> 长任务里最贵的不是 token（模型计量文本长度的单位），是这种**污染**。
> `mh/subagent.py` 用子代理（主代理派生出的独立执行者）做物理隔离：
> 独立消息历史、全新工具表、只回传一条摘要。读完本篇你能说清三个隔离
> 要素，以及"零泄漏"如何被两步验收证明。

## Background

没有外包机制时，代理包办一切：翻文件、跑命令、读回全部输出，所有过程
细节都堆在同一条上下文（模型一次会话能看到的全部消息）里，后续每一轮
对话都背着它们。此前的实验（04-12）一直在给这条上下文减压：10 压缩
事后瘦身，09 预算事前止损，但思路都是"先污染、后治理"。

痛点在"结果小、过程肥"的任务上最明显：让主代理统计一个 README 的行数、
中文字符数和标题数，它要执行 `wc`（数行数等统计）、`grep`（按模式搜
文本）并读回全部输出。结论只有三个数字，过程输出却可能占据几千 token，
而且此后每轮都在场，挤占真正有用的上下文。

Claude Code 的多代理输出层（02 解剖图第五层）给出了另一种结构：主代理
只当调度员，把整段脏活派给一个临时执行者，自己只保留结论。13 实验把
这个结构做成了 `mh/subagent.py`。

## What

子代理调度：主代理调用 `spawn_subagent(task)`（spawn 即"派生"），生成
一个拥有独立上下文的临时执行者。入参 `task` 是一段完整、自洽的自然
语言任务描述——这段话就是防火墙：子代理能知道的只有它。

子代理内部用自己的 loop（"调模型→调工具→再调模型"的循环）加全新工具
表实例跑完 N 轮；工具表是登记可用工具的清单，每项含描述、参数 schema
（入参格式说明）、执行函数与状态。跑完后主代理的上下文只新增一条被
截断的摘要，完整轨迹存在工具对象的 `last_trace` 里，可查但不污染。

心智模型一句话：**隔离的粒度不是权限，是"它能看到什么"——任务描述之外，
子代理一无所知。**

| 要素 | 实现 | 防的是什么 |
|:--|:--|:--|
| 独立消息历史 | 子代理有自己的 messages（消息列表） | 过程细节回流主上下文 |
| 全新工具表实例 | `tools_factory()` 每次新建 | 共享可变状态串场 |
| 返回值截断 | 摘要 ≤500 字符 | 摘要本身变成污染源 |

## When to Use

典型场景——结果小、过程肥、能整段交代的任务：

- 统计与盘点：数一个大文件的行数、字符数、标题数，结论是几个数字，
  过程要读全文。
- 定点排查：在代码库里找一个符号的全部出现位置，海量扫描输出只服务
  一个结论。
- 批量验证：把一堆相互独立的小检查分给多个子代理，各自跑各自的，
  互不污染。

何时不用：任务一两条命令就能干完时，不外包。spawn 有固定成本（新建
会话、新建系统提示——会话开始前给模型设定角色的文本），比污染本身
还贵；09 的教训在此同样成立：机制要配故障密度（值不值得上这套机制，
取决于它挡住的问题发生得多频繁）。

同类做法对比：

| 方案 | 差异 | 什么时候选它 |
|:--|:--|:--|
| 主代理直接做 | 过程细节全部留在主上下文 | 一两步完成、输出很短 |
| 上下文压缩（10 的主题） | 事后把旧消息折叠成摘要 | 污染已发生后的补救 |
| 预算止损（09 的主题） | 设上限，超限即停 | 防失控，不减少过程量 |
| 子代理外包（本篇） | 过程在独立上下文里发生，只回传摘要 | 过程肥、结论小、可整段交代 |

## Quick Start

前置条件：Python 3 环境；`MOCK=1` 走离线剧本，不需要模型服务；真机
运行需要一个可用的模型接入。

```bash
cd harness/13_subagent
MOCK=1 python3 demo.py    # 离线管道自检（子代理走剧本）
python3 demo.py           # 真机: 主代理分派 + 磁盘核对
```

真机实测：

```text
主代理: 1 次 spawn_subagent 调用, 0 条子代理命令泄漏
子代理: 3 轮 3 次工具调用（wc -l / grep 中文字符 / grep -c '##'）
摘要数字与磁盘核对: (69 行, 437 中文字符, 4 标题) 全部一致 ✅
```

验收口径是两步证明"隔离真的发生了"：① 在主代理全部消息的 JSON（一种
结构化文本格式）里逐条搜索子代理执行过的命令——0 命中；② 主代理汇报
的数字与磁盘重新计算的 truth（以磁盘为准算出的基准值）逐一比对。

摘要不是含糊其辞，是可核对的事实。**测隔离不能只看"结果对"，要证明
"过程没过去"。**

诚实预期：真机的轮次数取决于任务描述质量（机制见 How It Works）；
但"0 条泄漏"和"数字与磁盘一致"两条不应变，变了说明隔离被破坏。

## How It Works

派生流程按顺序走五步：

1. 主代理在自己的一轮里发起 `spawn_subagent(task)`；
2. harness（本系列给模型包的执行框架）调用 `tools_factory()`，现造
   一张全新工具表；
3. 子代理带着 `task` 独立跑自己的 loop，共 N 轮；
4. 结束后把执行结果摘要（截断后）作为一条工具结果塞回主上下文；
5. 完整轨迹写入 `sub["_state"]["last_trace"]`，留档但永不进主上下文。

核心实现：

```python
spawn_subagent(tools_factory=..., max_turns=..., chat_fn=...)
# → 工具表条目 {desc, schema, fn, _state}
sub["_state"]["last_trace"]   # 子代理完整轨迹(留档, 永不进主上下文)
```

`tools_factory` 是关键参数：spawn 每次都调用它拿一张全新工具表，两个
loop 因此不共享任何工具表状态。

与 Quick Start 的输出互相印证：`0 条子代理命令泄漏` 来自第 5 步——
轨迹只进 `last_trace`；`3 轮 3 次工具调用` 是子代理独立 loop 自己的
计数，主代理只拿到最后那条截断摘要。

**任务描述的质量决定子代理质量。**子代理只知道任务描述：写"统计
README"，它会先 `ls` 找文件；写明绝对路径、三项指标、每项一条命令，
它 3 轮收敛。

分派的艺术在任务描述里——这是调度员（主代理）的提示词工程（为模型
设计输入文本的技巧），不是子代理的。

## Pitfalls & Q&A

踩坑清单：

- **共享工具表**
- 现象：把主代理正在用的工具表对象直接交给子代理，两个 loop 互相
  踩到同一份工具表状态，计数器、缓存一类可变状态串场。
- 原因：工具表条目带 `_state`，是可变对象，不是只读清单。
- 解法：`tools_factory` 每次 spawn 都新建一张——隔离三要素的第三条
  就是为它设的。

Q&A：

**Q1: 为什么子代理不做权限/预算？**

演示版保持最小；生产中 spawn 工厂可以注入 07-09 的全部包装——子代理
的治理策略可以与主代理**不同**（更严），这正是工厂模式的红利（工厂
模式：把对象的创建交给一个专门函数，调用方不必关心构造细节）。

**Q2: 摘要丢了关键细节怎么办？**

与 10 压缩同一困境同一解法：摘要 prompt（给模型的输入文本）带硬性
要求（"必须含具体数字"），验收用磁盘核对兜底。

**Q3: 子代理还能再 spawn 吗？**

工厂里不注册 spawn 工具即可禁止——Claude Code 允许嵌套到 5 层（据
转述），本篇刻意 1 层，控制面（先有评测与治理、再放开能力的思路，
16 评测的主题）先行。
