# 13 · 子代理调度：任务描述就是上下文防火墙

> 长任务里最贵的不是 token，是**污染**：让主代理自己去翻 100 行 README
> 做统计，翻页过程会永久占据它的上下文。`mh/subagent.py` 的答案是一把
> hammer：子代理拥有独立消息历史与全新工具表实例，跑完只把一条摘要还给
> 主代理。真机验收：子代理 3 轮 3 次工具调用，主上下文**零泄漏**，摘要
> 数字与磁盘事实逐个核对一致。

## What

子代理调度：主代理调用 `spawn_subagent(task)`，入参是一段完整、自洽的
自然语言任务描述——这段话就是防火墙：子代理能知道的只有它。子代理内部
独立 loop + 全新工具表实例跑完 N 轮，主代理的上下文只新增一条被截断的
摘要；完整轨迹存在工具对象的 `last_trace` 里，可查但不污染。

心智模型一句话：**隔离的粒度不是权限，是"它能看到什么"——任务描述之外，
子代理一无所知。**

| 要素 | 实现 | 防的是什么 |
|:--|:--|:--|
| 独立消息历史 | 子代理有自己的 messages | 过程细节回流主上下文 |
| 全新工具表实例 | `tools_factory()` 每次新建 | 共享可变状态串场 |
| 返回值截断 | 摘要 ≤500 字符 | 摘要本身变成污染源 |

## Why

04-12 把单 agent 养得越来越强，但它的上下文仍是独木桥：10 压缩能瘦身、
09 预算能止损，都不如"脏活外包"来得干脆。Claude Code 的多 agent 输出层
（02 解剖图第五层）就是这个结构——主代理是调度员，子代理是干活的，
**调度员的办公桌上只放结论**。这也是 02 说的"上下文防火墙"：防火墙不是
过滤器，是物理隔离。

## How

```bash
cd harness/13_subagent
MOCK=1 python3 demo.py    # 离线管道自检（子代理走剧本）
python3 demo.py           # 真机: 主代理分派 + 磁盘核对
```

真机实测：

```text
主代理: 1 次 spawn_subagent 调用, 0 条子代理命令泄漏
子代理: 3 轮 3 次工具调用（wc -l / grep 中文字符 / grep -c '##'）
摘要数字与磁盘核对: (69 行, 437 中文字符, 4 标题) 全部一致 ✅
```

验收口径是**两步证明"隔离真的发生了"**：① 在主代理全部消息的 JSON 里
逐条搜索子代理执行过的命令——0 命中；② 主代理汇报的数字与磁盘重新计算
的 truth 逐一比对——摘要不是含糊其辞，是可核对的事实。**测隔离不能只看
"结果对"，要证明"过程没过去"。**

实现代码：

```python
spawn_subagent(tools_factory=..., max_turns=..., chat_fn=...)
# → 工具表条目 {desc, schema, fn, _state}
sub["_state"]["last_trace"]   # 子代理完整轨迹(留档, 永不进主上下文)
```

## Deep Dive

**任务描述的质量决定子代理质量。**子代理只知道任务描述：写"统计 README"
它会先 `ls` 找文件；写明绝对路径、三项指标、每项一条命令，它 3 轮收敛。
**分派的艺术在任务描述里**——这是调度员（主代理）的提示词工程，不是子
代理的。

踩坑清单：

- **共享工具表是设计期就要规避的坑**：如果直接把主代理的工具表交给子
  代理，两个 loop 会互相踩到同一份注册表状态。`tools_factory` 每次 spawn
  都调用它拿**全新**工具表——隔离三要素里"全新工具表实例"就是为它设的。

## Q&A

**Q1: 为什么子代理不做权限/预算？**

演示版保持最小；生产中 spawn 工厂可以注入 07-09 的全部包装——子代理的
治理策略可以与主代理**不同**（更严），这正是工厂模式的红利。

**Q2: 摘要丢了关键细节怎么办？**

与 10 压缩同一困境同一解法：摘要 prompt 带硬性要求（"必须含具体数字"），
验收用磁盘核对兜底。

**Q3: 子代理还能再 spawn 吗？**

工厂里不注册 spawn 工具即可禁止——Claude Code 允许嵌套到 5 层（据转述），
本篇刻意 1 层，控制面（16 评测）先行。

**Q4: 什么时候不该用子代理？**

任务本身一两条命令能干完时——spawn 的固定成本（新会话、新系统提示）比
污染更贵。09 的教训在此重演：机制要配故障密度。
