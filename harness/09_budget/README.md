# 09 · 预算与止损：给 07 的 7 轮空转装上硬天花板

> 控制面最后一块：`mh/budget.py`，给模型的连续空转（07 实测被拒后改道
> 7 轮）装上硬性天花板——`warn`（预算将尽注入"请尽快收敛"提醒）→
> `force`（撤走工具表 + 强制输出 HANDOFF 三行摘要）。超限**不抛异常**：
> 止损和自然收敛从同一扇门出去，这就是优雅降级。

## What

预算闸挂在主循环每轮之前：`warn` 档只在消息尾部附加提醒（工具还在，模型
可收尾可继续）；`force` 档则**撤走整个工具表**再要最终回答。`mh/budget.py`
支持轮次/token 双维度，warn 在 80% / max-1 触发。

优雅降级三原则：

1. **不抛异常**：预算超限走正常返回路径，`result["final"]` 就是 HANDOFF；
2. **force 轮撤走 tools**：`tools=None` 后模型协议上无法再调用工具；
3. **HANDOFF 固定三行**：已完成/未完成/关键文件——止损输出必须可交接，
   人或下一个 agent 能拿着它继续。

心智模型一句话：**止损不是打断 agent，而是换一种它无法拒绝的方式让它
收尾。**

## Why

Databricks 的失败模式清单里"延迟""上下文腐化""无限循环"全都指向同一件事：
agent 不知道自己该停。alphaXiv 论文的数据更狠——失败任务的 token 消耗是
成功任务的 **2.7 倍**，支架常让模型陷入无效推理循环。预算不是性能优化，
是**故障止损**：把钱和轮次的上限从"祈祷模型自觉"变成"harness 说了算"。

## How

```bash
cd harness/09_budget
MOCK=1 python3 demo.py    # 离线三组对照
python3 demo.py           # 真机: 无预算对照 / 步数预算 / token 预算
```

真机实测：

```text
① 对照组: 自然 3 轮完成 5/5（模型两条批量 bash 干完全部活）
② 步数预算 max_turns=2: 预算事件 [(warn,1),(force,2)] → HANDOFF 三行摘要 ✅
③ token 预算 ~100: 事件 [(force,3)] → HANDOFF ✅
   已完成: 创建 d1~d5 五个目录并统计确认均为 1 行
   未完成: 无
   关键文件: d1/f.txt … d5/f.txt
```

真机发现：**强模型批量执行让预算很难自然触发**——qwen3.8 把"5 目录 ×
建目录+写文件+统计"合并成两条 bash，3 轮干完，预算两次都没触发。最终
演示口径改为**预算低于自然轮次**（max_turns=2），才逼出止损路径。这条
设计约束直接写进后续实验：**16 评测台的任务集必须有"不可批量"的串行
依赖，预算指标才有区分度**。

实现代码：

```python
Budget(max_turns=…, max_tokens=…)      # 双维度, warn 在 80%/max-1 触发
budget_chat_fn(chat_fn, budget)        # 包一层 chat_fn, loop 零改动
# force 轮: chat_fn(finalize, tools=None) —— 撤走工具表
```

token 计量用字符估算（~3 字符/token，中英混合），够预算判断用；精确
计量（Ollama 响应里的 `eval_count`）归 16 评测台。

## Deep Dive

**force 是物理禁止而非口头禁止——本篇最重要的设计决策。**口头禁止
（"别再调工具了"）在 07 已被证明会被绕过；`tools=None` 后模型在协议上
根本拿不到工具。而 warn 档不直接撤工具，是给模型留"体面收尾"的机会——
多数任务在 warn 档就能自然收敛，省下一轮 force。人被 deadline 逼一逼
也会先收尾。

踩坑清单：

- **中途 system 消息会被无视**：第一版 force 用 `role: "system"` 注入收尾
  指令，qwen3.8 完全无视、照常输出任务汇报。改成**对话尾部的 user 消息**
  后立刻遵守。教训：会话中途的 system 消息在本地模型上权重不可靠，关键
  指令要用 user 角色 + 固定格式要求。

## Q&A

**Q1: HANDOFF 为什么不自动存盘？**

它是模型输出，可信度未经验证；11 会话持久化会把**工具副作用**（权威
事实）落盘，HANDOFF 只是给人看的摘要。

**Q2: 轮次和 token 两个维度都要吗？**

要。轮次限"死循环"，token 限"单轮爆炸"（超长命令/超长输出）——07 的
7 轮空转是前者，yes 刷屏是后者。

**Q3: 止损后任务算成功还是失败？**

都不是——HANDOFF 引入第三种终态："预算内未竟，可交接"。16 评测台会给
它单独计分。
