# 06 · 执行安全沙箱：让 `while True` 也拖不垮宿主

> `mh/sandbox.py` 三层防御对付"参数对但命令危险"的执行：词法守卫（`../`、
> fork 炸弹在执行前拒绝）、进程组限时（`killpg` 处决整组不留孤儿）、输出
> 截断（8KB 并告知模型）。三场景确定性验收全绿，真机 agent 循环一并过关
> ——过程中还揪出一个真 bug：**cwd 静默丢失，沙箱隔离整条链路失效**。

## What

执行安全沙箱：一条命令从进入到回喂要过三道关卡——词法守卫在执行前拒绝
危险模式；进程组执行带 3 秒限时，超时 `killpg` 全组处决；输出过 8KB 截断
器。所有出口都汇成"可回喂的文本"，`sandbox.run` 与 05 的 `Tool.call` 一样
**永不抛异常**。

心智模型一句话：**沙箱不阻止错误，只让每个错误的代价有上限。**

| 层 | 手段 | 挡得住 | 挡不住（诚实边界） |
|:--|:--|:--|:--|
| 词法守卫 | 模式匹配拒绝 | `../` 爬升、fork 炸弹、`rm -rf /` | 绝对路径写 `/tmp`、编码混淆 |
| 进程组限时 | `setsid` + `killpg` | 死循环、挂起 | 已写盘的副作用（要靠快照/事务） |
| 输出截断 | 字节上限 + 告知 | 上下文爆炸 | 语义空洞的长输出 |

词法守卫是**启发式**不是隔离：绝对路径治理归 07 权限门，容器级隔离
（Docker/nsjail）超出本实验范围——诚实标注，不假装。

## Why

04/05 的工具层对执行本身毫无防御：模型一句 `while true; do :; done` 就能
挂死宿主，一条 `yes | head -c 100M` 就能撑爆上下文。Databricks 把"沙箱与
执行环境"列为 harness 八大组件之一——**执行层的职责不是阻止错误，而是
让错误付不起代价**：3 秒处决、8KB 封顶、越界拒绝。

## How

```bash
cd harness/06_sandbox
python3 demo.py            # 三场景确定性验收（无需 LLM）
python3 demo.py --agent    # 追加真机 agent 循环（截断任务）
```

真机实测：

```text
场景1 死循环: 耗时 3.0s | [错误: 超时 3s, 进程组已杀死] | 孤儿进程 0
场景2 输出截断: 100KB 输出 → 返回 4590 字符 | 含截断提示 ✅
场景3 越界探测: echo hacked > ../treasure.txt 被拒 | 沙箱外文件零改动 ✅
agent 循环: 3 轮 2 次调用, big.txt 50000 字节生成并汇报 ✅
```

## Deep Dive

**为什么杀进程组而不只是子进程？**`bash -c "while true"` 的直接子进程死了，
bash 自己 spawn 的孙进程还活着。`start_new_session=True` 让命令独立成组，
超时后 `os.killpg` 一锅端——验收里"孤儿进程 0"就是这条的实测证据。

**截断必须"告知"。**只截断不告知，模型不知道自己看到的是残本，会基于
残本继续推理（幻觉放大器）。截断器在尾部追加"[输出已截断: 原始输出超过
8192 字节…]"——**元信息也是上下文工程的一部分**（10 压缩的雏形）。

踩坑清单：

- **cwd 静默丢失（潜伏两个实验的真 bug）**：`--agent` 验收时 `big.txt`
  没出现在沙箱里。排查发现：`as_loop_entry` 的包装函数签名是
  `def _fn(**args)`，而 loop 按 `'cwd' in signature(fn)` 决定是否注入任务
  目录——`**args` 吞掉了形参签名，cwd 静默丢失，agent 的写入全部落在
  **当前目录**。修复：`def _fn(cwd=None, **args)`。它的可怕之处：**之前
  的实验全部照常通过**——05 的故障注入走的是 `Tool.call` 直调路径，没经过
  loop 的 cwd 注入。教训：**包装器与调用方之间的隐式协议（签名约定）必须
  有测试钉死**，否则重构时它第一个坏、最后被发现。

## Q&A

**Q1: `sandbox.run` 为什么永不抛异常？**

与 05 的 `Tool.call` 同哲学：执行层的所有失败都要变成模型可读的文本回喂。
补充一条边界：异常只允许出现在 harness 自己的 bug 里，不允许出现在被治理
的对象上。

**Q2: 3 秒默认值怎么定的？**

本系列任务（文件操作/文本处理）正常执行都在亚秒级，3s 是 3 个数量级冗余；
编译/下载类任务应显式放宽，并配合 09 预算。

**Q3: `../` 守卫会不会误伤？**

会——`cd .. && ls` 这类合法操作也被拒。这是粗粒度词法防御的已知代价；
细粒度要等 07 的 allow/ask/deny 规则引擎。

**Q4: 场景 3 的"零改动"怎么证明？**

执行前后对沙箱外目录做内容 hash 快照对比——判分铁证哲学（01）在安全场景
的复用。
