# 04 · ⛓️ 最小 Agent Loop：mini-harness v0.1 首航

> `mh/` mini-harness 包的第一个器官是主循环：带工具 schema（用 JSON 声明工具名、参数与格式的说明书）请求模型 → 执行 tool_calls → 结果回填 → 直到无 tool_calls 收敛。34 行循环体撑起整个包的骨架，规则只有三条：**先执行再收尾、assistant 先落历史再回填、无 tool_calls 即收敛**。读完你能照着写出这个循环，并理解每条规则防的是哪种事故。

## Background

没有循环时，模型只被询问一次：程序把任务发给模型，打印回复，结束。多步任务（先写文件、再运行验证）要么靠人把每步结果手工贴回对话框，要么让模型一口气"说出"所有步骤然后祈祷不出错。

这条路在两步任务上就会断：模型第 1 步的输出要变成第 2 步的输入，中间的搬运、判断"要不要继续"、出错重试，全都没有承载者。01 实验已经录下这种形态的结局——命令正确、磁盘零变化、报告成功。

把"请求模型 → 执行它点名的工具 → 把结果回填 → 再请求"固化成一段自动运转的代码，就是 Agent Loop（代理循环）。

本实验把它做成 `mh/` 包的第一个器官：`mh/` 是本系列亲手实现的 mini-harness（模型外围负责执行与约束的微型设施层）包，`mh/loop.py` 约 60 行，接口按后续 17 个模块的形状预留——这一步走对，后面每篇就是"加一个文件、过一遍验收"。

## What

Agent Loop 是"模型意图"与"真实副作用"之间的传送带；`mh/loop.py` 约 60 行，其中循环体 34 行。

一次任务 = 若干个完整回合：每回合主循环带 tools schema（用 JSON 声明工具名、参数与格式的说明书）请求模型；返回 `message.tool_calls`（模型给出的结构化工具调用请求）就逐个执行，结果以 `role:tool`（协议里代表工具结果的消息角色）回填再进下一回合；返回纯文本即收敛。

轮次上限是最后的安全网。

循环三定律：

1. **先执行再收尾**：模型习惯"命令 + 任务完成"同轮输出（01 实验的致命 bug），循环必须先执行完所有 tool_calls 再判收敛；
2. **assistant 先落历史**：带 `tool_calls` 的 assistant 消息（对话中代表模型发言角色的消息）要先 append 进历史，tool 结果才能对上号（Ollama 协议要求）；
3. **无 tool_calls 即收敛**：不猜模型"想不想继续"，协议说了算。

心智模型：可以把主循环想象成模型与真实世界之间的传送带——模型把意图放上带子，循环把带子上的意图变成真实动作，再把动作结果送回模型面前。但和工厂传送带不同的是，这条例程什么时候停由模型的输出决定（无 tool_calls 即收敛），没有节拍器兜底，所以还需要轮次上限这条安全网。

## When to Use

什么时候需要一个自己掌控的最小循环：要给模型接工具做连续多步任务，并且需要看清或定制循环内部行为的场合。

典型场景：

1. 要在循环体里插桩时（预算统计、上下文压缩、权限检查都要挂在"每回合"这个位置）：自己的循环才能自由走线。
2. 学习 agent 运行时的最小骨架：60 行读完，后续所有扩展都有明确的挂载点。
3. 评测模型工具调用能力：`chat_fn` 可注入 mock 或切换模型，同一循环复用于不同被测对象。

何时不用：任务单轮即可完成、不涉及工具时，一次 API 调用就够；纯交付且不在意内部行为时，成熟框架的循环更省事。

同类方案对比：

| 方案 | 与本实验的差异 | 什么时候选它 |
|:--|:--|:--|
| 裸 API 单次调用 | 无循环，多步任务断链 | 单轮问答、无工具任务 |
| 成熟框架内置循环（LangChain/LangGraph 等） | 功能全，但循环体不可控 | 快速交付，不需要内部插桩 |
| 自研最小循环（本实验，`mh/loop.py`） | 60 行全透明，接口预留扩展 | 要在循环里插桩、要每行可控 |

选自研的理由是插桩位置：09 预算、10 压缩都要在循环体里挂钩，用别人的循环等于在控制不了的房子里走线——本系列要的就是"循环里每一行都是自己的"。

定位对照：agents 线的 07_agent_loop 已写过生产级循环，那是框架视角的"能跑"；`mh/loop.py` 是 harness 视角的"可生长"——刻意极简，但每个接口都为后续模块预留了挂载点。

## Quick Start

前置条件：Python 3；离线演示（`MOCK=1`，环境变量开关，用假回复走完协议）不需要模型服务；真机运行需要本机装有 Ollama（在本地运行大语言模型 LLM 的工具）与 `qwen3.8:latest`。

```bash
cd harness/04_min_loop
MOCK=1 python3 demo.py          # 离线：mock 走完整 tool_calls 协议
python3 demo.py                 # 真机：全自主完成两步任务（验收口径）
python3 demo.py --trace         # 打印完整消息历史
```

真机实测（3 轮 2 次工具调用，零人工干预）：

```text
--- 第 1 轮 ---
  >> run_bash({"command": "cat > hello.py << 'EOF'\nfrom datetime import date ..."})
--- 第 2 轮 ---
  >> run_bash({"command": "python3 hello.py"})
--- 第 3 轮 ---
[验收] hello.py 存在: ✅
[验收] 脚本输出 = 今天(2026-09-18): 2026-09-18 ✅
[验收] 最终回答: 已完成。hello.py 已创建并成功运行，脚本输出为 2026-09-18
```

诚实预期：真机应在 3 轮内、2 次工具调用完成两步任务，验收三行全部 ✅；`--trace` 下会看到一处反直觉现象（`content` 为空、推理藏在 `thinking` 字段），属预期行为，解释见踩坑清单第 1 条。

## How It Works

### 一个回合的执行顺序

顺序固定：带 tools schema 请求模型 → 判断返回里有没有 `message.tool_calls` → 有则逐个执行 `fn(**args)`，结果以 `role:tool` 回填进历史，进入下一回合 → 没有则把纯文本作为最终答案收敛。

对照输出：第 1 轮返回写文件的调用、第 2 轮返回运行脚本的调用、第 3 轮返回纯文本收敛，正好 3 轮 2 次调用。

三定律就长在这个顺序里：先执行再收尾，防"命令没跑就宣布完成"；assistant 消息先落历史，防协议报错；只认协议收敛，防猜错模型意图。轮次上限用 `for…else` 兜底——超限不算崩溃，返回已有 trace（完整调用轨迹）。

### 入口签名与三个刻意设计

```python
run_agent(task, tools, max_turns=8, chat_fn=None, cwd=None, on_event=None)
# → {"final", "turns", "tool_trace", "messages"}
```

- `chat_fn` 注入点：默认 `mh_llm.chat_with_retry`（重试+弹性超时），`MOCK=1` 时换剧本；16 评测台会用同一接口切模型；
- `except Exception → f"{type(e).__name__}: {e}"` 直传：v0.1 刻意裸奔，05 的第一个对比数据就用它；
- `for…else` 兜底轮次上限，超限不算崩溃，返回已有 trace。

签名里的另外两个参数同样是伏笔：`on_event` 是事件挂钩（每回合回调一次的观测点），09 预算与 16 评测都在这里插桩；`cwd` 强制工作目录，是 06 沙箱隔离执行位置的前提。

### 工具表：一切工具系统的种子

```python
TOOLS = {"run_bash": {"desc": ..., "schema": {...}, "fn": run_bash}}
```

三件套（描述/schema/函数）就是 05 工具契约的输入；`fn(**args)` 的裸调用在 05 会被 schema 校验包住，在 07 会被权限门拦截，在 08 被 hooks（在调用前后插入自定义逻辑的钩子机制）环绕。今天故意让它是裸的——先看见不设防的样子，才知道每层防线加在哪。

## Pitfalls & Q&A

### 踩坑清单

1. **`content` 为空、推理在 `thinking` 字段**。现象：加 `--trace` 后看到模型回复的 `content` 是空的，像是没有回答。原因：qwen3.8 是混合推理模型（回复里除正文外还生成思考段），Ollama 把思考单独存放在 `thinking` 字段。说明与解法：这是预期行为，`mh/llm.py` 原样透传该字段；思考比正文更占上下文，它是 10 上下文压缩要治理的对象之一。

### 深入问答

**Q：`max_turns=8` 够吗？**

两步任务 3 轮收敛，8 是 2.6 倍冗余；16 评测台会统计分布后再定生产值。

**Q：为什么 `cwd` 是 `run_agent` 的参数而不是工具的？**

工作目录是**任务级**约束，模型不该有权选择"在哪执行"——权限模型（07）的第一课。

**Q：收敛判据为什么信协议不信文本？**

与 01 判分铁证同源：确定性信息（tool_calls 有无）优于概率性信息（"任务完成"字样）。
