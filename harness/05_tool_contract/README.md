# 05 · 工具契约层：故障注入下量出契约的真实价值

> `mh/tools.py` 给工具系统装上**契约**（执行前校验参数、错误翻译成修正指令的约定层）：`@tool` 从类型注解自动生成 schema，jsonschema 在**执行前**拦截，错误翻译成"哪里错、怎么改"。loop 零改动换装成功——`Registry.to_loop_tools()` 直接喂 `run_agent`。实验用**故障注入**量它的真实价值：首个工具调用的参数被 harness 悄悄改坏（path 变数字、content 消失），然后比较两种工具层的自愈。读完你能给任意 Python 函数装上契约，并理解拦截位置为什么决定契约的价值。

## Background

04 的工具表里，`fn(**args)` 是裸调用：模型传错参数没人提前拦，异常原文直接抛回给模型。模型漏传一个 `content`，函数执行时才炸出一条 `TypeError`，模型只能对着异常堆栈猜哪里错、怎么改。

这套做法的代价随工具变多而放大：参数校验散落在每个函数体里，错误信息格式因人而异，模型自纠全靠运气；更糟的是校验发生在函数内部，参数不合法时副作用可能已经发生了一半。工具越多，"错误变成副作用"的概率越高。

工业形态的答案是**工具契约**：模型看到的不是函数而是 schema（用 JSON 声明工具名、参数与格式的说明书），harness（模型外围负责执行与约束的设施层）在"意图"与"副作用"之间做统一校验与错误翻译。

本实验把契约装进 `mh/tools.py`，并用故障注入（故意往输入里塞错误、观察防护是否生效的测试方法）量出它的真实价值——顺任务（模型一次就对、无故障发生）域测不出差异，这是 03 的教训。

## What

工具契约的定义：模型看到的不是函数而是 schema，harness 在意图与副作用之间做校验。`mh/tools.py` 三件套：

| 组件 | 职责 | 一句话 |
|:--|:--|:--|
| `@tool` | 类型注解 + docstring → JSON Schema | 工具即函数，schema 不手写 |
| 校验器 | jsonschema（按 schema 检查 JSON 数据的校验库）在**执行前**拦截 | 错误不变成副作用 |
| 错误翻译 | `ValidationError → 哪里错+必填清单+怎么改` | 错误是给模型的输入，不是给人的日志 |

心智模型一句话：**契约 = 在错误变成副作用之前，把它变成一条修正指令。**

可以把工具契约想象成海关申报：入境（执行）之前检查申报单（参数）是否完整合规，不合规当场退回并写明缺什么，而不是等"入了境"（副作用发生）再追责。但和海关不同的是，被退回的模型可以几秒内按清单改好材料重新排队——修正指令要写得它一看就会改。

## When to Use

什么时候需要给工具上契约：只要有模型之外的执行动作，契约就该在副作用之前站岗。

典型场景：

1. 给模型暴露任何会写文件、发请求的工具时：校验放在执行前，错误参数永远碰不到真实资源。
2. 工具数量多、参数复杂，手写 schema 维护不动时：`@tool` 从类型注解自动生成，函数即真相。
3. 需要量化 harness 一层的价值时：契约版与裸奔版加同样的故障对比自愈，数据说话。

何时不用：工具只供人调用、不经模型时，schema 与错误翻译没有受众；一次性原型可以暂缓——但涉及副作用的工具仍建议保留校验。

同类方案对比：

| 方案 | 与本实验的差异 | 什么时候选它 |
|:--|:--|:--|
| 裸调用（04 形态） | 无校验，异常直传模型 | 只读工具、快速试验 |
| 手写 schema + 各处校验 | 控制等价，但声明与实现易脱节 | 极少量、参数稳定的工具 |
| `@tool` 自动契约（本实验） | 注解生成 schema，校验与翻译统一 | 模型驱动的多工具系统 |

## Quick Start

前置条件：Python 3；离线演示（`MOCK=1`，环境变量开关，用剧本回复走完协议）不需要模型服务；真机运行需要本机装有 Ollama（在本地运行大语言模型 LLM 的工具）与 `qwen3.8:latest`。

```bash
cd harness/05_tool_contract
MOCK=1 python3 demo.py     # 离线：剧本走"故障→自纠"全链路
python3 demo.py            # 真机：契约/裸奔各跑一次带故障的任务（验收口径）
python3 demo.py --trace    # 打印两种配置的完整消息历史
```

真机实测（两配置均被注入同样的参数故障）：

```text
B 契约版: 轮次 4, 错误回传 1 次, 文件落盘(2 行) ✅
  write_file(...) → [error] 参数校验失败: 工具 write_file 的参数
                     ['(根对象)'] 不合法 —— 'content' is a required property。
                     必填参数: ['path', 'content']。请修正后重新调用。
  write_file(...) → [ok] ok: 已写入 note.txt
A 裸奔版: 轮次 4, 错误回传 1 次, 文件落盘(2 行) ✅
  write_file(...) → [error] 工具 write_file 执行失败:
                     TypeError: write_file() missing 1 required positional
                     argument: 'content'。请修正后重试。
```

验收达成：**校验失败 → 错误回传 → 第二次调用成功**的完整两轮在日志可见；04 demo 在 loop 零改动下回归通过。

诚实预期：真机结果 A/B 同为 4 轮 1 次错误回传后恢复——连模型 thinking（思考段）里的反省措辞都几乎一样。差别在**质**不在**量**：契约版拦截发生在执行前（零副作用风险）、错误信息指名 schema 期望。

差距要等弱模型（18 的 qwen3:4b 对照）或连环故障（09 预算）才拉开。与 03 相同，零差异不是实验失败，而是"harness 价值 ∝ 故障密度"这条规律的又一次独立验证。

## How It Works

### 故障注入：给 A/B 制造分歧机会

`build_tools()` 给每个工具包一层 `poisoned`，首个调用的参数被改坏（path 变数字、content 消失，只注入一次）。注入点选在 harness 层而非提示词层，保证 A/B 吃到完全相同的故障。

这正是 03 结论的落地：**顺任务测不出差异，故障域才能**。输出里两份 `[error]` 文本就来自同一次注入后的不同防护路径。

### 拦截为什么必须在执行前

执行前拦截 = 副作用零风险；把异常包装得好听 = 错误已经发生，只是"说得好听"。契约的硬价值就在这个位置上，与模型强弱无关。权限门（07）同位置同哲学。

`Tool.call` 永不抛异常是同一思想的另一面：任何异常都要变成模型可读的文本 `(ok, 文本)`——错误也是给模型的输入。但对宿主进程的风险，还要靠 06 沙箱兜底。

### 三个接口，loop 一行未改

```python
@tool
def write_file(path: str, content: str, cwd: str = None) -> str: ...
# 类型注解 → schema; cwd 是运行时上下文, 对模型不可见

Tool.call(args)  # 永不抛异常: (ok, 文本) —— 错误也要成为模型的输入
Registry.to_loop_tools()  # 产出 04 循环认的工具表, loop 一行未改
```

`@tool`（装饰器：包在函数上、返回增强版函数的语法）把类型注解转成 JSON Schema；`Registry.to_loop_tools()` 产出的工具表与 04 的格式完全一致，所以换装不需要动循环——"04 demo 回归通过"这行验收就是这条零改动的证据。

对照 Quick Start 的输出：B 版错误文本含"必填参数: ['path', 'content']"（指名 schema 期望），A 版只有 `TypeError` 原文，两段 `[error]` 的差距就来自错误翻译器。

## Pitfalls & Q&A

### 踩坑清单

1. **闭包晚绑定**。现象：所有包装函数共享了最后一个工具，`write_file` 实际调到了 `count_lines`。原因：循环里给每个工具包 `poisoned` 时引用了循环变量 `base`，闭包记住的是变量本身而不是当时的值，循环结束后它已指向最后一个工具。解法：用工厂函数绑定当次迭代的值。这是 harness 工程师的日常：**包装器比被包装者更容易出错。**

### 深入问答

**Q：schema 该细到什么程度？**

enum（枚举，限定取值范围）/格式约束越多，拦截越早，但 schema 膨胀吃上下文、增加模型理解成本。alphaXiv 论文的 token 通胀教训在这里适用。

**Q：为什么 `cwd` 不进 schema？**

工作目录是任务级约束，模型无权选择"在哪执行"——与 04 的权限观一致，07 会把它升级成显式规则。
