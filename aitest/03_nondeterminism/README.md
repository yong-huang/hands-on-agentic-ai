# 03 · 非确定性画像：同一道题问 30 遍，答案有多稳

> 测试 LLM 之前先回答一个前提问题：它的输出有多"飘"？
> 本实验对同一 prompt（提示词，发给模型的输入文本）在 temperature（温度参数，控制输出随机性，0 最保守）=0 与 0.8 两组各采样 30 次，统计字面一致率与语义近邻一致率，产出 REPORT.md。
> 读完你能用实测分布给断言定阈值，而不是拍脑袋——这两个数字会被项目 9 的劣化判定与项目 15 的复跑口径直接引用。

## Background

给 LLM 输出写断言，最初的做法是跑一次，把那次输出存成"标准答案"，以后每次对比它。

这种做法复跑一次就会撞墙：第二次的输出措辞变了——是被测对象坏了，还是它本来就每次不一样？判断不了"坏"和"飘"，断言要么误报（把正常波动当失败），要么漏报（阈值放到永远通过）。

golden set（固定标注的基准用例集，见 lab 02）解决了"考什么"的问题；本实验解决"输出有多飘"。做法来自实验设计的常规思路：固定输入，只动一个条件（温度），重复采样足够多次，量化输出的散布。散布数据就是后续一切断言阈值的标定依据。

## What

非确定性画像是一次受控重复实验：同一 prompt、两组温度、每组 n 次采样、两个散布指标，产出一份可复跑的数值报告。

可以把画像想象成靶场打靶——固定靶位（prompt）打 30 发（采样），量弹着点散布（一致率）。但和打靶不同的是：这里没有红心可瞄准，"答案"是自然语言，所以散布要用两个近似指标度量：

| 指标 | 定义 | 度量什么 |
|:--|:--|:--|
| 字面一致率 | 众数回答（出现最多的那条）占样本比例 | 完全相同输出的集中度 |
| 语义近邻一致率 | 所有两两对相似度（difflib ratio）的均值 | 措辞不同但意思相近的集中度 |

两个指标的差值本身就是信息：字面低、语义高 = 说法在变、意思稳定；两者都低 = 内容真的在漂。

## When to Use

典型场景：

1. 给断言定阈值之前：先知道"正常发挥"的下界，阈值才有着落（0.8 组的语义一致率就是项目 9 判劣化的参考线）。
2. 换模型或换版本之后：重新画一次画像，比较散布变化——新模型的稳定性和旧模型不可假设相同。
3. 排查"时好时坏"：单次跑批结果抖动时，画像告诉你这个幅度在不在正常散布内。

何时不用：MOCK 断言（剧本是确定的，无需画像）；纯确定性管道（模板引擎输出恒定）。

同类方案对比：

| 方案 | 差异 | 何时选它 |
|:--|:--|:--|
| 拍脑袋定阈值（如"相似度 > 0.8 就算过"） | 无实测依据，误报漏报未知 | 赶原型的临时方案 |
| 单次输出当标准答案 | 把一次采样当全集 | 只跑一次的脚本 |
| 双温度重复采样画像（本实验） | 散布有数值，阈值可复跑 | 一切要长期维护的断言 |

## Quick Start

前置条件：Python 3.10+；真机模式需要本机 Ollama 与 `qwen3:4b` 模型（2.5GB，本系列默认画像模型）；离线演示只需 `MOCK=1`。

```bash
cd aitest/03_nondeterminism
MOCK=1 python3 profile.py --n 8      # 离线演示统计管道（输出预置，秒级）
python3 profile.py                   # 真机：双温度各 30 次，约 5 分钟
```

真机实测输出（qwen3:4b，2026-10-09，节选）：

```text
==> 采样 temperature=0
  [temp=0.0] 30/30 55 字
==> 采样 temperature=0.8
  [temp=0.8] 30/30 46 字

REPORT.md -> /Users/hyhit/Desktop/workspace/projects/hands-on-agentic-ai/aitest/03_nondeterminism/REPORT.md
  字面一致率: temp0=1.0 temp0.8=0.067
  语义一致率: temp0=1.0 temp0.8=0.774
  断言: temp=0 字面一致率 > temp=0.8 ✅ (验收口径)
```

REPORT.md 的指标表（节选）：

```text
| 字面一致率(众数占比) | 1.0 | 0.067 |
| 语义近邻一致率(两两相似均值) | 1.0 | 0.774 |
| 不同输出数 | 1 | 28 |
| 采样耗时(秒) | 132.1 | 147.5 |
```

诚实预期：本轮 temp=0 出现了 30/30 全同——这是 qwen3:4b 配短答案的现象，不是可以写进断言的保证；temp=0.8 组 30 次里出现 28 种措辞，但语义近邻一致率仍有 0.774，典型的"说法在变、意思稳定"。全流程耗时约 5 分钟，与其他进程共享 GPU 时会更慢。

## How It Works

### 两个指标的算法

字面一致率是众数占比：`Counter(outputs).most_common(1)[0][1] / n`，衡量"一模一样的输出占了多少"。

语义近邻一致率是两两相似度均值：对全部 C(n,2) 对输出算 `difflib.SequenceMatcher.ratio()`（标准库的序列相似度，1.0 为全同），再取平均；相同字符串走快速通道直接记 1.0，30 样本 435 对在秒级内算完。

两组指标对照 Quick Start 的输出：temp=0.8 字面 0.067 但语义 0.774——28 种措辞大多是同义改写；这正是"断言要卡语义不是卡字面"的实证。

### 采样协议

`sample_group()` 复用 `qa/llm.py` 的 OpenAI 兼容客户端（环境变量约定与本仓库其他各线一致），临时把 `LLM_MODEL` 切到画像模型、跑完恢复原值；单次调用失败重试一次，网络抖动不中断采样。

qwen3 系是混合推理模型（回复前会先产出思考段），prompt 带 `/no_think` 并给足 `num_predict=400`，防止思考段吃掉输出预算导致采到空串。

统计函数（`exact_consistency` / `semantic_consistency` / `summarize`）是纯函数，与采样解耦——`tests/test_profile.py` 不启动任何服务就能验证指标正确性。

`MOCK=1` 则用预置输出池演示整条统计管道，REPORT 会明确标注"MOCK 演示"，不冒充真机数据。

### 自断言验收与下游消费

脚本最后一步是自断言：temp=0 组字面一致率必须大于 temp=0.8 组，否则 exit 1——画像本身也是被测的。REPORT 里的数字向下游流两条线：0.8 组的语义一致率成为项目 9 判提示词劣化的参考线；"单次跑批 ±1 个用例不算回归"的口径写进项目 15 的验收。

## Pitfalls & Q&A

### 踩坑清单

1. **重定向后日志一直是空文件**。现象：`python3 profile.py > run.log` 后 `tail` 看不到进度。原因：Python 标准输出重定向到文件时按块缓冲，不跑完不落盘。解法：`python3 -u` 或给关键 print 加 `flush=True`；本实验的进度行已按可观测需求处理。

2. **采到空字符串**。现象：某次采样输出 0 字。原因：混合推理模型的思考段占掉 `num_predict` 预算，正文没生成就被截断。解法：prompt 加 `/no_think` 并给足 `num_predict`；空串仍会被如实统计（它就是一次真实输出），不会被悄悄丢弃。

3. **共享 GPU 时耗时翻倍**。现象：平时 5 分钟的画像跑了十几分钟。原因：本地推理服务同时在服务其他进程，采样排队。解法：画像跑批避开高峰，或把耗时数字理解成"本机当时负载下的参考值"——它不是指标的一部分。

### 深入问答

**Q：temp=0 这轮 30/30 全同，画像还有意义吗？**

有意义，而且结论要两面读。一面：这轮实测里 temp=0 极稳，说明该配置可以进回归套件。另一面：全同是"本轮观察"不是"契约"——换模型、升版本、prompt 变长任何一项都可能打破它，所以断言依然不做精确全文匹配，画像在每次换模型后重画一遍。

**Q：语义相似度为什么用 difflib 不用 embedding？**

画像的对象是一句话量级的短文本，编辑相似度足够区分"同义改写"和"内容漂移"，且零模型依赖、可单测、可复跑。项目 5 的语义断言面对的是整段回答与标准答案，才需要 embedding（nomic-embed-text）——两个量级用两种工具，不提前背上模型依赖。

**Q：n=30 是怎么定的？**

按众数占比的标准误（样本比例的天然波动幅度，约 √(p(1-p)/n)）反推：p≈0.9 时标准误约 0.055，30 次采样能分辨"从 0.9 掉到 0.75"这种量级的变化，采样成本约 2.5 分钟。要把分辨精度提到 ±0.03，样本量要翻倍以上——先算再采，不盲加。
