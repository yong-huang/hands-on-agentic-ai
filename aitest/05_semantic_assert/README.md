# 05 · 语义断言：阈值是标出来的，不是拍的

> 字面断言卡不住同义改写——"回归就是改完再跑一遍旧用例"和标准答案一个字都不重合，意思却对。
> 本篇产出 `testbench/asserts/semantic.py`：embedding 余弦相似度 + 实测标定阈值（0.60），双侧矩阵验收（通过 9/10 · 拒绝 10/10）。
> 读完你能给"意思对不对"写出可复跑的断言，并掌握阈值标定这套通用手法。

## Background

项目 4 的结构断言解决了"格式对不对"，但测试 LLM 回答时更常遇到的问题是"意思对不对"。

用关键词匹配判语义，最初的做法是挑几个词做子串匹配。这条路撞墙撞在改写上：标准答案说"重新运行已有测试"，回答换成"把旧用例再跑一遍"，一个关键词都不重合，但判卷人（人类）一眼认定通过。关键词表越补越长，漏得越离谱。

信息检索领域的成熟做法是把文本变成向量（embedding，把一段文字映射成一串数字，意思越近的文本向量夹角越小），用余弦相似度度量"意思距离"。本实验把它落成断言，并补上工程里最容易缺的一环：阈值不拍脑袋，用标定集实测得出。

## What

语义断言是一个"三件套"：`embed()` 把文本变成 768 维向量（nomic-embed-text 模型），`cosine()` 算相似度，`check()` 拿相似度对比阈值给 PASS/FAIL。

可以把阈值想象成体温计的刻度线——37.3℃ 以上算发烧，这个线不是感觉定的，是大规模体检数据定的。但和体温计不同的是：相似度的"正常区间"跟领域与文本长度强相关，没有普适刻度线，所以每个测试台都要用自己的标定集画一次自己的线。

标定集的构成（内置 20 组，全部来自 mh 运维助手的任务域）：

| 组别 | 数量 | 期望 | 例子 |
|:--|:--:|:--|:--|
| 等价改写对 | 10 | 相似度 ≥ 阈值（应 PASS） | "list 可变 tuple 不可变" ← "列表能增删改，元组创建后不能修改" |
| 同域无关对 | 10 | 相似度 < 阈值（应 REJECT） | 回归测试的答案 ← "HTTP 默认端口是 80" |

无关对故意取同域内容（都是 IT 话题）——测试台要防的是"答非所问"，不是"完全不相干的两门学科"。

## When to Use

典型场景：

1. 项目 8 的全量评测：golden set 每条用例的期望要点用语义断言核对，不依赖回答措辞。
2. 项目 9 的提示词回归：改版前后各跑一次，用语义相似度判每条用例"变好还是变坏"。
3. 任何"标准答案唯一、表达方式自由"的判分场景：知识问答、意图识别、摘要忠实度初筛。

何时不用：需要精确结构时（项目 4 的 schema 断言）；需要核实事实真伪时（语义相似只管"说得像"，不管"说得对"，那是项目 6 幻觉检测的活）。

同类方案对比：

| 方案 | 差异 | 何时选它 |
|:--|:--|:--|
| 关键词子串匹配 | 被改写击穿，维护词表成本高 | 关键词天然固定的场景 |
| LLM 当判分员 | 灵活但慢、贵、自身不稳定（项目 7 专测） | 需要多维主观评价时 |
| embedding 阈值（本实验） | 毫秒级、确定、可标定 | 大批量"意思对不对"初筛 |

## Quick Start

前置条件：本机 Ollama 与 `nomic-embed-text` 模型（274MB，`ollama list` 确认）。

```bash
cd aitest
python3 -m testbench.asserts.semantic          # 标定 + 双侧矩阵(硬验收)
cd 05_semantic_assert && python3 semantic_assert.py   # 全流程演示
```

  0.60  0.950 ████████████████████████████  ← 选定

诚实预期：验收口径是双侧各 ≥9/10，本轮实测通过 9/10、拒绝 10/10。被漏掉的是 list/tuple 一对——参考句只有 12 个字，短句的向量表征偏弱（sim 0.506）。

这是 embedding 断言的真实边界，不是 bug；把参考句扩写成完整句即可修复（见 Pitfalls 第 1 条）。

## How It Works

### 相似度计算：一次向量，一次夹角

`cosine()` 是 6 行纯函数：两向量点积除以模长之积，1.0 同向、0.0 正交、负值反向。`embed()` 调 Ollama 的 `/v1/embeddings` 端点，nomic-embed-text 把任意长度文本映射成 768 维向量。

断言一次判定的开销是两次 embedding 调用加一次点积——对照 Quick Start 矩阵，40 次 embedding 几秒跑完，比 LLM 判分员（项目 7，一次评分数秒）快两个数量级。

### 阈值标定：曲线取顶，不凭感觉

`calibrate()` 把 20 组标定对各算一遍相似度，然后从 0.40 到 0.95 以 0.05 步长扫描阈值。

每个候选阈值算平衡精度（等价改写通过率与无关对拒绝率的均值），取最高点。对照 Quick Start 的曲线：0.55 时精度 0.800，0.60 升到 0.950，0.65 回落——顶点就是数据选出来的 0.60。

选定阈值连同相似度一起写进结果（`SemanticResult.ok/sim/threshold`）。

判定失败时能直接回答"差多少"：sim 0.506 对阈值 0.60，差 0.094，而不是干巴巴一个 FAIL。

### 双侧矩阵：单侧指标会骗人

只看"等价改写通过率"，把阈值降到 0.4 也能得到 10/10——代价是无关对全放行。

所以验收必须双侧：通过矩阵与拒绝矩阵同时 ≥9。Quick Start 的输出里两个矩阵逐格打勾，任何一格 ❌ 都带相似度数值，可直接归因。

## Pitfalls & Q&A

### 踩坑清单

1. **超短参考句的向量表征偏弱**。现象：12 字的"list 可变 tuple 不可变"与其改写的相似度只有 0.506，落在线下。原因：embedding 模型对信息密度过高的短句缺乏上下文锚点。解法：参考句写成完整句（主谓宾齐全，15 字以上），标定集立刻能过。

2. **只报 PASS/FAIL 不报数值，回归无从归因**。现象：断言失败后不知道离阈值差多远，调参全靠重跑。解法：`SemanticResult` 必须携带 sim 与 threshold 两个字段，判定与证据同体。

3. **`MOCK=1` 时真机矩阵用例会假绿**。现象：打桩 embedding 后改写对与无关对的相似度都失真。解法：真机矩阵用例显式标注 `skipif MOCK=1`，离线档只测纯函数（cosine/阈值逻辑），不冒充标定结果。

### 深入问答

**Q：阈值 0.60 换个模型还成立吗？**

不假设成立。阈值是"标定集 + 模型"的联合属性：换 embedding 模型、换语言、换文本长度分布，都要重跑 `calibrate()` 重新取顶。标定脚本秒级跑完，重标的成本可以忽略——这正是"标定"优于"拍脑袋"的地方：重标便宜，才敢频繁重标。

**Q：为什么无关对要刻意取同域内容？**

"回归测试"和"红烧肉做法"的相似度天然低，拿它们当负样本，阈值 0.9 都能通过验收——但毫无判别力。同域负样本（都是 IT 话题、都有术语）才是测试台真正要面对的分布：用户问 A 答了 B，A 和 B 还都在同一个技术领域里。负样本越难，标出的阈值越可用。

**Q：语义断言和项目 7 的 LLM-as-Judge 怎么分工？**

语义断言回答"说的和标准答案像不像"，毫秒级、可复跑，适合做大批量初筛和回归对比；judge 回答"这个回答好在哪、错在哪"，能处理没有标准答案的开放场景，但慢且自身有方差。本线的分工：能用 embedding 判的不上 judge，judge 留给需要推理的主观维度。
