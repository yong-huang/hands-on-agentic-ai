# 09 · 记忆污染攻防

> 覆盖面试题：长期记忆怎么避免"记忆污染"？
> 构造 12 条污染语料（A 谎报注入 / B 矛盾更新 / C 过时信息 / 干净事实），
> 无防御库 vs 三层防御库（来源置信度 / 时间戳 TTL / 冲突检测）同题对答，
> 真机追加 LLM 面对带元数据记忆的冲突判断对照。


2 条（TTL 检索排除）；LLM 面对带元数据的矛盾记忆主动指出冲突 ✓。

| 查询 | 无防御 | 有防御 |

| **通过率** | **0/5** | **5/5** |

## 2. 三层防御如何分工

- **来源置信度**（写入侧）：verified 1.0 / auto 0.8 / injected 0.3，
  低于 0.5 直接拒入库——把不可靠来源挡在门外。
- **冲突检测**（写入侧）：新记忆与旧记忆相似且矛盾（字面重合 >0.55）
  → 不静默覆盖，拦截并提示用户确认。高置信来源的污染（如表单误读）
  靠这层抓。
- **TTL/时间衰减**（读取侧）：过 365 天的记忆标记过期，检索时排除——
  "2025 年 5 月截止"不再冒充有效答案。

## 3. 深入要点

- 记忆污染的三个入口：对话谎报、矛盾的合法更新、过时信息残留——
  防御要在写入与读取两侧都设卡。
- "主动向用户确认"与"答对"同为通过：安全系统的正确姿态是
  不确定时降级为提问，而不是自信输出。
- 与注入攻击的关系：记忆污染是持久化的 prompt injection（项目 24），
  一次注入长期作恶，所以写入侧防线最关键。
