# 04 · ReAct 死循环检测与防护

> 覆盖面试题：最大步数怎么设？如何判断 Agent 陷入死循环？
> 四层防护（defense in depth）：L1 步数上限 / L2 重复 Action / L3 Thought 相似度 /
> L4 预算熔断（token+耗时），任何一层触发即输出诊断并**强制"失败总结"**——
> 不空转、不静默截断。

## 1. 四层防护一览

| 层 | 信号 | 抓什么循环 | 参数 |
|:--|:--|:--|:--|
| L1 步数上限 | 执行轮数 | 硬兜底，漏网循环最终被它拦 | max_steps=8 |
| L2 重复 Action | (action, input) 签名 | 撞墙式重试（连续 3 次完全相同） | repeat_limit=3 |
| L3 Thought 相似度 | 相邻思考文本编辑相似度 | 换汤不换药的复读（输入微调、思考没变） | ≥0.85 |
| L4 预算熔断 | 累计 token / 耗时 | 每步都不同但永不收敛的资源空转 | 1200 est.tokens / 30s |

怎么看：三层在线信号互为补充——L2 看**行为**、L3 看**语义**、L4 看**资源**，
单一信号都会误报/漏报；L1 不参与判断，只负责兜底。触发后统一走
`force_summary()`：把防护原因喂回模型，要求基于已有 Observation 产出失败总结。

## 2. 运行与实测

```bash
MOCK=1 python loop_guard.py    # 离线：脚本化病态策略，结果确定
python loop_guard.py           # 真实：S1 真模型首轮决策+卡带重放注入
```

## 3. 深入要点

- **最大步数怎么设**：它是兜底不是唯一防护；按任务复杂度分级（简单 3-5 /
  研究型 10-20），触发后必须强制总结、有意义地收尾，而不是静默截断。
- **怎么判断死循环**：行为层（重复 Action）→ 语义层（Thought 相似度）→
  资源层（token/耗时趋势），三层信号互补；等价于"从外到内观察 Agent 是否在推进"。
- **层间要划清语义边界**：完全相同的决策归 L2 管，L3 必须让位——否则相似度 1.00
  会在第 2 步抢先触发，"连续 3 次"永远数不满（实测踩到后用 identical-streak 修复）。
- **拦截的价值是交接而非止血**：S2 里答案其实第一步就拿到了，复读只是掩盖了
  已有 Observation；强制总结把半成品结果交接出来，这是护栏的核心价值。
- **测防护要注入病态策略**：死循环来自降级模型/重试逻辑 bug，健康模型测不出
  防护；用脚本化策略（离线）或重放注入（真机）才能稳定复现尾部风险。
