# 02 · CoT 失效场景解剖：何时该关 CoT

> 覆盖面试题：CoT 的局限性是什么？什么时候 CoT 反而降低性能？
> 三类对 CoT 不利的任务（简单常识 / 干扰数学 / 隐藏意图），有/无 CoT 两种
> 模式跑正确率 + token 消耗。qwen3.8 实测：**A 类常识题 CoT 有害 -20%，
> 且 CoT 消耗 65 倍 token**。

## 1. 为什么需要它

项目 1 发现强模型在简单题上四种模式全 100%（饱和），但 CoT 的适用边界还没
被系统化验证。本篇构造三类对 CoT 不利的任务，用实验数据回答面试高频追问
"什么时候不该用 CoT"——**知道 CoT 什么时候没用，比知道它有用更能体现实力**。

## 2. 实验设计

| 类别 | 任务特征 | 预期 |
| :--- | :--- | :--- |
| A·简单常识 | 零推理需求（"首都哪里"） | CoT 零增益，白花 token |
| B·干扰数学 | 题面含无关数字诱导错误推理链 | CoT 推理链被带偏，正确率降 |
| C·隐藏意图 | 需理解隐含条件（折扣/倒数/合作） | CoT 推理链帮助理解题意 |

## 3. 快速开始

```bash
cd interview/02_cot_failure
MOCK=1 python cot_failure.py    # 离线：预置正误模式
python cot_failure.py           # 真实：qwen3.8 两种模式 × 15 题
```

## 4. 真机实测结果（qwen3.8:latest）

| 类别 | direct | CoT | 差异 |
| :--- | :--- | :--- | :--- |
| A·简单常识 | 4/5 | **3/5** | **-20% ←CoT 有害** |
| B·干扰数学 | 5/5 | 5/5 | +0% |
| C·隐藏意图 | 5/5 | 5/5 | +0% |
| **token 消耗** | **53** | **3476（65×）** | |

三条核心发现：

1. **A 类 CoT 有害**：简单题加 CoT 后模型输出冗长的推理过程（如地球自转
   方向的物理解释），反而干扰了简单答案的提取——一个直接答"东方"的问题，
   CoT 版本写了一段地球自转科普；
2. **B 类干扰数学无差异**：qwen3.8 的指令遵循能力足够强，干扰数字没有
   带偏直接回答，也没有影响 CoT 推理链——这是模型能力强的表现；
3. **CoT token 消耗是直接回答的 65 倍**（3476 vs 53 字符）——大幅超过
   预期的"2-3 倍"，因为 CoT 输出包含完整的 markdown 格式推理过程。

## 5. 判断规则（数据驱动）

- **A 类（简单常识）→ 关 CoT**：零增益 + 65 倍 token 浪费 + 实测 -20%；
- **B 类（干扰数学）→ 看干扰强度**：qwen3.8 抗干扰能力足够，弱模型需测；
- **C 类（隐藏意图）→ 开 CoT**：推理链帮助理解隐含条件；
- **生产策略**：按任务类型分级启用 CoT——简单题 direct、中等题 zero-shot
  CoT、复杂题 few-shot CoT；或训练一个分类器自动预判。

## 6. 面试要点

- CoT 的本质局限：推理链可能被题面无关信息带偏，且"逐步思考"不保证每步
  正确——错误的中间结论会传导到最终答案；
- 简单题加 CoT 的实测伤害：token 65×、正确率 -20%（首答被冗长推理干扰）；
- 判断规则不是二分法而是连续谱：按任务推理深度和干扰强度动态调整；
- 生产实现：路由分类器 + 分级 CoT（简单题 direct，中等题 zero-shot，
  复杂题 few-shot）；
- 评估方法：三类分层题集 + 有/无 CoT 对照 + 关键词判分。
