# 21 · 多 Agent 客服系统雏形

> 覆盖面试题：设计一个多 Agent 协作的客户服务系统（高频大题的最小实现）
> 路由 Agent（意图分类: 订单/售后/闲聊/人工）+ 订单/售后专家（各自工具）
> + 共享上下文（会话级 Session: 身份/订单/历史）+ 人工兜底。10 条请求
> 端到端测试：路由正确率 + 转接后上下文可见（不用重复自我介绍）。
> 真机路由用 LLM 分类，离线用规则。

## 1. 运行与实测

```bash
MOCK=1 python multi_agent_cs.py    # 离线: 规则路由 + 模板回答
python multi_agent_cs.py           # 真实: qwen3.8 做意图路由
```

真机实测（2026-09-09，qwen3.8 LLM 路由）：

| 指标 | 结果 |
|:--|:--|
| 路由正确 | **10/10**（含 LLM 区分"退款多久到账"vs"什么时候能到"） |
| 上下文可见（转接后回复带称呼） | **10/10** |
| 人工兜底触发 | 投诉/要求人工 → human Agent 2 次 |

会话轨迹：order → order → aftersale → aftersale → order → chitchat ×2 →
order → human ×2。用户开场说一次"我是林晓, 订单 A1002"，后续所有专家
（含转接的售后/人工）都能带上称呼与订单号作答。

## 2. 面试要点

- 路由层决定架构：规则（快、可解释）→ LLM 分类（准）→ 混合（规则兜底、
  低置信上模型）；人工兜底是第四个 Agent，不是失败。
- 共享上下文是转接体验的生命线：身份/订单/已办事项放会话级 Session，
  专家只读自己需要的部分——用户永远不必重复自我介绍。
- 专家各持工具与提示词、互不感知；新增专家 = 注册处理器 + 路由加一项
  （项目 22 用 Agent Card 把这件事变成动态发现）。
