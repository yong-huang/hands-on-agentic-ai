# 11 · Reflection 反思机制

> 覆盖面试题：Generative Agents 中的 Reflection 机制怎么工作？
> 客服场景事件流（9 条记忆），每 3 条触发反思：把近期记忆归纳为高层洞察，
> 按 重要性×新近性（半衰期 72h）打分入库。同一模糊问题对比 有/无 Reflection
> 的回答质量（真机 LLM-as-Judge）与洞察引用数。

## 1. 运行与实测

```bash
MOCK=1 python reflection.py    # 离线: 预置洞察与回答 (引用 0 vs 2, 2.0 vs 4.4)
python reflection.py           # 真实: qwen3.8 做反思、作答与评分
```

真机实测（2026-09-09）出现**反常**：无 Reflection 版 4.0 分（回答主动覆盖
电话偏好 + VIP 身份，洞察引用 2/2）；有 Reflection 版 3.0 分（引用 1，
且倾向元分析式跑题）。两轮测量稳定（-4.0 → 修复 Judge 解析后 -1.0）。

诚实结论：**qwen3.8 这类强模型 + 少量记忆的场景下，原始记忆已足够支撑
高质量回答，Reflection 无增益甚至负增益**——洞察上下文反而诱发模型
"先分析再行动"的跑题。Reflection 的适用前提：记忆量大到原始条目互相
淹没、或模型较难自发归纳时，蒸馏出的洞察才有检索价值。离线模式用
抽取式基线（0 引用/2.0 分 vs 2 引用/4.4 分）复现了机制的理想收益。

## 2. 机制三要素（ Generative Agents ）

- 触发器：每累计 N 条记忆反思一次，流水账蒸馏为高层洞察。
- 打分：重要性 × 新近性（指数衰减）决定检索权重；洞察与原始记忆
  同池竞争——分层而非替换。
- 价值边界：原始记忆回答"发生过什么"，洞察回答"客户是谁、什么有效"。

## 3. 深入要点

- 能讲清机制 + 能讲清适用边界 = 完整答案：Reflection 不是免费增益，
  强模型小记忆场景收益趋零（本实验实测数据背书）。
- 洞察引用计数是检验"洞察是否真被使用"的行为指标，比主观评分硬。
