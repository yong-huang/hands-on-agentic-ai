# 01 · CoT 三态对比实验（Zero / Few / Auto-CoT vs 直接回答）

> 覆盖面试题：CoT 为什么能提升推理能力？Zero-shot 与 Few-shot CoT 区别？
> Auto-CoT 怎么实现？本篇自建 20 道数学题（10 单步 + 10 两步），四种模式
> 跑同一题集输出正确率对比表——并得到一个诚实的负结果：**强模型 + 简单题
> 会让四种模式全部饱和**，CoT 的差异化要在更难的题上才显形（见 mock 对照）。

## 1. 为什么需要它

"CoT 为什么有用"人人会背，但面试官接着问"你的实验数据呢"时多数人语塞。
本篇把答案做成可复现的实验：同一题集、同一评分（数值精确匹配）、四种模式
（direct / Zero-shot CoT / Few-shot CoT / Auto-CoT）。实验同时揭示了 CoT
的适用边界——这比无脑背诵"CoT 提升 10 个点"高一个段位。

## 2. 实验设计

| 模式 | 提示词 | 示例来源 |
| :--- | :--- | :--- |
| direct | "直接给出答案，只输出一个数字" | —— |
| zero_cot | "请一步步思考再回答，最后以'答案: 数字'结尾" | —— |
| few_cot | 3 个人工编写的带推理示例 | 人工 |
| auto_cot | 按固定步长取样 3 道代表题，让模型自产推理链示例 | **数据自产** |

评分：从回答中提取最终数值（优先"答案: X"，否则取最后一个数字），与标准
答案精确匹配。题集按单步/两步分层——CoT 的增益理论上集中在两步题。

## 3. 快速开始

```bash
cd interview/01_cot_compare
MOCK=1 python cot_compare.py    # 离线：预置回答模式，验证评估管线
python cot_compare.py           # 真实：qwen3.8（80 次 LLM 调用，约 10 分钟）
```

## 4. 实测结果与归因

**真实模式（qwen3.8:latest）**：四种模式全部 **20/20（100%）**——包括直接
回答。20 道简单数学题对当前旗舰级模型已无区分度，CoT 没有提升空间。

**MOCK 模式（模拟弱推理，验证评估管线的区分度）**：

| 模式 | 单步 | 两步 | 总体 |
| :--- | :--- | :--- | :--- |
| direct | 8/10 | **3/10** | 11/20 (55%) |
| zero_cot | 10/10 | 10/10 | 20/20 (100%) |
| few_cot | 10/10 | 10/10 | 20/20 (100%) |
| auto_cot | 10/10 | 10/10 | 20/20 (100%) |

两步题 3/10 → 10/10 的提升集中在 CoT 类模式——**缺失中间步骤正是直接回答
败给 CoT 的原因**。面试讲法："CoT 的增益 = 多步推理任务 × 模型能力不足的
乘积；任一因子变大，另一因子的影响就趋近于零。"

Auto-CoT 实测：取样 3 道代表题自产推理链作为示例，效果与人工 Few-shot 持平
（本例题集简单），省掉了人工编写 3 个示例的成本。

## 5. 已知边界与踩坑

- 负结果归因：题太简单。想看到提升需要更难的题（多步乘除、干扰数字），
  这正是项目 2「CoT 失效场景解剖」要系统化的事情；
- MockLLM 的"推理"是关键词规则的预置行为（诚实标注），只用于离线验证评估
  管线的区分度；
- 踩坑：few-shot 前缀剥离的正则误加 `re.S`，`.*` 跨行吞掉了问题行导致
  mock 全错——定位后去掉 flag（评估管线本身也要被测试）。

## 7. 面试要点

- CoT 的增益来自"把多步推理显式化为中间 token"，给模型更多计算与自检空间；
- Zero-shot CoT 只加一句"一步步想"；Few-shot 给带推理的示例（格式对齐更强）；
  Auto-CoT 用聚类/取样从数据自产示例，省人工；
- 强模型 + 简单任务时 CoT 无增益甚至有害（过度思考）——适用边界见项目 2；
- 评估要用分层题集（单步/多步），否则测不出模式差异；
- 数值评分要处理"答案: X"提取与取最后一个数字的兜底。

## 8. 总结

四种模式、20 道分层题、一张对比表——以及一个诚实的饱和结论。CoT 的适用
边界（何时反而有害）留到下一篇专门解剖。
