# 18 · 工具优雅降级

> 覆盖面试题：Agent 调用工具失败了怎么优雅降级？
> 机票价格查询的降级链：主工具（注入 100% 超时）→ 备用工具（覆盖部分
> 城市）→ 本地缓存 → 诚实拒答（附原因，真机由 LLM 组织话术）。配套
> 可降级标记（支付类不可降级）与熔断器（连续失败 3 次摘除主工具）。

## 1. 运行与实测

```bash
MOCK=1 python graceful_degrade.py    # 离线: 拒答话术用模板
python graceful_degrade.py           # 真实: 拒答话术由 qwen3.8 生成
```

实测（2026-09-09，真机）：主工具全挂情况下**可用率 8/10 (80%) 达标**
（备用接口命中 5 + 缓存命中 3，2 城诚实拒答并附原因）；熔断器在连续
3 次超时后打开，后续查询直接跳过主工具（日志 3 条可见）：

```
· [主工具] 成都 超时 (>0.4s), 熔断状态=closed   ×3 后
⚡ 熔断器 open: 连续失败 3 次, 暂时摘除主工具 1.0s
· [主工具] 熔断打开, 跳过 (拉萨/海口/...)
```

## 2. 深入要点

- 降级链是逐级放宽的一致性：实时价 → 批发价 → 旧缓存 → 拒答；每降
  一级都要告知数据来源，拒答必须带原因。
- 可降级性是工具属性：查询类可降级，资金/删除类不可降级——支付失败
  找"替代通道"是事故，不是降级。
- 熔断器保护的是系统：连续失败 N 次摘除主工具，避免每个请求白等一个
  超时；冷却后半开探测，恢复要及时。
