# 17 · 并行工具调用（依赖分析 DAG）

> 覆盖面试题：多工具并行调用怎么实现？工具间依赖怎么处理？
> 模型一轮吐 4 个工具调用，calc_cost 的参数用 $1/$2 占位符引用前两个
> 调用的结果。三种调度器对跑：串行 / 分析后并行（$引用建 DAG，无依赖层
> asyncio.gather）/ 盲并行（不分析直接全量并发）。工具以 0.3s sleep
> 模拟耗时，计时完全可复现。

## 1. 运行与实测

```bash
MOCK=1 python parallel_tools.py    # 离线: 预置调用批次
python parallel_tools.py           # 真实: qwen3.8 生成调用批次, 计时同
```

实测（2026-09-09，两种模式一致）：

| 调度器 | 耗时 | 结果 |
|:--|:--:|:--|
| 串行 | 1.21s | 4/4 成功 |
| 分析后并行 | **0.60s（50%）** | 4/4 成功，2.0x 加速 ✓ |
| 盲并行 | 0.30s | **calc_cost 失败**：读到未解析占位符 "$1" ✓ 可复现 |

## 2. 深入要点

- 依赖检测是关键：扫描参数里的 $N 引用建 DAG，无依赖的进同一波
  gather；有依赖的等前序结果回填后再发。
- 盲并行的失败模式：占位符没回填就开跑，拿到 "$1" 字符串——错得快
  不等于对，依赖错序的结果必须拦截。
- 结果按调用 id 归位（不是完成顺序），保持与模型的 tool_call_id 对应，
  下一轮对话才不会串线。
- 真机补充：qwen3.8 原生支持一轮多 tool_calls（项目 5 实测一轮并行
  两个查询），FC 的并行能力是传输层自带的。
