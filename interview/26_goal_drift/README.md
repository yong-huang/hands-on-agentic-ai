# 26 · 目标漂移检测（Goal Drift）

> 覆盖面试题：如何防止 Agent 的"目标漂移"？
> 研究型长任务（咖啡店选址调研）每 3 步"对账"：把原始目标 + 近期行动
> 交给评估器打偏离度 0~1，超过阈值即拉回（重申目标 + 限定下一步范围）。
> 漂移注入：第 5 步起用户消息诱导转向房价话题。对照无检测版与有检测版，
> 输出偏离度曲线。真机用 qwen3.8 当漂移评估器。

## 1. 运行与实测

```bash
MOCK=1 python goal_drift.py    # 离线: 规则评估器, 阈值 0.6
python goal_drift.py           # 真实: qwen3.8 评估器 (阈值校准到 0.4)
```

真机实测（2026-09-09）：无检测版 8 步后交付的是楼市报告（任务失败）；
有检测版偏离度曲线 **step3=0.1 → step6=0.45（超阈值拉回）→ step9=0.1**，
注入后 3 步内拉回 ✓，最终交付 3 个候选点位 ✓。

校准发现：qwen3.8 评估器系统性偏宽松（漂移中段只给 0.45，0.6 阈值漏报），
阈值需按评估器实测下调到 0.4 才触发——**评估器换型必须重新校准阈值**，
这是把评测器用到生产前最容易被跳过的一步。

## 2. 深入要点

- 对账（re-align）是核心机制：漂移是渐变的，等交付时发现就晚了；
  周期性用"原始目标 + 近期行动"打偏离度。
- 拉回动作要具体：重申目标 + 限定下一步范围；连续超阈值就中止（止损
  也是防护）。
- 漂移来源 = 用户中途插入的无关请求 + 工具返回的诱饵内容——与注入
  同源，检测机制可与项目 9/24 的防御共用。
