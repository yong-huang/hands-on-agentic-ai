# 10 · 混合检索（向量 + 关键词 + RRF）

> 覆盖面试题：向量检索、关键词检索、混合检索怎么选择？
> 50 条文档语料，三种检索器对跑 15 条查询（精确词/语义改写/混合 各 5，
> Hit@3 评测）：BM25 简化实现 / 向量检索（真机 nomic，离线 hash 退化）/
> RRF 排名融合。

## 1. 运行与实测

```bash
MOCK=1 python hybrid_retrieval.py    # 离线: hash 向量 (链路验证)
python hybrid_retrieval.py           # 真实: nomic-embed-text
```

实测（2026-09-09，nomic-embed-text）：

| 检索器 | 精确词 | 语义改写 | 混合 | overall |
|:--|:--:|:--:|:--:|:--:|
| BM25 | **5/5** | 2/5 | **4/5** | 11/15 |
| Vector | 5/5 | **3/5** | 1/5 | 9/15 |
| RRF | 5/5 | 2/5 | 4/5 | 11/15 |

诚实解读：本语料（短文档 + 中文二元组分词）下 RRF 与 BM25 打平、未拉开
差距——RRF 的收益依赖两路召回互补（向量路要能捞回 BM25 漏掉的语义改写，
本组实测只捞回 1 条）。语料越长、查询改写越激进，向量路与 RRF 的优势
越明显；精确词类两路都全对，RRF 不会拖后腿。

## 2. RRF 一条公式

score(d) = Σ 1/(60 + rank_i(d))——只看排名不看分数，天然规避两路
分数量纲不可比的问题，这是它成为混合检索默认融合方案的原因。

## 3. 面试要点

- 精确词命中（型号/报错码/专名）靠 BM25——向量对精确 token 不敏感。
- 换说法的问题靠向量——字面零重叠时 BM25 直接失明（离线模式实测）。
- 生产默认混合检索：两路召回 + RRF 融合；评测用 Hit@k/MRR 驱动
  chunking 与 k 的调参，而不是凭感觉。
