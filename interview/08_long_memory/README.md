# 08 · 长期记忆库（写入 + 检索注入）

> 覆盖面试题：请设计一个 Agent 的记忆系统，包括短期和长期记忆。
> SQLite 持久化 + 向量检索 + TopK 注入 system prompt。写入路径 = 显式
> "记住" + 自动抽取（LLM/规则归一化事实）；读取路径 = query 向量化 →
> 余弦 TopK → 注入。跨会话测试：关库重开（模拟新进程）后提问 4 个事实。

## 1. 运行与实测

```bash
MOCK=1 python long_memory.py    # 离线: hash 词袋退化向量 + 模板回答
python long_memory.py           # 真实: nomic-embed-text + qwen3.8
```

实测（2026-09-09，真实模式 4/4 全对）：

| 查询 | Top1 命中 | 相似度 | 结果 |
|:--|:--|:--:|:--:|
| 我的项目代号是什么？ | 用户的项目代号叫夜莺 | 0.92 | ✓ |
| 我叫什么名字？ | 用户名叫林晓 | 0.75 | ✓ |
| 我在哪个城市？ | 用户常驻杭州 | 0.65 | ✓ |
| 我咖啡喝什么？ | 用户咖啡只喝燕麦拿铁 | 0.74 | ✓ |

nomic 语义检索把表面形式完全不同的查询（"我在哪个城市" vs "用户常驻
杭州"）正确配对——这是 hash 退化向量做不到的（离线模式 3/4，"城市"查询
零字面重叠导致漏检，恰说明语义 embedding 是这一层不可省的投入）。
记忆写入前先做归一化（"我叫林晓" → "用户的名字是林晓"）显著提升检索稳定性。

## 2. 记忆系统全貌（架构答辩图）

```
用户输入 ──► 短期记忆 (窗口/摘要, 本会话上下文) ──► LLM
                │ 会话结束/关键事实
                ▼
            写入路径: 显式"记住" + 自动抽取(归一化)
                ▼
            长期记忆库 (SQLite + 向量, 跨会话)
                │ 检索 TopK 注入
                ▼
            下一次会话的 system prompt ◄── 读取路径
```

## 3. 面试要点

- 记忆系统 = 短期（管理上下文预算，项目 7）+ 长期（跨会话持久化，本项目）。
- 写入要过滤、读取要检索——这对读写路径就是"设计记忆系统"大题的骨架。
- 追问预备：冲突记忆怎么办（项目 9 的置信度/冲突检测）、记忆怎么过期
  （TTL）、为什么不用全文检索（语义改写场景字面零重叠）。
