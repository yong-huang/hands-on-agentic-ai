# 06 · ToT 求解器（BFS vs DFS）

> 覆盖面试题：ToT 和 CoT 本质区别？BFS/DFS 怎么选？计算成本怎么控？
> 思维树引擎双任务域共用：24 点（状态=剩余数字）+ 迷宫（状态=坐标）。
> LLM 只生成候选（每次扩展 1 次调用），评估打分用规则神谕；BFS/DFS 可切换，
> 剪枝=分数阈值丢弃；统计每配置 LLM 调用数与成功率。

## 1. 四配置对比

| 配置 | 信号 | 语义 |
|:--|:--|:--|
| CoT | 单链自回归 | 错一步错到底 |
| ToT-BFS | 层层展开 beam=2 | 找浅解稳，调用多 |
| ToT-DFS | 高分优先深潜 | 首解快，回溯代价大 |
| ToT-BFS+剪枝 | 神谕阈值砍死分支 | 评估器越强省得越多 |

## 2. 运行与实测

```bash
MOCK=1 python tot_solver.py    # 离线全量: 20 题 + 迷宫, 结果确定
python tot_solver.py           # 真实: CoT + ToT-BFS+剪枝 (10 题 24 点)
```

实测（2026-09-09，qwen3.8@Ollama，思考模型 ~100s/次，故真机裁剪配置）：

| 配置 | mock 24点(10题) | mock 调用 | mock 迷宫 | 真机 24点 |
|:--|:--:|:--:|:--:|:--:|
| CoT | 4/10 | 10 | ✗ | **9/10** |
| ToT-BFS | 10/10 | 55 | ✓ (17 次) | — |
| ToT-DFS | 10/10 | 55 | ✓ (13 次) | — |
| ToT-BFS+剪枝 | 10/10 | 30 (**省 46%**) | ✓ (17 次) | **2/10** |

真机反常结果（最有价值的发现）：**CoT 9/10 反超 ToT 2/10**。
分析：评估器是完美神谕（剩余数字能否凑出 24），而 qwen3.8 的候选生成
偏保守（难解需要 3/4、8/3 这类分数除法），浅候选被神谕全部剪掉，树在
根上枯死；同时 qwen3.8 的思考型 CoT 一步推理已很强。结论：**ToT 要求
生成器与评估器能力匹配——评估器过强 + 生成器过弱 = 组合死锁**。这正是
ToT 论文用 GPT-4 同时做生成与评估的原因。离线全量表补齐 BFS/DFS 策略
对比与剪枝节省（46% ≥ 30% 验收线）。

## 3. 深入要点

- 本质区别：CoT 是链，ToT 是树——支持分叉、评估、回溯；把"生成"交给
  模型，把"验证与调度"交给程序。
- BFS vs DFS：解浅（24 点固定 3 步）用 DFS 省调用；解深/浅解不明用 BFS
  （迷宫实测 DFS 13 < BFS 17，但 DFS 首解失败时要付回溯代价）。
- 成本控制三板斧：beam 宽度 / 评估器剪枝 / max_calls 预算熔断。
- ToT 不是银弹：组件能力错配时（神谕评估 + 弱生成）反而不如 CoT，
  能讲出这个失败模式比背"ToT 更强"更加分。
